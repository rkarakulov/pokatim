# Контракт независимого ревью (общий для всех движков)

Единый источник правды для Claude `independent-reviewer`, Codex reviewer и `codex_review.sh`.
Одинаковый вход и одинаковая схема находок — результаты сравнимы между движками.

Смысл: ревьюер **не** писал изменение и **не** доверяет автору. Ревьюится реальный diff против spec и правил.

## Вход — пакет ревью

1. **Task** — `task.md` (goal, scope, out of scope, placement & reuse gate, acceptance, security checklist).
2. **Diff** — `git diff <base>...HEAD`, незакоммиченные изменения (staged + unstaged), новые файлы,
   `git log <base>..HEAD --oneline`. `<base>` по умолчанию `main`.
3. **Правила** — `AGENTS.md` (инварианты §4) → `.claude/rules/*.md` затронутых путей → ADR из `docs/adr/`.

Diff — точка входа, не граница: ревьюер открывает любые файлы, чтобы проверить вызовы и регрессии.

## Измерения (покрыть все)

correctness · регрессии / call sites · безопасность · placement и границы модулей ·
contracts-first и совместимость со старыми мобильными клиентами · серверный авторитет ·
append-only аудит (если проект его ведёт) · миграции (expand/contract, не при старте) · идемпотентность задач очереди ·
обработка ошибок · edge cases · тесты (есть, честные, не тавтологии) · соответствие acceptance ·
лишняя сложность · i18n · Documentation Sync (раздел 10 task.md vs diff) ·
**дизайн-система** (AGENTS.md §4.11: UI из токенов и `@rkarakulov/ui`; недостающее — расширением системы
с тестом и примером на `/ui-kit`) · **состояния данных** (§4.12: скелетон по раскладке на первой загрузке,
ошибки с повтором, данные не прячутся при ошибке обновления, пусто, мутации — состояние кнопки) ·
**все платформы** (§4.13: фича = iOS, Android и web/PWA с тем же функционалом; развилки — только файлами
`.web` / `.native` рядом; публичные экраны — SSR с OG).

## Выход — findings.md

Заголовок прохода:

```
# Findings — <slug> — pass <N> — reviewer: <claude | codex | …>
base: <base>   commits: <range | working tree>
verdict: APPROVE | REQUEST CHANGES
```

Каждая находка:

```
### [<SEVERITY>] <короткий заголовок>
- **file:** <путь от корня>
- **location:** <строки / символ>
- **problem:** <что не так>
- **why_it_matters:** <конкретный сбой или нарушенное правило>
- **evidence:** <цитата кода / ссылка на правило / вызов — проверяемо>
- **recommended_fix:** <конкретно, в рамках scope>
```

Severity:

- **CRITICAL** — корректность, безопасность, потеря данных, нарушение инварианта §4.1–§4.10; блокирует.
- Нарушение §4.11 (UI вне дизайн-системы), §4.12 (нет скелетона / ошибки с повтором) и §4.13 (экран не
  работает на одной из платформ проекта) — **HIGH**. В том числе: нет web-варианта экрана или модуля
  (нативный модуль без `.web`-реализации, экран не открывается в браузере) — **HIGH**.
- MongoDB: объект из запроса (не примитив после zod) в фильтре или обновлении — операторная инъекция
  (`{ $ne: null }` совпадает со всеми документами); `$where`/`$function`/`$accumulator` — **HIGH**
  (`.claude/rules/db.md`).
- pokatim: запись в документы аккаунта в транзакции без `lockUser` (первой операцией) — **HIGH**
  (`.claude/rules/pokatim-db.md`, R1); исключения — создание нового аккаунта (уникальный `users_email_unique`) и
  транзакция, первая операция которой — запись в тот же документ `users` (очистка, `findOneAndDelete`).
- **HIGH** — серьёзный дефект или нарушение правила; исправить до merge.
- **MEDIUM** — стоит исправить; сам по себе не блокер.
- **LOW** — мелочь, по желанию.

Правила отчёта:

- `REQUEST CHANGES` ⇔ есть ≥1 CRITICAL или HIGH.
- Не выдумывать находки ради количества. Пустой список — хороший результат.
- Ревьюер не правит код. Исправляет автор, затем новый проход (pass N+1) дописывается в тот же `findings.md`.
- Непроверенное — `NOT VERIFIED` с причиной, не догадка.

## Цикл между движками

- Claude пишет → Codex ревьюит, и наоборот; либо свежий агент того же движка, если второго нет.
- Автор применяет только **подтверждённые** CRITICAL/HIGH (`superpowers:receiving-code-review`:
  сначала проверить, неверное замечание оспорить с доказательством).
- Finding «решён», только когда повторный проход его больше не репортит.
