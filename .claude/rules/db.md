# База данных — MongoDB 8.0 (replica set), официальный драйвер `mongodb`

Пакеты: `@rkarakulov/api-kit/mongo` (клиент, транзакции, outbox, мигратор, `uuidv7`, `isDuplicateKey`) и
`@rkarakulov/test-kit/mongo` (стенд). Корни `@rkarakulov/api-kit` и `@rkarakulov/test-kit` — PostgreSQL: импорт
запрещён (ESLint).

## Миграции

- Коллекции и индексы — **только миграциями**: `src/db/migrations/NNNN_<имя>.ts` (`{ id, up(db) }`) и список в
  `migrations/index.ts`; новая — в конец, применённую не меняют. Применять: `pnpm --filter @pokatim/api db:migrate`.
- Миграции **не** выполняются при старте приложения (и `createIndex` в коде модулей — тоже нет) — отдельный шаг
  деплоя.
- Миграция идемпотентна (`createIndex` того же индекса — без ошибки; изменить опции индекса — новый индекс с
  новым именем, затем удаление старого) и без транзакции (DDL на непустых коллекциях в транзакции запрещён).
- Деструктивные операции (удаление коллекции, поля, индекса, сужение типа) — только expand → migrate data →
  contract в разных релизах и с человеком. Код читает документы старой формы: новые поля могут отсутствовать.
- Установленные мобильные приложения живут долго: данные должны оставаться совместимыми с API предыдущей версии.

## Документы

- Коллекция модуля — `modules/<context>/<имя>.collection.ts`: имя коллекции и TS-интерфейс документа
  (`Collection<XDoc>`). Вход и выход API — zod-контракты; документы из БД zod-ом повторно не валидируются.
- `_id` — строка UUID v7: `uuidv7()` из `@rkarakulov/api-kit/mongo` (совместим с `Uuid` контрактов). `ObjectId` — нет.
- Время — BSON `Date` (UTC), «сейчас» — из `CLOCK`, не `new Date()` в сервисах.
- Персональные данные — в отдельных полях/коллекциях, чтобы их было просто анонимизировать и не выдавать лишнего.

## Запросы и транзакции

- Фильтры и `$set` — **только из примитивов после zod**: объект из запроса в фильтр не передавать
  (`{ token: { $ne: null } }` совпадает со всеми документами — операторная инъекция). `$where`, `$function`,
  `$accumulator` — запрещены.
- Транзакция — `MongoTransactions.run((session) => …)`; репозиторий принимает `session?: DbSession` и передаёт
  `{ session }` в **каждую** операцию. Колбэк может выполниться повторно (`TransientTransactionError`): внутри — без
  побочных эффектов (очереди, почта, HTTP) — они через outbox.
- Событие outbox — `MongoOutboxWriter.append(session, event)` в той же транзакции, что и данные.
- Условие по **другому** документу в транзакции (snapshot isolation не ловит write skew): либо запись в этот
  документ (`$inc: { version: 1 }` — тогда конфликт записи), либо денормализация в изменяемый документ.
- Атомарный переход состояния — `findOneAndUpdate` с условием на текущее состояние в фильтре (возвращает документ
  или `null`); «прочитать, проверить, записать» отдельными операциями — нет.
- Уникальность — уникальный индекс в миграции + `isDuplicateKey(error, 'имя_индекса')`; значение ключа из ошибки
  наружу и в логи не попадает (там персональные данные).
- TTL-индекс — только уборка (удаляет с задержкой до минуты): истечение проверяет сервер по `CLOCK`.
- Append-only коллекции (аудит, история решений) — без update/delete в коде; в проде — роль без `update`/`remove`.

## Тесты

Каждая миграция проверяется на чистой базе: `*_test` удаляется перед прогоном, миграции проекта применяются
заново (`test/global-setup.ts`); перед тестом коллекции очищаются, индексы остаются. Репозитории — интеграционными
тестами на реальном replica set, конкурентные сценарии — параллельными операциями.
