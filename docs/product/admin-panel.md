# Панель «Протокол» — команда платформы

Решения автора 2026-10-25 (task `docs/tasks/2026-10-25-admin-01-foundation`, §8.2) и план разделов. Макеты автора
конфиденциальны и в репозиторий не копируются; здесь — только решения и краткая карта.

## Доступ (ADR-0009)

- Один аккаунт на человека (D-13): вход в панель тем же e-mail и паролем, что в приложении «Покатим»; роль команды
  выдаётся существующему пользователю с подтверждённым e-mail. Отдельных служебных аккаунтов нет.
- Вход в панель — всегда повторный ввод пароля и отдельная сессия панели (простой 2 ч, абсолют 12 ч).
- Первый администратор — CLI на сервере (`docs/runbooks/deploy.md`, «Панель: первый администратор»); дальше роли выдаёт,
  меняет и снимает только администратор в «Сотрудниках». Причина обязательна при смене и снятии, при выдаче — нет.
- Приглашение (ADR-0026): «Пригласить» в «Сотрудниках» — e-mail, имя в панели, роль; аккаунта может не быть. Письмо
  со ссылкой (действует 7 дней): приглашённый регистрируется в приложении на этот адрес, подтверждает e-mail,
  открывает ссылку и принимает приглашение своим паролем — сразу вход в панель (с шагом 2FA при необходимости).
  Блок «Приглашения» под таблицей: «Истекло», «Письмо не отправлено», «Отправить повторно» (прежняя ссылка гаснет),
  «Отозвать» (без причины). «Выдать роль» на адрес без аккаунта подсказывает «Аккаунта нет — отправьте приглашение».
- Письма сотруднику: роль выдана, изменена, снята (в том числе CLI `grant-admin`) — без причины, с кнопкой «Открыть
  панель». Принятие приглашения и сброс 2FA письма о роли не дают.
- Сброс пароля — общий сброс приложения («Забыли пароль?» ведёт на `/forgot-password` web приложения).
- 2FA (TOTP, ADR-0024): **обязательна для администратора до прода** (флаг `PANEL_TOTP_ENFORCED`; admin без 2FA
  подключает её прямо на экране входа), модератору и организатору — по желанию, с рекомендацией на «Обзоре». Раздел
  «Безопасность» (из блока сотрудника): подключение (QR + ключ, коды восстановления — один раз), перевыпуск кодов,
  отключение. «Запомнить это устройство на 30 дней» пропускает только код. Потерян телефон — код восстановления;
  нет кодов — сброс другим администратором в «Сотрудниках» (с причиной) или CLI `reset-totp` на сервере.
- Название в интерфейсе — «Панель команды платформы».
- Прод — `/admin/` того же домена (принятый риск, ADR-0009).

## Журнал действий

Append-only, хранится бессрочно; видят admin и moderator. Пишутся: выдача (в том числе CLI), смена и снятие роли
(кто, над кем, роль было/стало, причина), вход и выход из панели; panel-invitations — «Отправлено приглашение»,
«Отозвано приглашение», «Принято приглашение» (объект `Приглашение ·<id>`, роль; e-mail и имя приглашённого в журнал
не пишутся); admin-02 — создание и изменение сезона, создание,
изменение, публикация, отмена (шаблон причины) и удаление черновика гонки, записи календаря (снятие — с причиной) с
объектом и его названием на момент действия и именами изменённых полей (без значений); 05b — «Скрыт кофе-райд»,
«Возвращён кофе-райд», «Отклонены жалобы на кофе-райд» (объект — райд с названием, причина, число закрытых жалоб);
ride-photo — «Удалено фото кофе-райда» (объект — райд с названием, причина; id фото в журнал не пишется);
profile-02 — «Сброшено имя участника» (объект — райдер `Участник ·<id>`, причина; само имя в журнал не пишется);
profile-moderation — «Сброшено фото участника», «Сброшен клуб участника», «Жалобы на профиль отклонены» (объект —
`Участник ·<id>`, причина, число закрытых жалоб; сброс имени тоже пишет число закрытых жалоб; ни имя, ни клуб, ни фото
в журнал не пишутся); profile-moderation-followups — «Снят запрет загрузки фото» (объект — `Участник ·<id>`, причина;
запрета не было — записи нет), у «Сброшено фото участника» — дата окончания запрета, если его включил этот сброс; app-themes — «Тема приложения изменена: Классика → Атлас» (объект «Оформление приложения», без причины: смена
обратима; повтор той же темы не пишется; после user-theme новых записей нет — история); halloween-decor — «Сезонный
декор изменён: Без декора → Хеллоуин»; event-tickets — «Настройки билетов изменены» (объект — гонка или старт
календаря с названием, имена изменённых полей) и «Участник отмечен» (объект — событие, код билета `Билет ·<код>`; имени
и e-mail участника в журнале нет); материалы (event-tickets C) — «Добавлен материал события», «Изменён материал
события» (подписи изменённых полей), «Удалён материал события», «Изменён порядок материалов» (объект — событие).
Неудачные входы и «Нет доступа к панели» — нет.
E-mail, IP, UA в журнал не попадают.

Маршруты команды (раздел «Маршруты» и поле «Эталонный коридор» гонки) загружаются файлом GPX, KML, KMZ или TCX до 5 МБ
(upload-limits-kml-panel, routes-formats); формат проверяет сервер по содержимому. Страница маршрута `/routes/:id` (routes-05,
`races.read`): карта MapLibre с толстой линией, цифры, профиль высоты со скраббингом, статус и действия каталога; в
окне публикации и поле коридора — компактная карта и «Открыть маршрут». Гонка с сохранённым коридором — под формой
секция «Карта гонки» (panel-race-map): тот же блок карты, цифр и профиля со скраббингом, на карте — коридор ±допуск. Стиль карты — env сборки
`VITE_MAP_STYLE_LIGHT` (без него — SVG-превью линии). Правила маршрутов — `routes.md`.

«Обзор» (admin-overview, все роли; `GET /v1/admin/overview` — блок без права не отдаётся, считает сервер):

- **Требует внимания** — карточки-счётчики со ссылкой в раздел, только при праве: открытые споры (`disputes.read`);
  гонки, ждущие публикации протокола (окно закрыто, протокола нет), из них готовы к публикации, и сумма невыполненных
  пунктов чек-листа публикации — «блокеры» (`races.read`, организатор — только свои); кофе-райды с жалобами
  (`rides.moderate`); заявки в каталог и маршруты с жалобами (`routes.moderate`); профили с жалобами
  (`profiles.moderate`); удаления аккаунтов, чья очистка не завершилась за сутки (`platform.stats`, ссылка — экран
  «Сбои удаления аккаунтов»). Счётчики — те же очереди, что в разделах. Ноль — «Всё разобрано», не ошибка.
- **Сейчас идёт** (`races.read`) — гонки с открытым окном (участники, загруженные попытки без снятых; ссылка в
  «Результаты»; первые 20, «Показаны N из M»), организатор — только свои; 5 ближайших опубликованных стартов
  календаря, не закончившихся к сегодняшнему дню Минска.
- **Платформа** (`platform.stats`, только admin) — KPI strip: новые пользователи и загрузки заездов за 7 суток,
  активные кофе-райды (опубликованы, старт впереди).
- **Сбои удаления аккаунтов** (erasure-failures, `platform.stats`, `/account-erasures`, вход — карточка «Обзора»):
  те же зависшие удаления (порог — сутки), самые давние первыми; аккаунт — «Участник ·<id>», время удаления, шаг и
  код последнего сбоя, число неудачных попыток, время последнего повтора — без e-mail, имени и текста ошибки.
  «Повторить удаление» — окно с обязательной причиной (журнал `account.erasure_retried`), очистка запускается заново
  со всех шагов; повтор в течение 15 мин без нового сбоя — «уже запрошен», без второй записи.
- Статуса API на «Обзоре» нет (решение пользователя 2026-10-29: заглушка admin-01 больше не нужна).

«Профили райдеров» (profile-moderation, `profiles.moderate`, вкладка «Модерации»): очередь «Открытые жалобы» —
профили с открытыми жалобами от последней жалобы к старым (подпись `Имя ·<id>` только при согласии райдера, иначе
`Участник ·<id>`; число жалоб и главная причина, при нескольких причинах — строка «Причины: …»; время последней; есть
ли фото и клуб), «Показать ещё». Над таблицей — вкладки «Все», «Имя», «Фото», «Клуб» (profile-moderation-followups):
фильтр по причине открытой жалобы, в адресе (`?reason=name|photo|club`; прочее — «Все»), «Показать ещё» листает внутри
вкладки; «Выдаёт себя за другого», «Спам», «Другое» — только во «Все» (строкой причин). Пусто — «Жалоб нет» / «Жалоб на
имя нет» / «Жалоб на фото нет» / «Жалоб на клуб нет». Карточка `/rider-profiles/:userId`: фото 128 px (или пустой квадрат) и клуб — и у скрытого райдером профиля
(модератор видит то, на что жаловались), статус «Публичный» / «Скрыт райдером», жалобы без автора. Действия «Сбросить
фото», «Сбросить клуб», «Сбросить имя» (неактивны, когда сбрасывать нечего) и «Отклонить жалобы» (при открытых) —
окно с обязательной причиной и предупреждением «Не повторяйте имя или клуб в причине»; сброс закрывает открытые
жалобы, райдер получает уведомление. Под клубом — «Сбросов фото за 180 дней: N» и, пока действует запрет загрузки
фото, «Загрузка фото запрещена до <дата, время>» (по Минску); при запрете — действие «Снять запрет» (окно с
обязательной причиной; история сбросов сохраняется — следующий сброс в окне снова запретит). Пришла новая жалоба после
открытия карточки — «Пришли новые жалобы, обновите карточку» с «Обновить». Правила
профиля и жалоб — `profile.md`.

Блок «Достижения» карточки райдера (achievements-panel, `achievements.manage` — только admin; API —
`/v1/admin/rider-achievements/:userId`; модератор блока не видит): все выдачи райдера, несезонные и сезонные, со статусом
(«выдано», «выдано вручную», «отозвано сверкой», «отозвано вручную»), объектом (нет — «Объект недоступен»), уровнем,
датой факта, ручным решением (сотрудник, дата) и колонкой «По фактам» (заработано и уровень / не заработано /
неизвестно). Действия — окно с обязательной причиной («причина видна команде»):

- **Выдать вручную** — код каталога и id объекта (гонка, маршрут, кофе-райд или сезон — по коду); объект проверяет
  сервер (гонка — опубликована или отменена; райд — опубликован, старт прошёл; маршрут — виден райдеру; сезон —
  завершён); уровень счётного — выбирает admin (по умолчанию бронза). Видимая выдача уже есть — отказ. Райдер видит
  вспышку и получает уведомление; автоматика не отзывает и не меняет выдачу, пока решение не снимут.
- **Отозвать вручную** — любую видимую выдачу; райдер видит молча, автоматика не вернёт её, пока решение не снимут.
- **Вернуть автоматике** — решение снимается, выдача сразу пересчитывается по фактам (у райдера, ещё не открывавшего
  достижения, — при первом входе).

Журнал — `achievement.granted_manually` / `achievement.revoked_manually` / `achievement.override_cleared`, объект
`Участник ·<id>`, детали — код, вид и id объекта, уровень (без имён и названий). Лимит — 60 действий в час на
сотрудника. Сезонные итоги недоступны — предупреждение «Сезонные достижения временно недоступны» (названия сезонов и
«По фактам» для них не показаны). В окне выдачи уже выданное несезонное достижение недоступно («— уже выдано»), id
объекта берётся из адреса его страницы в панели; подтверждение неактивно, пока id не похож на id (UUID). Ошибки —
в окне: объект не найден или не подходит (под полем id), выдача уже есть / уже отозвана (список перечитывается),
