### [MEDIUM] Возврат к загруженному набору шрифтов может оставить тему в ожидании
- **file:** apps/app/src/theme/use-theme-fonts.ts
- **location:** строки 27–46, `useClientThemeFonts`
- **problem:** Ветка `allLoaded(set)` завершает эффект, не обновляя состояние. Если A загружался, затем выбран уже загруженный B, завершение загрузки A игнорируется через `active = false`. При возврате к A сохранённое состояние всё ещё содержит `{ set: A, ready: false }`. Эффект видит загруженные шрифты и снова ничего не меняет.
- **why_it_matters:** `AppThemeProvider` продолжает показывать предыдущую тему, хотя шрифты запрошенной темы уже доступны. Повторные рендеры ожидание не снимают.
- **evidence:** Воспроизведено на фактическом хуке через React: A → `{ ready: false }`, загруженный B → `{ ready: true }`, завершение A, возврат к A → `Font.isLoaded('A') === true`, но `{ ready: false }`. Текущие тесты не проверяют возврат к набору после отменённого ожидания.
- **recommended_fix:** При `allLoaded(set)` синхронизировать состояние с `{ set, ...READY }` либо учитывать загруженность и при `state.set === set`. Добавить регрессионный тест A → B → завершение A → A.

### [MEDIUM] Middleware не обеспечивает заявленное ограничение запросов темы
- **file:** apps/app/src/features/appearance/ssr-theme.ts
- **location:** строки 25–27, `refreshSsrTheme`; вызывается из `src/app/+middleware.ts`
- **problem:** Каждый GET ожидает `fetchPublicForSsr`, но его кэш сохраняет только завершённые успешные ответы и 404. Одновременные запросы при пустом или истёкшем кэше не объединяются, а ошибки вообще не ограничивают частоту повторов.
- **why_it_matters:** При недоступном API каждая страница, включая вход и регистрацию, получает дополнительное ожидание до двух секунд. Параллельный трафик создаёт соответствующее число запросов к API, несмотря на заявленное в security checklist ограничение «≤ 1 запрос в 60 с на процесс».
- **evidence:** Проверка фактического `public-ssr.ts` в памяти: три одновременных обращения к `/v1/appearance` дали три вызова `fetch`; два последовательных отказа — два вызова. В helper отсутствует учёт незавершённых запросов; исключение возвращает `UNAVAILABLE` без кэширования.
- **recommended_fix:** Объединять параллельные обновления темы одной Promise и ограничивать повторные попытки после отказа, сохраняя последнюю известную тему. Добавить тесты параллельного обновления и повторных GET при недоступном API.
