# app-themes — 7 тем приложения на базе дизайн-системы, выбор темы в админке

Уровень: task3, слайсы A–D. Ветка `feature/app-themes` от `origin/develop`. Решения пользователя — `decisions.md`.
Связано: ADR-0014 (карты и стили OpenFreeMap), `packages/design-tokens/src/brand.ts`, база
`@rkarakulov/design-tokens` и `@rkarakulov/ui` (репозиторий app-foundation).

## 1. Title

Темы приложения: «Классика» (текущая) и 6 новых. Выбирает админ платформы, приложение применяет без перезапуска.

## 2. Goal

Владелец платформы хочет менять облик приложения райдера одним переключателем в «Протоколе». Ориентир — приватный
референс из 6 тем: «Атлас», «Хронометр», «Планировщик», «Журнал», «Навигация», «Типографика». Тема — набор
семантических токенов дизайн-системы. Компоненты читают только токены, а смена темы не требует правок экранов.

## 2.1 Продуктовые решения (пользователь, 2026-10-27)

| # | Вопрос | Решение |
|---|---|---|
| T1 | Чья тема | глобальная настройка платформы; личный выбор райдера — возможный follow-up, контракт его не блокирует |
| T2 | Когда применяется | при запуске и при возврате в приложение (native — AppState active, web — фокус вкладки); сразу, без перезапуска и без потери экрана; задержка до ~60 с из-за кэша публичного API |
| T3 | Светлая и тёмная схема | по характеру темы: Классика, Атлас, Планировщик, Журнал, Типографика — пара светлая/тёмная по системе; Хронометр и Навигация — всегда тёмные |
| T4 | Глубина | токены (цвета, шрифты, форма, плотность, иконки, карта, профиль) **плюс варианты раскладки** на главной, в карточке маршрута и таб-баре |
| T5 | Геометрия базовых компонентов | расширить базу app-foundation (форма — токены темы), выпустить новую версию `@rkarakulov/*`, обновить каталог |
| T6 | Админка | остаётся в теме `panel`; меняется только приложение (пользователь допускает и общую смену, если так проще — не проще) |

## 3. Scope

### Слайс A — база app-foundation (отдельный PR и релиз)

- `@rkarakulov/design-tokens`: необязательная группа ролей темы `shape`: радиусы `button`, `field`, `chip`, `card`,
  `sheet` и регистр подписи кнопки (`buttonCase: 'upper' | 'none'`). Дефолт базы — нынешняя геометрия (квадрат,
  заглавные): у проектов без `shape` поведение не меняется.
- `@rkarakulov/ui`:
  - компоненты (Button, TextField/FieldFrame, Chip, Pill, SegmentedControl, Banner и пр.) берут форму из
    `useTheme().shape ?? дефолт`;
  - `ThemeProvider` (контекст): проект передаёт набор тем и шрифты; `useTheme()`, `textStyle()`, `fontFamilyFor()`
    читают контекст, если он есть, иначе — `configureDesignSystem` (обратная совместимость);
  - смена значения провайдера перерисовывает потребителей без перемонтирования (навигация и состояние экранов
    сохраняются).
- Changeset → релиз через `release.yml` (Version Packages PR) → новая minor-версия.

### Слайс B — токены pokatim, «Классика», провайдер, карта, SSR

- `@pokatim/design-tokens`: реестр `appThemes: Record<AppThemeId, AppThemeDefinition>`, где
  `AppThemeId = 'classic' | 'atlas' | 'chrono' | 'planner' | 'journal' | 'navigation' | 'typography'`.
  `AppThemeDefinition`:
  - `schemes: { light, dark }` — роли базы плюс группы pokatim `map`, `surfaceBar`, новые `profile`
    (линия, заливка сверху и снизу для градиента, сетка) и `chart`; у тёмных тем `light === dark`;
  - `colorScheme: 'system' | 'dark'`;
  - `fonts`: семейства ролей `display` / `text` (веса базы) и стек для web;
  - `shape` (слайс A); `density: 'regular' | 'comfortable'` (отступы карточек и строк списка);
  - `icons: { weight, filled }` для `expo-symbols`;
  - `map: { basemap: 'light' | 'dark' }` по схеме — URL стиля по-прежнему из env (ADR-0014);
  - `layout`: `home`, `routeStats`, `profileFill`, `tabBar`, `routeCard` (варианты — слайс C; у «Классики» —
    нынешние).
- «Классика» = нынешние `light`/`dark` без визуальных изменений (снимки и контраст-тесты прежние). Тема `panel`
  админки не меняется.
- app: `AppThemeProvider` поверх `ThemeProvider` базы — активная тема и схема (`colorScheme` темы + системная);
  проектный хук `useAppTheme()` (токены pokatim, layout, icons). Все `theme === themes.dark` →
  `theme.map.basemap`. Компонент `Icon` (обёртка `SymbolView`, вес и заливка из темы).
- Шрифты: `fonts.ts` — ассеты по темам; `useFonts` грузит шрифты только активной темы; смена темы применяется после
  загрузки её шрифтов.
- web/SSR: тема определяется до рендера (в слайсе B — всегда `classic`, источник данных — слайс D); `+html.tsx`,
  `manifest`, `theme-color` — из активной темы; `window.__POKATIM_THEME__` для гидрации без мигания.

### Слайс C — 6 тем

- Палитры, шрифты (все с кириллицей, `@expo-google-fonts/*`): Атлас — Manrope; Хронометр — Roboto Condensed + Inter;
  Планировщик — Onest; Журнал — Golos Text; Навигация — Inter Tight + Inter; Типографика — Oswald + Inter.
- Характер по референсу (описание своими словами, сам референс в репозиторий не кладём):

  | Тема | Фон и поверхности | Акцент, линии | Раскладка |
  |---|---|---|---|
  | Атлас | светло-серый, белые скруглённые карточки | оранжевый, цветные линии маршрутов | главная: герой маршрута с картой и круглой кнопкой-стрелкой |
  | Хронометр | почти чёрный, тёмно-серые карточки | ярко-оранжевый, оранжевые линии | карточка маршрута: три крупные цифры плитками, профиль с градиентом |
  | Планировщик | тёплый бежево-серый | чёрные линии с вершинами | главная: плитки «Рекомендуемые» с мини-картами |
  | Журнал | светлый с зеленоватым оттенком | зелёный | список с зелёными контурами, зелёный профиль |
  | Навигация | тёмная карта во весь блок | синий или оранжевый | круглые кнопки карты, крупные цифры |
  | Типографика | светлый | оранжевый диагональный блок | огромные сжатые цифры км, полоса покрытия |

- Тёмные пары для светлых тем — по тем же ролям; контраст WCAG по `contrastPairs` для каждой схемы каждой темы.
- Варианты раскладки — компоненты-варианты в `features/home` и `features/routes`, выбор по `layout` темы. Данные —
  только существующие API (если контура маршрута нет в списке, контур рисуется по геометрии, если она уже есть,
  иначе вариант без контура — решает architect).

### Слайс D — API, админка, доставка темы

- contracts: `appThemeIdSchema`, `appearanceSchema { themeId, version, updatedAt }`, `updateAppearanceSchema
  { themeId, version }`; permission `appearance.manage` (в конец `PERMISSIONS`, только роль admin); audit action
  `appearance.theme_changed`, subject kind `platform` (в конец enum-ов, снимки тестов).
- api: модуль `appearance`, коллекция `platform_settings` (документ `_id: 'appearance'`; нет документа — `classic`,
  `version: 0`):
  - `GET /v1/appearance` — публичный, `PublicReadGuard`, `Cache-Control: public, max-age=60`;
  - `GET /v1/admin/appearance`, `PUT /v1/admin/appearance` — `PanelGuard` + `@RequirePermission('appearance.manage')`,
    оптимистичная блокировка `version` (409 при конфликте), аудит в той же транзакции.
- admin: пункт «Оформление приложения» (группа bottom, право `appearance.manage`), экран: 7 карточек-превью (мини-
  макет из токенов темы: фон, карточка, акцент, линия маршрута, шрифт), выбор, «Сохранить», баннер конфликта.
- app: `useAppearanceQuery` (публичный GET, refetch при фокусе/AppState); кэш native — SecureStore (`appTheme`),
  web — состояние SSR; сплэш держится до чтения кэша и шрифтов. Фолбэк — «Классика» (нет сети, неизвестный id).
- app server: middleware Express до `render` получает тему (`fetchPublicForSsr`, кэш 60 с, при ошибке — последняя
  известная или `classic`) и передаёт её в рендер.

## 4. Out of Scope

- Недельный график, кнопка «Поехать», запись и навигация заезда — нового функционала нет (экраны навигации и
  записи — только стилистика).
- Личный выбор темы райдером, предпросмотр темы в приложении, push-смена темы.
- Смена темы админки.
- Свои стили карт: подложка — светлая или тёмная из env (ADR-0014).

## 8. Risks / Assumptions / Open Questions

- R1. Релиз базы — внешний репозиторий; слайс B ждёт опубликованную версию. Если релиз невозможен (токен, CI) —
  стоп и вопрос пользователю.
- R2. SSR: тема глобальная → активная тема — состояние процесса сервера, одинаковое для всех запросов; гонка при
  смене темы во время рендера — максимум одна страница с перерисовкой после гидрации.
- R3. Шрифты: 7 семейств увеличивают бандл native (TTF ~1–2 МБ). web грузит только активные.
- R4. `expo-symbols`: вес и заливка зависят от платформы (iOS — `weight`, Android/web — Material Symbols) —
  architect проверяет API.
- R5. Контраст: у ярких акцентов (оранжевый на белом) — проверка WCAG; при провале — затемнённый оттенок для текста.

## 9. Acceptance Criteria

1. В `@pokatim/design-tokens` 7 тем одной формы; тесты: полнота ролей, контраст WCAG для каждой схемы, шрифты каждой
   темы разрешаются в подключённые файлы.
2. «Классика» визуально не меняется (существующие тесты зелёные без правки снимков).
3. В `apps/app/src` нет хардкода цветов, шрифтов и сравнений `=== themes.dark`; форма и иконки — из темы.
4. Смена темы в приложении применяется без перезапуска и без потери экрана (тест провайдера).
5. web SSR отдаёт HTML в активной теме (фон, `theme-color`, шрифты), гидрация без мигания.
6. API: публичный GET без авторизации; PUT — только с `appearance.manage` (403 иначе), 409 при устаревшей `version`,
   запись аудита; int-тесты.
7. Админка: экран «Оформление приложения» с 7 превью, сохранение и конфликт; админка остаётся в теме `panel`.
8. На dev: смена темы в админке → приложение в браузере в новой теме (проверены минимум 3 темы, включая тёмную).
9. `TURBO_CONCURRENCY=1 pnpm check` зелёный; два независимых ревью (Claude, Codex) — APPROVE.
