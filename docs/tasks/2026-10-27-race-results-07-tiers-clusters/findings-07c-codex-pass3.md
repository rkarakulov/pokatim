### [HIGH] Новый запрос участия в экранах спора не обрабатывает ошибки и отсутствие сети

- **file:** apps/app/src/features/races/disputes/rival-card.tsx; apps/app/src/features/races/disputes/dispute-form.tsx
- **location:** rival-card.tsx:109–120; dispute-form.tsx:179–189
- **problem:** Добавленный `useMyRaceEntry` проверяется только через `isPending`. Если результаты и споры уже доступны, а запрос участия приостановлен без сети, действие остаётся на бесконечном скелетоне без сообщения и повтора. Если запрос участия завершился ошибкой, `isPending` становится `false`: показывается действие подачи, а отсутствующая группа трактуется как разрешённая через `inOtherGroup(undefined, …)`. Ошибка участия, включая ошибку фонового обновления, нигде не показывается.
- **why_it_matters:** Нарушен AGENTS.md §4.12: ошибка нового блока данных должна показываться с повтором. Кроме того, при отказе загрузки участия исправление ограничения по группе перестаёт работать: пользователю снова предлагается заведомо недоступный спор на чужую группу. Серверная проверка сохраняется.
- **evidence:** Обе ветки используют `disputes.data && !entry.isPending`, обрабатывают только `disputes.isError` и вызывают повтор только для `disputes`. Проверка установленного TanStack Query в памяти подтвердила: после отказа запроса `isPending=false, isError=true`; без сети при отсутствии кэша — `isPending=true, fetchStatus='paused'`. Тесты новых экранов покрывают успешную загрузку участия, но не эти состояния.
- **recommended_fix:** Обработать запрос участия через `AsyncContent` либо эквивалентные состояния: при паузе без данных — «Нет соединения» с повтором; при ошибке — соответствующий баннер с `entry.refetch()`; при ошибке обновления сохранить данные и показать баннер. Пока участие не загружено, подачу не предлагать. Добавить тесты обоих экранов для отказа и приостановки запроса участия.
