### [MEDIUM] Обновление анкеты превращает нетронутые поля формы в изменения
- **file:** apps/admin/src/features/results/VerifiedDemographicsDialog.tsx
- **location:** 75–76, 87–92; `DemographicsBody`
- **problem:** Значения полей инициализируются через `useState` один раз, но тело PATCH сравнивает их с обновляемым `current`. Если повторный GET приносит изменённый другим сотрудником год, поле формы сохраняет старый год и автоматически считается изменённым. Последующее сохранение пола отправит также старый год, хотя пользователь его не редактировал.
- **why_it_matters:** Сохранение может незаметно отменить чужую правку демографии. Нарушается требование отправлять только изменённые пользователем поля.
- **evidence:** `DemographicsForm` сохраняет экземпляр благодаря `key={userId}` при обновлении `current.data`. При этом `birthYear` включается в запрос по сравнению с `current.birthYear`. Серверный `ProfileVerifiedAdminService.update` применяет переданные поля без проверки версии исходных значений.
- **recommended_fix:** Отслеживать изменённые пользователем поля отдельно; при обновлении данных синхронизировать нетронутые поля, сохраняя введённые изменения. Добавить тест: загрузка → правка пола → повторный GET с новым годом → PATCH содержит только пол и причину.

Предыдущие HIGH исправлены: финишёры запрашиваются отдельно с фильтром до ограничения ответа; ошибка обновления анкеты показывает баннер с повтором и сохраняет форму. Проверены связанные серверные фильтры, контракты, права, аудит, состояния данных, дизайн-система, i18n и документация. Миграции и обработчики очередей этим diff не меняются; приложение относится к отдельному 07c.
