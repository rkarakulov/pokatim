### [HIGH] Новые вкладки остаются на скелетоне без сети
- **file:** apps/app/src/features/races/results-table.tsx
- **location:** 275–285, 306–315
- **problem:** Первая загрузка группы или финишёров обрабатывает только `isError`, игнорируя `fetchStatus === 'paused'`. Если таблица уже загружена, затем соединение потеряно и пользователь открывает ещё не загруженную вкладку, запрос приостанавливается, а вкладка показывает бесконечный скелетон.
- **why_it_matters:** Нет сообщения «Нет соединения» и повтора. Это нарушение AGENTS.md §4.12 и acceptance 07c.
- **evidence:** При отсутствии данных и `isError === false` безусловно выводится `RowsSkeleton`. Запросы `useRaceResults` и `useRaceFinishers` используют стандартный сетевой режим; `src/lib/online-manager.ts` передаёт отсутствие соединения в TanStack Query.
- **recommended_fix:** Использовать `AsyncContent` для содержимого обеих вкладок либо явно обрабатывать приостановленный запрос без данных. Добавить тест: загрузить список вкладок, вызвать `onlineManager.setOnline(false)`, открыть незагруженную вкладку и проверить сообщение с повтором.

### [MEDIUM] После блокировки демографии форма продолжает отправлять отвергнутые значения
- **file:** apps/app/src/features/profile/verified-profile-form.tsx
- **location:** 121–127, 147–150, 184–202
- **problem:** После `VERIFIED_DEMOGRAPHICS_LOCKED` анкета перезапрашивается, но значения react-hook-form не синхронизируются с ответом. Пол и год становятся только читаемыми и показываются из `view.profile`, тогда как отправка использует прежние значения формы.
- **why_it_matters:** Например, пользователь выбирает другой пол, а первая Verified-заявка в другой сессии фиксирует исходный. После 409 интерфейс показывает исходный пол, но каждый следующий PUT снова отправляет изменённый и получает 409. Сохранить разрешённые изменения веса, роста или FTP без повторного открытия экрана нельзя.
- **evidence:** `defaultValues: valuesOf(view)` задаёт начальные значения; единственный `form.reset` вызывается после успешного PUT. В ветке 409 выполняется только `invalidateQueries`. Существующий тест 409 проверяет появление блока только чтения, но не повторное сохранение.
- **recommended_fix:** При получении заблокированной анкеты синхронизировать поля `gender` и `birthYear` с сервером, сохранив пользовательские изменения остальных полей. Продолжить тест 409 повторным сохранением и проверить корректное тело PUT.

### [MEDIUM] Pull-to-refresh не обновляет выбранную группу и финишёров
- **file:** apps/app/src/features/races/results-table.tsx
- **location:** 234–236
- **problem:** Новые запросы выбранной группы и финишёров создаются внутри таблицы, но не участвуют в обновлении карточки гонки.
- **why_it_matters:** Пользователь обновляет экран жестом, однако видимые результаты остаются прежними. Обновляется только группа по умолчанию; её новые счётчики могут отображаться вместе с устаревшими строками выбранной вкладки.
- **evidence:** В `race-detail.tsx:210–227` массив `refetchers` содержит только `results.refetch` запроса без `group`. `groupResults` и `finishers` имеют отдельные ключи кэша, а вызов `results.refetch()` их не обновляет.
- **recommended_fix:** При обновлении карточки перезапрашивать активные запросы под `raceResultsKey(id)` либо подключить запрос выбранной вкладки к общему refresh. Добавить тест обновления строк другой группы и финишёров через `RefreshControl`.
