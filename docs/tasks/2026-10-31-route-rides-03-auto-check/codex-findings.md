### [CRITICAL] Повтор события расширяет план сверх 20 маршрутов
- **file:** apps/api/src/modules/route-rides/route-ride-auto.processor.ts
- **location:** `run`, строки 87–90; `plan`, строки 100–118
- **problem:** При каждом запуске план строится заново. Маршруты с уже сохранённым автозаездом исключаются, а освободившиеся места занимают следующие маршруты. Для 21 подходящего собственного маршрута первый запуск создаёт 20 заездов, повтор того же события — ещё один.
- **why_it_matters:** Повтор задачи меняет результат успешной обработки и превышает лимит V2. Нарушена идемпотентность очередей из AGENTS.md §4.5. При ретрае после частичного успеха также проверяются маршруты за пределами исходных двадцати.
- **evidence:** `autoPlan` исключает маршруты с заездом группы, после чего `plan` снова набирает `maxRoutes`. Выполнение текущих `autoPlan` и `nearRoutes` подтвердило: первый план — 20 маршрутов, повторный — оставшийся 21-й. Существующий тест повтора использует один маршрут и этого не обнаруживает.
- **recommended_fix:** Сохранять исходный план до начала сверок и использовать его при повторных попытках; завершённое событие не должно формировать новый план. Добавить тест повторной обработки для 21 подходящего маршрута и ретрая после частичного успеха.

### [MEDIUM] Удалённый прошлый заезд исключает собственный маршрут из автопроверки
- **file:** apps/api/src/modules/route-rides/route-rides.policy.ts
- **location:** `autoPlan`, строки 81–95
- **problem:** Маршрут добавляется в `seen` до проверки живых активностей. Если все его прошлые активности удалены, он исключается из группы «уже ездил», а затем из собственных маршрутов тоже.
- **why_it_matters:** Собственный готовый маршрут перестаёт автоматически проверяться после удаления последней связанной активности, хотя остаётся подходящим по V2(б). Сиротские записи сохраняются до следующего ручного создания заезда.
- **evidence:** Для `ridden: [{ routeId: 'own', activityIds: ['deleted'], ... }]`, пустого `heads` и `own: ['own']` текущая функция возвращает `[]`. Причина — сочетание `seen.add(route.routeId)`, `alive.length === 0` и фильтра `!seen.has(routeId)`.
- **recommended_fix:** Разделить отсутствие живой истории и блокирующие условия V4. Маршрут без живой истории должен оставаться кандидатом из собственных готовых маршрутов. Добавить соответствующий unit-тест.

### [MEDIUM] Удалённые активности определяют приоритет маршрутов
- **file:** apps/api/src/modules/route-rides/route-rides.repository.ts
- **location:** `ridesByRoute`, строки 90–98; `route-rides.policy.ts`, строки 84–93
- **problem:** `lastStartedAt` вычисляется по всем сохранённым заездам, включая заезды с удалёнными активностями. Последующая фильтрация живых активностей не пересчитывает эту дату.
- **why_it_matters:** Маршрут с давним видимым заездом и недавно удалённым заездом получает приоритет перед маршрутом с более свежим видимым заездом. При ограничении 20 это меняет выбранные маршруты вопреки порядку V2 и AC-4.
- **evidence:** Агрегация использует `$max: '$activity.startedAt'` до проверки живости. `autoPlan` фильтрует `activityIds`, но сортирует по исходному `lastStartedAt`. Проверка текущей функции подтвердила сохранение приоритета по удалённому заезду.
- **recommended_fix:** Передавать даты вместе с идентификаторами активностей и вычислять последнюю дату только по живым заездам перед окончательной сортировкой. Добавить тест с удалённым самым свежим заездом.
