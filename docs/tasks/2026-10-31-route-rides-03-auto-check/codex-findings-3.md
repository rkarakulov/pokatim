### [CRITICAL] Повтор события после удаления задачи всё ещё расширяет исходный план

- **file:** apps/api/src/modules/route-rides/route-ride-auto.processor.ts
- **location:** `run`, строки 99–102; `plan`, строки 134–142
- **problem:** Исходный план сохраняется только в данных BullMQ. При повторной доставке события после удаления задачи он строится заново. `done` резервирует места только для успешных автозаездов; маршруты с `not_passed` нигде не сохраняются. Новый подходящий маршрут может занять их место.
- **why_it_matters:** Повтор уже обработанного события создаёт дополнительный результат и проверяет маршрут вне исходных двадцати. Нарушены идемпотентность очередей (AGENTS.md §4.5) и гарантия неизменного плана из task.md §8.2. Новый маршрут фактически получает запрещённый бэкфилл старой активности.
- **evidence:** Воспроизведено выполнением текущих `RouteRideAutoProcessor.run`, `autoPlan` и `nearRoutes` в памяти с подменёнными портами. Первый запуск: 20 собственных маршрутов, 19 результатов `passed`, один `not_passed` → `{ planned: 20, passed: 19 }`. Затем добавлен новый собственный маршрут первым в порядке. Повтор без данных удалённой задачи → `{ planned: 20, passed: 1 }`: проверен новый маршрут; суммарно проверен 21 различный маршрут. Существующий тест изменения входов использует сохранившуюся задачу, а тест удаления задачи — двадцать успешных результатов; сочетание отказа и изменения входов не покрыто.
- **recommended_fix:** Сохранять исходный план или маркер завершения по id события независимо от срока жизни BullMQ-задачи. Повтор после её удаления должен использовать исходный план либо завершаться без новых сверок. Добавить регрессионный тест приведённого сценария.

### [MEDIUM] Квота собственного маршрута вне скана истории проверяется после отсечения двадцати

- **file:** apps/api/src/modules/route-rides/route-ride-auto.processor.ts
- **location:** `plan`, строки 125–142; `checkRoute`, строки 175–184
- **problem:** Квота учитывается при построении плана только для маршрутов, попавших в `ridesByRoute(..., 200)`. Собственный маршрут вне этого скана добавляется через `ownReadyIds` без проверки квоты. Он занимает место в двадцатке и проходит дорогую сверку; заполненность обнаруживается только перед вставкой.
- **why_it_matters:** Нарушено AC-4: пропуски по квоте должны применяться до отсечения двадцати. Подходящий маршрут остаётся непроверенным, хотя место занял маршрут, для которого заведомо нельзя сохранить результат.
- **evidence:** Выполнение текущего процессора с подменёнными портами: 200 более свежих маршрутов истории сейчас невидимы; собственный маршрут со 100 живыми заездами находится вне скана; далее идут 20 подходящих собственных маршрутов. Получено `{ planned: 20, passed: 19 }`: заполненный маршрут вызвал `evaluate`, последний подходящий маршрут не проверен.
- **recommended_fix:** Для собственных кандидатов вне скана истории проверить число живых заездов до включения в ограниченный план. Добавить тест, где заполненный собственный маршрут находится за границей скана, а следующие двадцать должны быть проверены.
