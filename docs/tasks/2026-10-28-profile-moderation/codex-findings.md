### [HIGH] Ошибки обновления карточки скрываются при наличии данных
- **file:** apps/admin/src/features/rider-profiles/RiderProfileScreen.tsx
- **location:** строки 124–143, 215–240
- **problem:** Обработка ошибок выполняется только внутри `if (!profile.data)`. После успешной загрузки ошибка повторного запроса не показывает ни сообщения, ни кнопки повтора. Таблица также получает принудительные `isError: false` и `error: null`.
- **why_it_matters:** Если сброс выполнен успешно, а последующее перечитывание карточки завершилось сетевой ошибкой или 500, модератор продолжает видеть прежние поля и открытые жалобы без предупреждения. При 404 после удаления профиля остаются старая карточка и кнопки действий. Это нарушает AGENTS.md §4.12: ошибка обновления должна показываться баннером с повтором поверх сохранённых данных.
- **evidence:** `refresh()` инвалидирует запрос карточки, но ветка с `profile.data` нигде не проверяет `profile.isError`. `stale` устанавливается только при конфликте мутации. Общий `DataTable` умеет показывать ошибку обновления, однако переданные константы отключают эту обработку. В `features/rider-routes/RiderRouteScreen.tsx` уже реализованы отдельная обработка 403/404 и баннер ошибки перечитывания.
- **recommended_fix:** Обрабатывать 403/404 независимо от наличия кэшированных данных; при остальных ошибках обновления сохранять карточку и показывать баннер с повтором. Добавить тесты: успешная загрузка → ошибка перечитывания 500/сети; успешная мутация → ошибка перечитывания; успешная загрузка → 404.

Проверки исполнения: **NOT VERIFIED** — тесты и `pnpm check` не запускались в окружении с доступом только на чтение. Результаты исполнителя независимо не подтверждены. Файлы не изменялись.
