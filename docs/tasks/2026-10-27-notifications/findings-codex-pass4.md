### [MEDIUM] Поздняя регистрация старой сессии перезаписывает токен нового аккаунта

- **file:** apps/api/src/modules/notifications/notifications.repository.ts
- **location:** `registerToken`, строки 255–268
- **problem:** Находка pass 3 остаётся: запрос регистрации A, прошедший `AuthGuard` до выхода, может записаться после регистрации B того же Expo-токена.
- **why_it_matters:** Безусловный upsert возвращает владение устройством аккаунту A с отозванной сессией. Доставка B перестаёт находить токен, а доставка A удаляет его как принадлежащий мёртвой сессии. Push B пропадают до следующей регистрации.
- **evidence:** Фильтр записи — только `{ token }`, обновление — `$set: { userId, sessionId, ... }`. Проверка сессии происходит раньше, в `AuthGuard`, и с записью не сериализована. Клиентский таймаут выхода оставляет серверный запрос в полёте.
- **recommended_fix:** Через порт identity сериализовать проверку живой сессии и запись токена с отзывом сессии, используя транзакцию и общий замок аккаунта. Добавить конкурентный тест с одним токеном: остановить A перед записью → выйти из A → зарегистрировать B → продолжить A; владельцем должен остаться B.

### [MEDIUM] Порядок UUID внутри миллисекунды может отбросить последнее событие схлопывания

- **file:** apps/api/src/modules/notifications/notifications.repository.ts
- **location:** `writeNotices`, строка 137
- **problem:** Условие `sourceEventId: { $lt: sourceEventId }` считает лексикографически больший UUID более поздним событием. Используемый `uuidv7()` содержит случайные биты после времени и не сохраняет порядок генерации внутри одной миллисекунды.
- **why_it_matters:** Два последовательных события одного райда могут получить обратный порядок id. Тогда последнее событие не обновит уведомление: оно останется прочитанным или с прежним состоянием доставки, вопреки N7. Повтор после конфликта уникальности этого не исправляет — условие сравнения остаётся тем же.
- **evidence:** `node_modules/@rkarakulov/api-kit/dist/mongo/uuid.js` использует `randomBytes(16)` и записывает только `Date.now()` в первые шесть байт. Независимая проверка при фиксированном времени дала 49 убывающих соседних пар из 99. Новый тест гонки использует события с разницей в минуту и этот случай не покрывает.
- **recommended_fix:** Для схлопываемых событий использовать последовательность изменений райда, увеличиваемую атомарно вместе с доменной записью, и сравнивать её. Добавить тест двух последовательных событий в одну миллисекунду с обратным лексикографическим порядком UUID.
