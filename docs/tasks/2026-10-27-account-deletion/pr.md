# Удаление аккаунта райдера (экран 14 «Путь райдера»)

## Что

Без удаления из приложения App Store не примет приложение, а Google Play требует ещё и ссылку на удаление из веба.
Решения автора A1–A12 — `docs/product/account.md`, архитектура — ADR-0015.

- **contracts / api-client:** `POST /v1/account/delete` (`{ password }` → 204), коды `PASSWORD_INCORRECT` (403 — не
  401, чтобы клиент не ушёл в refresh/выход) и `ACCOUNT_PANEL_MEMBER` (409), причина `account_deleted`, действие журнала
  панели `account.deleted`; `api.deleteAccount`.
- **API, синхронно** (модуль-оркестратор `account`, своих коллекций нет): лимит 5/ч → член команды панели — 409 (A11)
  → пароль через `CredentialsCheck` (общие счётчики входа) → одна транзакция: `lockUserCredentials` первой операцией,
  `deletedAt`, отзыв **всех** сессий, гашение ссылок и токена регистрации, запись журнала панели, outbox
  `account.deletion-requested`. Web — cookie очищается, `no-store`.
- **API, фоновая очистка** (очередь `account-deletion`, идемпотентные шаги через порты модулей):
  profile → rides (отмена будущих своих райдов, снятие отметок, стирание подписи) → routes («Мои маршруты» с файлами) →
  devices (отзыв в Open Wearables, наши данные) → tracks (загрузки, заезды, файлы; попытки в открытых гонках снимаются)
  → identity (письмо «Аккаунт удалён», затем e-mail → HMAC-маркер, стираются дата рождения и хеш пароля). Повторный
  проход через 15 мин (поздние записи) и регламент раз в час для незавершённых. Опубликованные протоколы не меняются —
  строка «Участник». Append-only журналы не трогаются.
- **Регистрация** на адрес удалённого — тот же нейтральный отказ D-07 (по маркеру); вход и сброс — как для
  неизвестного адреса.
- **Приложение (iOS/Android/web):** «Профиль» → «Удалить аккаунт» → `settings/account/delete` (последствия, пароль,
  «Удалить навсегда»); гость по ссылке → «Вход» → возврат (адрес для Google Play). Удаление — под замком сессии, после
  успеха — локальный выход без sign-out и «Регистрация» с баннером «Аккаунт удалён». i18n, a11y.
- **docs:** `docs/product/account.md`, ADR-0015, runbook `docs/runbooks/account-deletion.md`, правила
  `pokatim-{db,security,backend,app,contracts}.md`, `profile.md` P4.

## Важно

- **Миграция `0023_account_deletion`** — только добавляет индексы (`userId` для `device_connections`,
  `device_imports`, `device_link_tickets`; частичный `users_erasure_pending_idx`). Данные не меняются. Порядок деплоя:
  миграция → API/worker.
- **Новая env `SUPPORT_EMAIL`** (необязательная): адрес поддержки в письме «Аккаунт удалён»; пусто — строки «напишите
  на …» нет. **До прода задать.**
- **Ручной шаг:** пользователя в Open Wearables ключ API удалить не может — runbook §1.
- **Юрист (D10):** хранение журналов согласий после удаления — проверить до прода.
- Смена `EMAIL_TOKEN_SECRET` снимает блок повторной регистрации со стёртых адресов (runbook §5).
- Откат API после первых удалений: удалённые аккаунты остаются недоступными (старый код проверяет `deletedAt`), но
  старая регистрация не ищет маркер — стёртый адрес снова регистрируется, а незавершённая очистка ждёт возврата кода.
