### [MEDIUM] Первый пройденный заезд не обновляет таблицу на карточке
- **file:** apps/app/src/features/routes/route-detail.tsx
- **location:** 372–381, `useBestRideChange`
- **problem:** Отсутствие лучшего заезда и отсутствие загруженных данных представлены одинаковым `undefined`. Когда опрос «Моих заездов» впервые возвращает лучший заезд, условие `was !== undefined` запрещает инвалидацию.
- **why_it_matters:** Если райдер остаётся на карточке во время проверки первого успешного заезда, «Мои заезды» уже показывают результат, а таблица «Другие» продолжает показывать прежнее состояние без собственной строки. Истечение `staleTime` само по себе запрос не запускает.
- **evidence:** Хук вызывается с `rides.data?.summary.best?.id`; переход `summary.best: null → { id: … }` превращается в `undefined → id` и пропускается строкой 378. Task §8.1 RC-B6 требует обновления таблицы при смене лучшего заезда на карточке.
- **recommended_fix:** Различить незагруженный список и загруженный список без лучшего заезда, например через `undefined` и `null`. Инвалидировать при переходе `null → id`. Добавить тест: список с проверяемым заездом без лучшего → опрос возвращает первый пройденный → таблица перезапрашивается.

### [MEDIUM] Возврат на экран не обновляет устаревшую таблицу
- **file:** apps/app/src/features/route-rides/queries.ts
- **location:** 107–122, `useRouteRideLeaderboard`
- **problem:** Запрос остаётся подписанным при уходе экрана в стек и не обрабатывает возврат навигационного фокуса.
- **why_it_matters:** На iOS/Android после перехода с таблицы в профиль другого райдера и возврата старые места, имена и строки сохраняются независимо от прошедшего времени. Заявленное обновление по фокусу не происходит, пока нет другого триггера запроса.
- **evidence:** В `useRouteRideLeaderboard` есть только `staleTime` и `enabled`. Соседний `useRouteRides` использует `useIsFocused()` и `subscribed: focused` для обновления при возврате. `lib/focus-manager.ts` отслеживает состояние приложения через `AppState`, а не переходы между экранами.
- **recommended_fix:** Применить существующий подход `useIsFocused()` / `subscribed: focused`. Добавить тест возврата на экран после истечения `DEFAULT_STALE_MS` с проверкой повторного запроса.
