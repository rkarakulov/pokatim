# 1. Title

Follow-up карточек для сторис (PR #139, #142) и приглашений панели (PR #141, ADR-0026).

# 2. Goal

Закрыть хвосты двух фич одним PR (мелко, task1/task2):

- A1. Смена темы показывала старую картинку карточки: ключ запроса статуса карточки без темы.
- A2. Экраны карточек (`/rides/invite`, `/achievements/story`, `/routes/story`, `/races/story`) без `robots: noindex`.
- A3. Карточку-приглашение райда никто не проверял глазами.
- B4. Повторно приглашённый (или повторно получивший роль) сотрудник упирался в старый TOTP.
- B5. Нет e2e «приглашение → письмо → вход».
- B6. «Ссылка действует 7 дней» — слово «дней» не склонялось.

# 3. Scope

Контракты, коллекции, очереди, env и миграции не меняются. Поведение API меняется в одном месте — снятие роли
(`PanelMembersService.revoke`) и повторная активация снятого (`activateIn`).

# 4. Решения

- **A1.** Сервер рисует карточку в теме запрашивающего (`RIDER_THEMES.themeOf`, хэш с `themeId`), а клиентский ключ был
  `[…, template]` — после смены темы TanStack Query отдавал кэш прошлой темы на `staleTime`. `useCardStatus` добавляет к
  ключу источника `useAppTheme().id` (одно место для всех четырёх карточек). `useCardFile` ключуется токеном — новый
  токен даёт новый файл. Тема меняется оптимистично: ответ, полученный до сохранения `PUT /v1/profile/theme`, — карточка
  прежней темы под новым ключом, поэтому успех `useSetTheme` инвалидирует статусы карточек (`invalidateCardStatuses`,
  метка `meta.cardStatus`: `cancelQueries`, затем `invalidateQueries` — запрос в полёте отменяется и повторяется). Отсчёт 30 с ожидания `pending` — по шаблону и
  теме (смена темы не наследует чужой отсчёт).
- **A2.** `noindexPageMetadata(title)` (`src/lib/page-metadata.ts`) — нейтральная мета без данных объекта + `noindex`;
  `generateMetadata` в четырёх маршрутах. `Disallow` в `robots.txt` остаётся: экраны только для вошедших; `noindex` —
  защита в глубину, если HTML всё же попадёт к краулеру в обход robots. Правило SEO (`pokatim-app.md`) и комментарий
  `seo.ts` дополнены этим исключением. Попутно `routes/story/[id]` получил `useSettingsShell` (правило:
  каждый экран `Stack.Protected` вне вкладок — за оболочкой) и строку в сторож `protected-shell.test.tsx`.
- **A3.** Превью серверного рендера (`pnpm --filter @pokatim/api preview:story-cards`) падало на карточках достижений —
  в фикстурах скрипта не было `level` после уровней достижений; до приглашений не доходило. Фикстуры дополнены, все
  карточки (7 тем × 2 шаблона) отрендерены и просмотрены: приглашение — заголовок, дата, день и время, место, линия,
  дистанция и темп; длинные название и место переносятся/обрезаются многоточием, без линии — без пустой рамки; «Ночь»
  — та же композиция, что у карточки маршрута. Экран в приложении покрыт `ride-invite.test.tsx`.
- **B4.** Причина — RC-13 задачи `2026-10-30-panel-invitations`: снятие роли не удаляло `panel_totp`, и при повторной
  активации (выдача, CLI, принятие приглашения) вход требовал код старого аутентификатора.
  `[ASSUMPTION]` 2FA — свойство члена команды (ADR-0024 п. 10): снятие роли в своей транзакции под `lockMember`
  удаляет 2FA (и незавершённое подключение) и доверенные устройства — без отдельной записи журнала (её покрывает
  `panel.role_revoked`); повторная активация снятого делает то же — для снятых до изменения. Вернувшийся подключает 2FA
  заново (admin при `PANEL_TOTP_ENFORCED` — `totpSetupRequired`). Альтернатива — хранить 2FA и дать выбор при
  возвращении — отвергнута: секрет ушедшего сотрудника хранить незачем, а «старый телефон» — частый случай. ADR-0026 —
  дополнение.
- **B5.** `apps/admin/e2e/invitations.spec.ts`: CLI `grant-admin` → вход → «Пригласить» адрес без аккаунта → письмо в
  Mailpit (`invitationLink`) → регистрация приглашённого в приложении → ссылка → токен убран из адреса → «Принять и
  войти» → «Обзор» с ролью; у админа — сотрудник в списке, приглашения нет. Помощник Mailpit обобщён
  (`lastMessageText`).
- **B6.** `admin.members.inviteLead` — плюральная форма `{count}` (`one/few/many/other`), как `calendar.daysLeft`.

# 6. Security checklist

- AuthN/AuthZ: не меняются; снятие роли по-прежнему `members.manage`, под `lockForChange`.
- Входные данные: без новых входов.
- Данные наружу: мета экранов карточек — без id объекта и данных, `noindex`.
- Злоупотребления: без новых эндпоинтов.
- Секреты и логи: удаление секрета TOTP снятого — меньше хранимых секретов; логов не добавлено.
- Аудит: `panel.role_revoked` в той же транзакции, что удаление 2FA.
