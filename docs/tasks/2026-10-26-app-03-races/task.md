# 1. Title

Приложение, блок 03: Гонки и сезон — вкладка «Гонки» (список с фильтрами, герой, группы «Скоро» / «Завершённые»,
курсорная пагинация), публичная карточка гонки по ссылке (SSR + OG), экран сезона (даты, гонки сезона, другие сезоны)
на read-модели admin-02 + три публичных эндпоинта сезонов

# 2. Goal

Райдер «Покатим» (iOS, Android, web/PWA) на вкладке «Гонки» видит не заготовку, а список гонок платформы: фильтры по
классу велосипеда и месяцу, герой «ближайшая гонка», затем остальные открытые и предстоящие («Скоро») и прошедшие
и отменённые («Завершённые»), с подгрузкой страниц. Нажатие на гонку (во вкладке и на герое Главной) открывает
карточку гонки — окно, дистанция, класс, покрытия, сезон, плановая дата протокола, описание, статус отмены с причиной.
Карточка — публичная ссылка: открывается без входа и без установки, в web — HTML с сервера и OG без ПДн; в приложении —
`pokatim://races/<id>`. Из вкладки и карточки — экран сезона: название, даты, фаза, гонки сезона, другие сезоны.

Гонка сейчас — анонс (ADR-0010 п. 9): коридора, участия, треков, результатов и сезонного рейтинга (FR-4) нет. Всё,
что от них зависит, — скрыто без заглушек «скоро» (как Q2 блока 02), перечень — §4.

Источники: прототип «03 Гонки и сезон» (`key-races`, конфиденциален — краткая карта в Приложении A); для связей —
«04 Результат» (`key-race-result`: анатомия детали гонки — только как ориентир расширения, в scope не входит) и
`key-home`; `docs/product/races-and-seasons.md`, `docs/product/home.md`; ADR-0003, ADR-0010;
`docs/tasks/2026-10-26-admin-02-seasons-races/task.md` §7 «Публичное чтение», §13; `docs/tasks/2026-10-26-app-02-home/task.md`
(Q6, R8, R9, §8.2); `AGENTS.md` §1, §4.1–4.4, §4.7, §4.11–4.13; `.claude/rules/{app,pokatim-app,contracts,pokatim-contracts,
backend,pokatim-backend,db,pokatim-db,security,pokatim-security,tests,pokatim-tests}.md`.

# 3. Scope

**Вкладка «Гонки» (`(tabs)/races.tsx`, все платформы, только для вошедших — как все вкладки)**
- Шапка: кикер/заголовок «Гонки» (`SectionHeader`), справа в слоте действия — secondary «{название сезона}»
  (Q3) → экран сезона; без лида прототипа (Q10). Шапка и фильтры видны сразу при любом состоянии данных.
- Фильтры (`FilterGroup` из `Chip`): «Класс» — Шоссе · ТТ · Гравий · МТБ (`BIKE_CLASSES`), «Дата» — три месяца от
  текущего по Минску (Q6). Внутри группы — ИЛИ, между — И (делает сервер, `RaceListQuery`). Активен хоть один чип —
  строка «Сбросить фильтры» (без «Найдено N», Q5). Предустановки класса из профиля нет (Q7, OQ40).
- Герой «Ближайшая гонка» / «Ближайшая по фильтрам»: первая запись `scope=current` — типографский `SectionHero`
  (даты окна крупно, название, мета «{км} км · класс «{класс}». Окно: {даты}, до {время}.», строка жизненного цикла
  по `phase`); нажимается → карточка. «Участвовать» скрыта.
- «Все гонки»: группа «Скоро» — остальные записи `current`; группа «Завершённые» — `scope=past` (закрытые и
  отменённые, новые сверху), подгружается после исчерпания `current` (Q4). Карточка в списке (`RaceListCard`):
  даты окна («4–12» + «октября»), км справа, название, «Класс «…» · покрытие: …», строка жизненного цикла
  (§7), у отменённой — нейтральный `Banner` с шаблонной причиной; нажатие → карточка гонки.
- Пагинация — курсор (`nextCursor`), `limit: 20`, подгрузка у конца списка, в подвале — скелетон карточки на время
  догрузки, ошибка догрузки — баннер с повтором в подвале (данные остаются).
- Состояния (§4.12): первая загрузка — скелетон героя и карточек под фильтрами; ошибка без данных — «Нет соединения» /
  «Не удалось загрузить» + «Повторить» (`AsyncContent`), чипы сохраняются; ошибка обновления при данных — баннер;
  пусто без фильтров — пустой герой «Пока нет открытых гонок» + «Календарь стартов» (→ вкладка «Календарь»), ниже —
  «Завершённые», если есть; пусто с фильтрами — `EmptyState` «Ничего не найдено» + текст по фильтрам + «Сбросить
  фильтры». Смена фильтра — скелетон на месте данных (R7).
- Обновление: pull-to-refresh (`usePullToRefresh`), фокус/возврат из фона (`focusManager`), `staleTime` 60 с.

**Карточка гонки (`src/app/races/[id].tsx`, публичная, вне гардов)**
- Шапка `DetailHeader`: «назад» (история есть — назад, нет — `/races` для вошедшего, `/` для гостя) и название в
  title bar. Без карты/коридора — типографский герой: кикер «Гонка · {класс}», даты окна крупно, название.
- Блок «Окно»: «Откроется / открыто / закрыто» по `phase` с датой и временем по Минску, «до 23:59» — из
  `windowEndsAt`; дистанция; класс; покрытия; сезон — ссылкой на экран сезона; «Протокол — {дата} (план)» (Q9);
  описание (многострочный текст как есть, без разметки и автоссылок); отменённая — `Banner` «Гонка отменена.
  Причина: {причина}.» (тот же текст, что обещает превью панели `admin.races.cancelPreview`, Q13), строк окна нет.
- `'unknown'` в фазе/классе/покрытии/причине — нейтрально (R9 блока 02): без строки и подписи.
- Состояния: скелетон раскладки; 404 и невалидный id — «Гонка не найдена» + «Все гонки» (R6); сеть/сервер —
  `AsyncContent`. Обновление — фокус, pull-to-refresh.
- Web SSR: `loader` — посев (`useLoaderSeed`), `generateMetadata(request, params)` — `<title>`, description и OG из
  публичных полей гонки (название, даты окна, класс, дистанция), `og:url` — `WEB_ORIGIN` + `/races/<id>`;
  не найдена/ошибка API — нейтральная мета + `robots: noindex` (R5). `DocumentTitle` после клиентской навигации.
- Deep link `pokatim://races/<id>` — штатно через Router (scheme `pokatim`). Universal/app links — слайс 5 (§4).

**Экран сезона (`src/app/seasons/[id].tsx`, публичный, вне гардов)** — Q1–Q3
- Шапка `DetailHeader`; заголовок «{название}» (`displayTitle`), даты «1 апреля–31 октября» + метка фазы
  (`Pill`: «Текущий» / «Предстоящий» / «Завершён»).
- «Гонки сезона»: `RaceListCard` по концу окна (сезон гонки — по концу окна), курсор; пусто — «В сезоне пока нет
  гонок» [ASSUMPTION]. «Другие сезоны» — строки (название, даты, фаза) → экран сезона.
- Таблицы сезона, места, переключателей класс/кластер, заметки о зачёте — нет (FR-4, §4).
- SSR как у карточки: `loader` (сезон), `generateMetadata` (название и даты), `og:url` `/seasons/<id>`.

**Главная (блок 02) — правка**

**API (S1–S2).**
- `SeasonRaceListQuery = strictObject({ limit 1–50, default 20; cursor: PageCursor.optional() })` — отдельная схема,
  не новый `scope` в `RaceListQuery` (R2). Курсор `{ k: windowEndsAt (UtcMinute), id }` — `decodeCursor`.
- `listSeasonRacesPublic(seasonId, after, limit)`: фильтр `{ seasonId, status: { $in: ['published','cancelled'] } }`
  (у черновика `seasonId: null`, условие по статусу — защита), курсор по `(windowEndsAt, _id)` возр., `limit + 1`.
  Сервис: `findSeason` → нет — `404 NOT_FOUND` (`domainError`), иначе страница. Порядок проверок: сначала сезон, потом

# 8. Risks / Assumptions / Open Questions

- **Общий IP SSR (R5).** `loader` и `generateMetadata` ходят в API с адреса web-сервера: все гости делят IP-лимит
  `public-read` (300/мин). Смягчение в задаче — кэш 60 с и отказ в `null` (страница догрузит данные из браузера со
  своего IP); при росте трафика — отдельный лимит для web-сервера (follow-up, секрет и инфраструктура — с человеком).
- **Коллизия маршрутов** `/races` (вкладка) и `/races/:id` (публичный) — проверить в S5 первым (R4).
- **`'unknown'` фаз результатов.** admin-04 добавит `provisional`/`final` в `RACE_PHASES`: эта сборка покажет такие
  гонки без строки окна (R9) — в «Завершённых» по `scope=past` они останутся, если сервер оставит их в `past`.
- **Свежесть.** `max-age=60` + `staleTime` 60 с: отмена видна с задержкой до ~2 мин — принято (как Главная).
- **Мягкий 404 web.** HTML «Гонка не найдена» отдаётся с `200` и `noindex`; `StatusError` в `loader` нарушил бы
  правило «ошибка API → `null`, не 500» — не используем (R6).
- **Рефакторинг Главной (S3)** — только перенос: тесты Главной зелёные без правок ожиданий.
- **Пустые данные на dev** — гонки и сезоны через панель (runbook, фикстура e2e блока 02).
- `[ASSUMPTION]` Тексты экранов — до ответа автора (Q11). Месяцы фильтра, группы, «Протокол ожидается» — Q6, Q4, Q9.

# 8.3 Security checklist

Затронуто: **публичные ссылки** (карточка гонки, сезон — SSR без входа), новые публичные эндпоинты API, SSR-запросы
web-сервера к API. `security.md`, `pokatim-security.md`, `pokatim-app.md` «Публичные экраны».

1. **AuthN/AuthZ.** Новые `GET /v1/seasons*` — без входа (Q14 admin-02), только `PublicReadGuard`; мутаций нет. Клиент
   вызывает публичные методы без Bearer (тест api-client). Экраны карточки/сезона не читают сессию для данных.
2. **Входные данные.** `:id` — pipe `Uuid` (иначе `400`), запрос — `SeasonRaceListQuery` strict (`limit ≤ 50`, курсор —
   `decodeCursor` с zod, мусор — `400`); в фильтр Mongo — только примитивы. Приложение: `id` из URL — `Uuid.safeParse`
   до запроса и до SSR-`fetch` (нет инъекции пути во внутренний API), `encodeURIComponent`.
3. **Данные наружу.** Только `SeasonCard`/`RaceCard`/`RaceDetail` — без `ownerUserId`, `version`, `createdAt`,
   `publishedAt`; черновик и неизвестная — одинаковый `404`. OG/`<title>`/HTML — только публичные поля гонки/сезона,
   без ПДн; `og:url` — из `WEB_ORIGIN`, не из `Host`. Описание — `Text` (без HTML/markdown, без автоссылок — XSS и
   фишинговые ссылки организатора не становятся кликабельными).
4. **Злоупотребления.** IP-лимит `public-read` 300/мин на все публичные; SSR — кэш 60 с и отказ в `null` при `429`
   (R5), общий IP web-сервера — риск §8, follow-up. Подгрузка страниц — только по прокрутке, без polling.
5. **Секреты и логи.** Новых env/секретов нет (`API_INTERNAL_URL`, `WEB_ORIGIN` — есть); SSR-ошибки не логируют URL
   с параметрами сверх пути; токены не участвуют.
6. **Аудит.** Только чтение — без аудита; append-only не затронут.

# 9. Acceptance Criteria

1. **Контракты:** `SeasonList`, `SeasonRaceListQuery` (лишний ключ, `limit` 0/51, мусорный курсор — ошибки);
   `SeasonCard` с незнакомой фазой — `'unknown'`. Старые схемы не менялись.
2. **API:** `GET /v1/seasons` — все сезоны новыми сверху, фазы по `CLOCK`, `public, max-age=60`; `GET /v1/seasons/:id`
   — сезон или `404`, `GET /v1/seasons/current` по-прежнему `200` (порядок маршрутов); `GET /v1/seasons/:id/races` —
   опубликованные и отменённые гонки сезона по концу окна, черновиков нет, курсор без пропусков и повторов на
   равных `windowEndsAt`, неизвестный сезон — `404`, невалидный id — `400`; превышение лимита — `429`; миграция
   `0009` идемпотентна, запрос — `IXSCAN` по новому индексу без `SORT`.
3. **Вкладка «Гонки» (iOS, Android, web):** шапка и чипы видны сразу, на месте данных — скелетоны; данные →
   герой первой `current`-гонки (даты по Минску в TZ ≠ Минск), «Скоро», затем «Завершённые» после исчерпания
   `current`; чипы класса/месяца перезапрашивают с `bikeClass`/`month`, «Сбросить фильтры» снимает все; без
   совпадений — «Ничего не найдено» + сброс; пусто без фильтров — пустой герой + «Календарь стартов» → вкладка
   «Календарь»; отменённая — баннер с причиной; подгрузка у конца списка, ошибка догрузки — баннер в подвале,
   загруженное остаётся.
4. **Строки окна:** `upcoming` / `open` (сегодня, завтра, позже) / `closed` (до и после плановой даты протокола) /
   `cancelled` / `'unknown'` — по §7, тест в `TZ=UTC`, `America/New_York`, `Asia/Tokyo`.
5. **Карточка гонки:** из списка, с героя вкладки и с героя Главной → `/races/<id>`; поля §3; ссылка сезона → экран

   — без сессии), «назад» без истории ведёт на `/races` (вошедший) или `/` (гость).
6. **Web SSR карточки и сезона:** `curl /races/<id>` — HTML с названием гонки и `og:title`/`og:description` до JS, без
   e-mail/владельца; `og:url` = `WEB_ORIGIN/races/<id>`; неизвестная — нейтральная мета + `noindex`, не `500`; API
   недоступен — HTML со скелетоном, не `500`; гидрация без ошибок (`pageerror`/`console.error` пусто).
7. **Экран сезона:** название, даты, метка фазы, гонки сезона (курсор), «Другие сезоны» → экран сезона; таблицы и
   мест нет. Кнопка сезона во вкладке — текущий, иначе ближайший предстоящий, иначе последний завершённый; сезонов
