### [MEDIUM] Сбой чтения сезонных итогов завершает задачу райдера успешно

- **file:** apps/api/src/modules/achievements/achievements-sync.processor.ts
- **location:** `rider`, строки 73–84; вызываемый `AchievementsReconciler.seasonOutcomes`
- **problem:** Новый worker вызывает сверку, которая перехватывает исключение `standings.outcomesOf` и возвращает пустой список сезонов. Процессор получает успешный результат и возвращает `'reconciled'`, хотя сезонные достижения не проверены.
- **why_it_matters:** Даже однократный сбой порта отключает предусмотренные три попытки и финальный лог ошибки. Курсор sweep уже продвинут; без следующего изменения фактов серверная выдача и push не повторятся. Задача исчезает как успешно выполненная.
- **evidence:** `AchievementsReconciler.seasonOutcomes`, строки 108–114: `catch` пишет `achievements.seasons_unavailable` и возвращает `[]`. `AchievementsSyncProcessor.rider` повторяет задачу только при исключении из `reconcile`. `AchievementsSweep` сохраняет курсоры после постановки задач, до их исполнения. Существующий тест отказа `outcomesOf` проверяет восстановление следующим GET; аналогичного сценария worker нет.
- **recommended_fix:** Для `origin: 'server'` передавать ошибку сезонного порта процессору либо возвращать признак неполной сверки, по которому процессор бросает исключение. Сохранить мягкий отказ для GET. Добавить интеграционный тест: однократный отказ порта → повтор задачи → сезонная выдача и уведомление.
