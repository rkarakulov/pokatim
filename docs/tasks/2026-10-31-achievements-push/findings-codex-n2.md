### [MEDIUM] Переход сезона из pending в final после отмены гонки не запускает сверку

- **file:** apps/api/src/modules/standings/rider-season-standings.ts
- **location:** settledRidersAfter, строки 87–102
- **problem:** Источник учитывает только `computedAt` и `endsBefore`. Если в конце сезона осталась гонка без протокола, первая серверная сверка увидит `pending`, но курсор сезона будет пройден. Последующая отмена этой гонки делает сезон `final`, не меняя оба времени.
- **why_it_matters:** Сезонные достижения не выдаются сервером и push не приходит до другого изменения фактов или открытия приложения. Сбой инфраструктуры для этого не нужен.
- **evidence:** `outcomesOf` проверяет `awaitingProtocol`; `RacesRepository.seasonsAwaitingProtocol` исключает отменённые гонки. `RacesService.cancel` допускает отмену опубликованной гонки без протокола. Такая гонка отсутствовала в `StandingsSource.load`, поэтому её отмена не меняет fingerprint; `StandingsRecalc.sync` пропускает пересчёт при равном fingerprint.
- **recommended_fix:** Учесть в источнике переход завершённого сезона `pending → final`, включая отмену последней гонки без протокола. Добавить интеграционный сценарий: конец сезона → сверка с `pending` → отмена → серверная выдача и уведомление без GET.

### [MEDIUM] Источник протоколов делает до 501 последовательного запроса за страницу

- **file:** apps/api/src/modules/results/rider-results.ts
- **location:** revisedRidersAfter, строки 87–97
- **problem:** После чтения страницы журнала для каждой ревизии последовательно вызывается `protocolRowUserIds`. При `pageRows: 500` источник выполняет 501 запрос вместо предусмотренных задачей 1–2.
- **why_it_matters:** Накопившиеся ревизии задерживают остальные источники и постановку всех задач райдеров. Стоимость прогона существенно превышает бюджет §5.D.
- **evidence:** Цикл `for (const { raceId, revision } of revisions)` содержит `await this.repository.protocolRowUserIds(...)`; этот метод выполняет отдельный `find(...).toArray()`.
- **recommended_fix:** Читать получателей всей страницы ревизий одним запросом по парам `(raceId, revision)` через существующий индекс, затем удалять повторы. Проверить бюджет запросов интеграционным тестом с несколькими ревизиями.

### [MEDIUM] Истечение замка допускает параллельные прогоны и откат курсоров

- **file:** apps/api/src/modules/achievements/achievements-sync.state.ts
- **location:** lock, строки 54–63; AchievementsSweep.sweep, запись курсоров
- **problem:** Замок истекает через пять минут без продления. Прогон не ограничен этим временем и перед записью курсоров не проверяет владение замком.
- **why_it_matters:** При долгом запросе или постановке задач следующий прогон захватит замок и продвинет курсоры. Старый прогон после возобновления может перезаписать их более ранними значениями. Требование «один прогон за раз» перестаёт выполняться.
- **evidence:** Используется однократный `SET NX PX`; проверка токена есть только при `unlock`. `setCursor` выполняет безусловный `SET`.
- **recommended_fix:** Продлевать аренду своим токеном и прекращать запись при потере владения; защитить сохранение курсоров проверкой токена. Добавить тест истечения аренды с двумя прогонами.
