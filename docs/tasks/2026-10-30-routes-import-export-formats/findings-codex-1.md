### [MEDIUM] Сигнатура EOCD внутри комментария ломает корректный KMZ
- **file:** packages/tracks/src/kmz.ts
- **location:** 79–85, `findEocd`
- **problem:** Поиск принимает первое с конца совпадение сигнатуры EOCD, не проверяя длину комментария. Допустимый комментарий ZIP может содержать эти же байты.
- **why_it_matters:** Корректный KMZ с таким комментарием получает `failed/unreadable`, хотя содержит читаемый `doc.kml`.
- **evidence:** Воспроизведено на `route-earth.kmz`: добавлен комментарий из 32 байтов с `PK\x05\x06` в начале, длина комментария настоящего EOCD обновлена. Исходник распаковывается в 10 838 байтов; архив с комментарием отвергается.
- **recommended_fix:** Для кандидата проверять `offset + 22 + commentLength === bytes.length`; при несовпадении продолжать поиск. Добавить тест на сигнатуру EOCD внутри комментария.

### [MEDIUM] KML не задаёт режим использования экспортированных высот
- **file:** packages/tracks/src/route-kml.ts
- **location:** 15, создание `LineString`
- **problem:** Высоты записываются в `coordinates`, но `altitudeMode` отсутствует.
- **why_it_matters:** Google Earth использует по умолчанию `clampToGround` и игнорирует переданные высоты. Обещанный экспорт высот фактически отображает высоты рельефа принимающего приложения.
- **evidence:** Выход содержит `<LineString><coordinates>` без режима высоты. Поведение по умолчанию описано в [документации KML](https://developers.google.com/kml/documentation/altitudemode). Тест обратного разбора этого не обнаруживает: `parseKml` не учитывает `altitudeMode`.
- **recommended_fix:** Для линии с высотами явно задавать `altitudeMode=absolute`; определить поведение при частично отсутствующих высотах. Добавить проверку семантики режима в тест экспорта.
