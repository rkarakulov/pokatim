# simplify-track-perf — `simplifyTrack` без O(n²) на стоянках

Уровень: task2. Follow-up maps-02 §8.2 D1 ([task](../2026-10-27-maps-02-own-track/task.md)).

## 1. Title

`simplifyTrack` (Дуглас — Пекер, `packages/tracks/src/simplify.ts`) — без квадратичного времени, результат тот же.

## 2. Goal

Приём заезда (`analyzeTrack`, поток разбора, таймаут 30 с) и маршрута (`analyzeRoute`) не упираются в упрощение
линии на длинных стоянках. Замер maps-02: 190 000 точек дрожания — 71 473 мс.

## 3. Scope

- Корень: на стоянке координаты повторяются; у точек с одинаковым расстоянием до хорды ничья, выбирается первая —
  каждое деление «отщипывает» одну точку от края и заново сканирует весь диапазон: O(n²) (воспроизведено: 10k / 20k /
  40k точек стоянки — 204 / 792 / 3192 мс, ×4 на удвоение).
- Поиск дальней точки диапазона — по выпуклым оболочкам дерева отрезков (вершины оболочки — реальные точки, повторы
  координат схлопнуты в меньший индекс). Расстояние до отрезка — выпуклая функция, её максимум на множестве
  достигается в вершине оболочки → тот же `argmax` (при ничьей — меньший индекс), что у полного перебора.
- Оболочки строятся лениво: пока суммарный перебор ≤ 64 проходов по точкам (сбалансированные деления обычного
  трека), поиск — прежним сканом; превысил 64 прохода — строится индекс (`farthest-point.ts`, из пакета не экспортируется).
  Результат от выбора пути не зависит.
- Удвоение допуска не пересчитывает Дугласа — Пекера: дерево делений от допуска не зависит, точка сохраняется при
  допуске `τ`, если минимум расстояний на её пути от корня `> τ²`.
- Вызовы (`parse.ts`, `story-card.png.ts`, тесты) и сигнатура не меняются.

## 4. Out of Scope

- Смена алгоритма упрощения (Visvalingam, расстояние до прямой) — меняет линии и `corridor-golden`.
- Хранимые линии `activity_tracks` / `route_geometries` — результат тот же, пересчёт не нужен.

## 5. Architecture Context / 5.1 Placement & Reuse Gate

- Только `packages/tracks`: `simplify.ts` (сигнатура `simplifyTrack` прежняя), новый внутренний модуль
  `farthest-point.ts` — `index.ts` его не реэкспортирует. Вызовы `parse.ts`, `apps/api` (`story-card.png.ts`) не
  меняются. Без новых зависимостей; классы без parameter properties (поток разбора грузит `.ts` через
  strip-types).

## 8. Risks / Assumptions

- Равенство с перебором точное в вещественной арифметике; в float ничья «вершина оболочки ↔ точка на ребре» —
  почти коллинеарные точки в оболочке сохраняются (допуск по векторному произведению). Подтверждение — golden на
  всех фикстурах + сверка с эталонным перебором на случайных треках (сетка, квантование, петли, стоянки).
- Худший случай остаётся сверхлинейным только на выпуклых кривых с несбалансированными делениями (оболочка = все
  точки) — не GPS-трек; для них время не хуже прежнего.

## 9. Acceptance Criteria

- AC1: `simplify-golden.json` (снят на старом коде) — все фикстуры `__fixtures__` и `__fixtures__/corridor`, профили
  вызовов (5/1000, 1/20000, 1/300, 5/50) — без изменений. `corridor-golden.json` не меняется.
- AC2: на случайных треках результат = эталонному перебору (старый алгоритм в тесте).
- AC3: 200 000 точек стоянки (в памяти теста) ≤ 2 с локально (×3 на CI); кольцо 200 000 — тест не хуже.
- AC4: `pnpm check` зелёный.

## 8.3 Security checklist

Н/п по существу: чистая функция без I/O. Злоупотребления — худший вход стал дешевле (стоянка — длинный трек на
пределе `TRACK_MAX_POINTS` больше не держит поток разбора десятки секунд); память индекса — в лимитах потока (бенч
Worker 160/32 МБ, 300k точек — heap 41–55 МБ, у прежнего 48–61 МБ).

## 8.2 Deviations from spec

- Нет. Сложность: на стоянке (ничьи) — O(n log n) запросов по O(log n) узлов с оболочками из нескольких вершин;
  в общем случае запрос стоит Σ размеров оболочек узлов ≤ размера диапазона — не хуже прежнего скана. Гарантии
  O(n log n) на любом входе нет (выпуклая кривая с несбалансированными делениями — оболочка = все точки), это не GPS.
  Память индекса — Σ оболочек узлов, худший случай n·log(n/16) индексов (≈ 2,8 млн на 200k), на стоянке — единицы.

## 10. Documentation Impact

- `.claude/rules/pokatim-tests.md` — golden упрощения; `.claude/rules/pokatim-backend.md`, комментарии
  `corridor/track-map.ts` и `parse.ts` (`analyzeAttempt`) — без «O(n²)». ADR и `docs/product` не затронуты.
