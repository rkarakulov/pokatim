# 1. Title

Приложение, блок 04: Календарь стартов — вкладка «Календарь» (фильтры «Дата» / «Дисциплина» / «Город», герой
«Ближайший старт», список по месяцам, курсорная подгрузка), публичная карточка старта по ссылке (SSR + OG,
`pokatim://calendar/<id>`) с переходом на регистрацию у организатора; герой старта на Главной ведёт в карточку.
Read-API календаря (ADR-0010) дополняется фазой старта и списком месяцев.

# 2. Goal

Райдер «Покатим» (iOS, Android, web/PWA) на вкладке «Календарь» видит не заготовку, а реальные массовые старты сезона:
фильтры по месяцу, дисциплине и городу, герой «ближайший старт» и остальные старты, сгруппированные по месяцам, с
подгрузкой страниц. Нажатие на старт (во вкладке и на герое Главной) открывает карточку: дисциплина, название, дата,
время и место старта, дистанции, описание и кнопка «Регистрация у организатора» — уход на сайт организатора в
системном браузере. Карточка — публичная ссылка: открывается без входа и без установки, в web — HTML с сервера и OG
без ПДн; в приложении — `pokatim://calendar/<id>`.

Старт календаря — внешнее событие (ADR-0010 п. 1): участия, загрузки трека и результатов у него нет. Медиа, комментарии
и перекрёстные ссылки на маршруты прототипа требуют модулей, которых ещё нет, — скрыты без заглушек «скоро» (§4).

Источники: прототип «Календарь» (`key-calendar`, конфиденциален — краткая карта без данных в Приложении A); для
связей — `key-home` (герой старта) и `key-races` (пустой герой «Календарь стартов» → вкладка);
`docs/product/races-and-seasons.md` «Календарь стартов», `docs/product/home.md`; ADR-0003, ADR-0010 (п. 1, 3, 6, 8);
`docs/tasks/2026-10-26-admin-02-seasons-races/task.md` (календарь, §13 «Публичное чтение»);
`docs/tasks/2026-10-26-app-03-races/task.md` (образец: §5.1, §7, §8.1 R4–R8, §8.2); `AGENTS.md` §1, §4.1–4.4, §4.7,
§4.11–4.13; `.claude/rules/{app,pokatim-app,contracts,pokatim-contracts,backend,pokatim-backend,db,pokatim-db,
security,pokatim-security,tests,pokatim-tests}.md`.

Нумерация: в `docs/product/home.md` и блоке 03 карточка старта названа «блок 09» — это и есть настоящий блок 04
(документы поправить, §10).

# 3. Scope

**Вкладка «Календарь» (`(tabs)/calendar.tsx`, сейчас `ScreenPlaceholder`; все платформы, только для вошедших)**
- Шапка: `SectionHeader` — кикер «Календарь», заголовок «Календарь стартов»; под ним лид «Реальные старты сезона.
  Регистрация — у организаторов.» (Q6). Шапка и фильтры видны сразу при любом состоянии данных.
- Фильтры (`FilterGroup` из `Chip`), три группы, внутри — ИЛИ, между — И (делает сервер, `CalendarQuery`):
  - «Дата» — месяцы, в которых есть будущие опубликованные старты (новый `GET /v1/calendar/months`, Q2); подпись —
    «Июнь», не текущего года — «Июнь 2027» (`monthChipLabel`);
  - «Дисциплина» — Шоссе · Гравий · МТБ (`DISCIPLINES`; «Циклокросс» прототипа — нет в справочнике, Q11);
  - «Город» — `GET /v1/calendar/cities` (уже есть).
  Группы «Дата» и «Город» до ответа — подпись + скелетон ряда чипов; ошибка или пусто — группа скрыта (список
  работает без неё). Активен хоть один чип — «Сбросить фильтры» (без «Найдено N», Q5). Выбранное значение, которого
  больше нет в ответе (месяц прошёл, город ушёл) — снимается молча.
- Герой «Ближайший старт» / «Ближайший по фильтрам» — первая запись списка, типографский `SectionHero` (кикер, дата
  крупно, название, мета «{дистанции} · {дисциплина} · {город}», строка «До старта N дней.» / «Старт сегодня.» /
  «Идёт сейчас.», при ссылке — «Регистрация у организатора.» текстом) — тот же герой, что на Главной; нажимается →
  карточка.
- «Все старты»: остальные записи, сгруппированы по месяцу начала — подпись группы «Июнь 2027» (всегда с годом).
  Строка списка (`CalendarListRow`): рамка даты (день «14» / «26–27» + месяц), название, мета, роль `link`; нажатие →
  карточка. Шеврона нет (иконок в системе нет, §5.1).
- Пагинация — курсор (`nextCursor`), `limit: 20`, `FlatList` + `onEndReached`, в подвале — скелетон строки на время
  догрузки, ошибка догрузки — баннер с повтором в подвале (данные остаются).
- Состояния (§4.12): первая загрузка — скелетон героя и строк под фильтрами; ошибка без данных — «Нет соединения» /
  «Не удалось загрузить» + «Повторить» (`AsyncContent`), чипы сохраняются; ошибка обновления при данных — баннер;
  без сети при данных — `OfflineBanner`; пусто без фильтров — `EmptyState` «Пока нет стартов в календаре»; пусто с
  фильтрами — `EmptyState` «Ничего не найдено» + «Нет стартов по выбранным фильтрам.» + «Сбросить фильтры». Смена
  фильтра — скелетон на месте данных (как R7 блока 03).
- Обновление: pull-to-refresh (`usePullToRefresh`: список, месяцы, города), фокус/возврат из фона (`focusManager`),
  `staleTime` 60 с.

**Карточка старта (`src/app/calendar/[id].tsx`, публичная, вне гардов)**
- Шапка `DetailHeader`: «Назад» (история есть — назад, нет — `/calendar` вошедшему, `/` гостю) и название в title bar.
- Типографский герой без обложки: кикер «Календарь», строка «{Дисциплина} · массовый старт · вне приложения», название,
  дата крупно — всегда с годом («14 июня 2027», многодневный «26–27 июня 2027»); строка «Старт в {время} · {город},
  {место}» (нет времени — «{город}, {место}», нет места — без него).
- Дистанции — `StatBlock`: «100 км», «60 км» с подписью «Дистанция» у каждой (Q7).
- Регистрация: есть безопасная ссылка (`RegistrationUrl.safeParse`, только `https`) и фаза не `finished` — primary
  «Регистрация у организатора» + строка «Откроется сайт организатора. Регистрация и оплата — там.»; нажатие — системный
  браузер (native `Linking.openURL`, web — новая вкладка `noopener,noreferrer`, Q4). Фаза `finished` — вместо кнопки
  строка «Старт прошёл.» (Q8); фаза `ongoing` — строка «Идёт сейчас.» над кнопкой. Ссылки нет или она не `https` —
  кнопки нет, строки-пояснения нет.
- «О старте» — описание как есть (`Text selectable`, без разметки и автоссылок).
- `'unknown'` в дисциплине и фазе — нейтрально (R9 блоков 02/03): без подписи / без строки.
- Состояния: скелетон раскладки; 404 (снятый, неизвестный) и невалидный id — «Старт не найден» + «Все старты»; сеть /
  сервер — `AsyncContent`; `OfflineBanner`. Обновление — фокус, pull-to-refresh.
- Web SSR: `loader` — посев (`useLoaderSeed`), `generateMetadata(request, params)` — `<title>`, description и OG
  из публичных полей («14 июня 2027 · Шоссе · Минск · 100 км»), `og:url` — `WEB_ORIGIN` + `/calendar/<id>`; не найден —
  нейтральная мета + `robots: noindex`; API недоступен — нейтральная мета без `robots`. `DocumentTitle`.
- Deep link `pokatim://calendar/<id>` — штатно через Router (scheme `pokatim`). Universal/app links — слайс 5 онбординга.

**Главная (блок 02) — правка**
- Герой раздела «Календарь стартов» нажимается → `/calendar/<id>` (снимает Q6 блока 02 для старта). Тексты и

# 4. Out of Scope

Части прототипа без своего модуля — скрыть без заглушек «скоро» и без «на вырост»:
- **медиа:** обложка старта и фото-герой со скримом и кроссфейдом, галерея «Фото и видео» — модуль медиа (S3,
  подписанные URL, модерация D-30); поле обложки в панели;
- **комментарии:** список, поле, «Отправляется…», правка/удаление своего (OQ51), «Войдите, чтобы оставить комментарий»
  и «Войти» гостя в шапке (D-74) — модуль комментариев с модерацией по жалобам;
- **перекрёстные ссылки** «Этот старт в других разделах» (маршруты похожей дистанции, D-66, Story 3.3) — блок маршрутов;
- **«Регистрация открыта»** — статуса регистрации в модели нет; **«Найдено N стартов»** — нет `total` (Q5);
- **«Циклокросс»** и другие дисциплины — расширение справочника (contracts + панель, только в конец `DISCIPLINES`, Q11);
- **подписи дистанций** «Основная / Короткая» — в модели только числа (Q7);
- **прошедшие старты в списке** (архив) — список с сегодняшнего дня по Минску (`from`), как прототип (Q9);
- **«рядом» по геопозиции** — у старта нет координат (только город и место текстом); нужны поле координат в панели,
  геокодирование и foreground-геопозиция — фича «рядом» (Q13);
- **кофе-райды в календаре** — отдельная сущность и вкладка «Райды» (ADR-0010 п. 1); смешанная лента — продуктовое
  решение вне MVP (Q13);
- **поделиться**, OG-картинка 1200×630 — блок шеринга; «Добавить в календарь устройства» (.ics) — нет в прототипе;
- universal / app links (AASA, assetlinks) — слайс 5 онбординга; возврат к объекту после регистрации — с первым
  действием на карточке, которое требует входа;
- гостевая вкладка «Календарь» (вкладки — только для вошедших, Q5 блока 02);
- шеврон в строке и значок внешней ссылки на кнопке — иконок в дизайн-системе нет (кандидат в базу, §5.1);
- изменения app-foundation (кандидаты — §5.1); изменения панели и модели календаря admin-02.

# 5. Architecture Context

- **api, calendar:** `CalendarPublicController` — `@Get('months')` **до** `@Get(':id')` (иначе `months` уйдёт в pipe
  `Uuid` → `400`, как `cities`) → `CalendarPublicService.months()` → `CalendarRepository.months(from, cap)` (новый,
  агрегация по `calendar_starts`). Фаза — чистая функция `calendarPhase(doc, today)` (`calendar.policy.ts`, новый) в
  приватном `card()` сервиса; «сегодня» — `minskToday(CLOCK.now())`, как `from`. Модули `races`, `panel` — не трогаются.
- **db:** миграций нет. `months` — тот же `$match`, что `cities` (`status` + `endsOn/startsOn ≥ from`), коллекция —
  десятки/сотни записей; индекс `calendar_starts_public_idx` покрывает префикс `status`. Номер `0013` не занимается.
- **contracts:** `calendar/calendar-public.schema.ts` — `CALENDAR_PHASES`, `CalendarPhase`, `phase` в
  `CalendarStartCard` (`tolerantEnum`), `CalendarMonths`, `CALENDAR_MONTHS_CAP`; комментарий у `CalendarStartCard`
  («`registrationUrl` нет — кнопки регистрации нет») устарел — поправить. Только добавления: старые сборки (Главная
  блока 02) отбрасывают незнакомое поле (`z.object` без `strict`).
- **app:** вкладка `src/app/(tabs)/calendar.tsx`; публичный маршрут `src/app/calendar/[id].tsx` в корневом `Stack` вне
  `Stack.Protected` (как `races/[id]`); фича `src/features/calendar/` (`queries.ts`, `filters.ts`, `format.ts`,
  `registration.ts`, `calendar-feed.tsx`, `calendar-detail.tsx`, `calendar-hero.tsx`); внешний переход —
  `src/lib/open-external-url(.web).ts`; продуктовые компоненты `src/components/{calendar-list-row,stat-block}.tsx`.
- **Маршруты:** `(tabs)/calendar.tsx` → `/calendar`, `calendar/[id].tsx` → `/calendar/:id` — та же схема, что
  `/races` ↔ `/races/:id` (проверена в блоке 03); проверка — `app-routes.ts` + `build:web` + `curl` в S5.
- **Очереди/outbox:** нет. **Аудит:** нет (только чтение).
- **Порядок:** S1 → S2 (API) ∥ S3 (перенос в app) → S4 → S5 → S6. S2 и S3–S5 не пересекаются по файлам.

**API (S1–S2).**
- `calendarPhase({ startsOn, endsOn }, today)`: `startsOn > today` — `upcoming`; `(endsOn ?? startsOn) < today` —
  `finished`; иначе `ongoing`. Только строки `LocalDate` (лексикографическое сравнение `YYYY-MM-DD`), без `Date`.
  Граница — 00:00 Минска (`minskToday`), тест на 20:59:59Z / 21:00:00Z UTC.
- `CalendarRepository.months(from, cap)`: `$match` как `cities`; `$project` — `[substr(startsOn,0,7),
  substr(endsOn ?? startsOn,0,7)]`; `$unwind`; `$match m ≥ from.slice(0,7)` (идущий многодневный, начавшийся в прошлом
  месяце, не даёт прошлый месяц); `$group` по месяцу; `$sort` возр.; `$limit cap`. Многодневный ≤ 14 дней — максимум
  два месяца. Ответ разбирается `YearMonth` в сервисе (защита от мусора в БД — как `cities`).
- `CALENDAR_MONTHS_CAP = 24`: на e2e-БД месяцы реальных стартов + `9001-06`; при > 24 месяцах вперёд хвост обрезается
  (R5).

**Вкладка «Календарь».**
- **Ключи:** `['calendar','list',{ discipline, city, month, limit: 20 },'pages']` (`useInfiniteQuery`; суффикс
  `'pages'` — форма `InfiniteData` ≠ ключ Главной `['calendar','list',{limit:1}]`, префикс общий); значения фильтров
  отсортированы (`toggle`). `['calendar','months']`, `['calendar','cities']`, `['calendar','detail',id]`.
  `staleTime: 60_000`. `from` не передаём — «сегодня» берёт сервер.
- **Фильтры (`features/calendar/filters.ts`, чистые функции):** `CalendarFilters { discipline: Discipline[];
  city: string[]; month: YearMonth[] }`, `NO_FILTERS`, `hasFilters`, `withinAvailable(filters, { months, cities })`
  (снять исчезнувшие значения; значения чипов города — ровно строки ответа `cities`, клиент их не нормализует —
  регистр и пробелы сводит сервер через `cityKeyOf`). Лимиты `CalendarQuery` (12 городов, 12 месяцев): чипов может быть больше — при выборе
  13-го значение не добавляется [ASSUMPTION; на текущих данных недостижимо].
- **Лента (`useCalendarFeed(filters)`)**: одна выдача (без `scope`); герой — `pages[0].items[0]`; остальное — строки с
  подписями месяцев: `groupByMonth(items)` → плоские элементы `{ kind: 'month', month } | { kind: 'start', start }`
  (подпись — при смене `startsOn.slice(0,7)` между соседними, поперёк страниц). Многодневный через границу месяцев — в
  группе месяца начала (R8). Список — `FlatList`, не `ScrollView` + `map`.
- **Часы:** вкладка без SSR — `useMinskClock` (как Главная): «До старта N дней» и год в датах — по «сейчас».
- **Подписи строки:** дата — `formatLocalRange(startsOn, endsOn ?? startsOn, now)` (день/диапазон + месяц; год — если
  не текущий); мета — `calendarMeta` (как Главная: «80 и 120 км · Гравий · Нарочь», Q15). Метка для скринридера:
  «{название}. {дата}. {мета}».

**Карточка старта (публичная).**
- Корневой `Stack`: `<Stack.Screen name="calendar/[id]" />` вне `Stack.Protected` (рядом с `races/[id]`).

  показывает).
- **Регистрация (`features/calendar/registration.ts`):** `registrationLink(start): string | null` —

- **Доступность:** строка и герой — роль `link`, одна метка; подписи групп месяцев — роль `header`; `StatBlock` —
  одна метка «Дистанция 100 км» на ячейку; кнопка регистрации — подпись говорит, куда ведёт, пояснение — видимым

**Главная.** `CalendarStartHero` (теперь из `features/calendar`) получает `onPress` → `router.push('/calendar/<id>')`;
«Регистрация у организатора.» на герое — по-прежнему текст.

# 8. Risks / Assumptions / Open Questions

- **Общий IP SSR** — как R5 блока 03: кэш 60 с в `public-ssr.ts`, отказ в `unavailable`; доверенный IP web-сервера —
  follow-up (уже записан в блоке 03).
- **Коллизия маршрутов** `/calendar` ↔ `/calendar/:id` — схема та же, что у гонок (работает); проверка — S5 шаг 1.
- **Открытие ссылки на web из PWA (standalone).** `window.open` из установленной PWA на iOS открывает Safari / вкладку
  в системном браузере — это и нужно; блокировщик всплывающих окон не срабатывает, потому что вызов — в обработчике
  нажатия (не после `await`). `openExternalUrl` не должен ничего ждать до `window.open`.
- **Фаза на старых сборках.** Сборки блока 02 поле `phase` отбрасывают; новые значения фазы (если появятся) — в конец
  `CALENDAR_PHASES`, у старых — `'unknown'` → без строки.
- **Месяцы > 24** — хвост чипов обрезается (R5); список стартов от этого не страдает (фильтр не выбран = все).
- **Свежесть.** `max-age=60` + `staleTime` 60 с + SSR-кэш: снятый с публикации старт может быть виден до ~2 мин.
- **Мягкий 404 web** — HTML 200 + `noindex` (как карточка гонки, R6 блока 03).
- **Перенос Главной (S3)** — только перенос: `home.test.tsx` зелёный без правок ожиданий, кроме нового «герой старта
  нажимается».
- **Данные на dev** — 7 опубликованных стартов 2027 (панель); e2e — свои старты 9001 года через API панели.

# 8.3 Security checklist

Затронуто: **публичная ссылка** (карточка старта — SSR без входа), новый публичный эндпоинт и поле API, **внешние
ссылки организатора** (переход на чужой сайт), SSR-запросы web-сервера к API. `security.md`, `pokatim-security.md`
(модуль `calendar`, `public-read.guard.ts`), `pokatim-app.md` «Публичные экраны».

1. **AuthN/AuthZ.** `GET /v1/calendar/months` — без входа (Q14 admin-02), только `PublicReadGuard`; мутаций нет. Клиент
   вызывает публичные методы без Bearer (тест api-client). Карточка не читает сессию для данных (только для «назад»).
2. **Входные данные.** `months` — без параметров; `:id` — pipe `Uuid` (иначе `400`); запросы списка — `CalendarQuery`
   strict (как есть). Приложение: `id` из URL — `publicPath` (`Uuid.safeParse` + `encodeURIComponent`) до запроса и до
   SSR-`fetch`; значения чипов — только строки ответов API.
3. **Данные наружу.** Только поля `CalendarStartCard`/`Detail` (+ `phase`) и `CalendarMonths` — без `createdByUserId`,
   `cityKey`, `status`, `version`, `unpublishedAt`; снятый и неизвестный — одинаковый `404`. OG/`<title>`/HTML — только
   публичные поля старта, без ПДн; `og:url` — из `WEB_ORIGIN`, не из `Host`. Описание — `Text` без разметки и автоссылок.
4. **Внешние ссылки.** Источник — только панель (`calendar.manage`), ввод — `RegistrationUrl` (только `https`, без
   учётных данных, ≤ 500). Клиент повторно проверяет той же схемой: не `https` / `javascript:` / `data:` /
   `user:pass@` — кнопки нет. Web — `window.open(url, '_blank', 'noopener,noreferrer')` (нет `window.opener` —
   защита от tabnabbing, без Referer); native — системный браузер через `Linking.openURL`, не WebView (адресная строка
   видна, cookie и платёжные данные приложения не доступны сайту). URL не логируется ни при успехе, ни при ошибке.
   Открытие — только по нажатию пользователя (не автоматически, не из deep link).
5. **Злоупотребления.** IP-лимит `public-read` 300/мин на `months` (как на все публичные); агрегация ограничена
   `$limit 24` и `$match` по индексированному `status`; SSR — кэш 60 с и `unavailable` при `429`. Подгрузка — только по
   прокрутке, без polling.
6. **Секреты и логи.** Новых env/секретов нет (`API_INTERNAL_URL`, `WEB_ORIGIN` — есть); SSR-ошибки не логируют URL.
7. **Аудит.** Только чтение — без аудита; append-only не затронут.

# 9. Acceptance Criteria

1. **Контракты:** `CalendarStartCard.phase` — `upcoming`/`ongoing`/`finished`, незнакомое значение — `'unknown'`;
   поле обязательно для нового клиента (он работает только с новым сервером), старые сборки его отбрасывают;
   `CalendarMonths` — мусорный месяц в ответе — ошибка разбора; `CalendarQuery` и остальные поля карточки не менялись.
2. **API:** `GET /v1/calendar*` возвращает `phase` по `CLOCK` (граница 00:00 Минска; однодневный сегодня — `ongoing`;
   многодневный идущий — `ongoing`; вчерашний по ссылке — `finished`); `GET /v1/calendar/months` — месяцы будущих
   опубликованных, многодневный через границу — оба месяца, начавшийся в прошлом месяце — без прошлого месяца, снятые
   — нет, возр., ≤ 24, `public, max-age=60`; `GET /v1/calendar/cities` и `/:id` по-прежнему `200`/`404` (порядок
   маршрутов), `GET /v1/calendar/months` не уходит в `:id`; `429` на 301-м запросе.
3. **Вкладка (iOS, Android, web):** шапка, лид и группа «Дисциплина» видны сразу, «Дата» и «Город» — скелетон ряда до
   ответа, ошибка — группа скрыта; данные → герой первого старта, «Все старты» с подписями месяцев; чипы перезапрашивают
   с `discipline`/`city`/`month`, «Сбросить фильтры» снимает все; без совпадений — «Ничего не найдено» + сброс; пусто —
   «Пока нет стартов в календаре»; подгрузка у конца списка, ошибка догрузки — баннер в подвале, загруженное остаётся;
   даты по Минску в TZ ≠ Минск.
4. **Карточка:** из строки, героя вкладки и героя Главной → `/calendar/<id>`; поля §3; кнопка — только при `https`-ссылке
   и фазе ≠ `finished`; нажатие → `openExternalUrl(url)` (native `Linking.openURL`, web `window.open` с
   `noopener,noreferrer`); `finished` — «Старт прошёл.» без кнопки; `ongoing` — «Идёт сейчас.»; `http://` и
   `javascript:` ссылки — без кнопки; `404`/невалидный id — «Старт не найден» + «Все старты»; гость открывает без входа,
   «назад» без истории — `/calendar` (вошедший) или `/` (гость).
5. **Web SSR:** `curl /calendar/<id>` — HTML с названием и `og:title`/`og:description` до JS, без ПДн; `og:url` =
   `WEB_ORIGIN/calendar/<id>`; неизвестный — нейтральная мета + `noindex`, не `500`; API недоступен — HTML со
   скелетоном, без `robots`, не `500`; гидрация без ошибок; «Старт прошёл» одинаков в HTML и после гидрации.
6. **Состояния §4.12** на вкладке и карточке: офлайн-старт native — «Нет соединения», возврат сети — данные; ошибка
   фонового обновления при данных — данные + баннер; pull-to-refresh — индикатор только на время жеста.
7. **Скрыто (§4):** медиа, обложки, комментарии, «Войти» гостя, кросс-ссылки, «Регистрация открыта», «Найдено N»,
   «Циклокросс», «рядом».
8. **Главная:** герой старта нажимается → карточка; остальные тесты Главной — без правок ожиданий.
9. **Архитектура:** DTO — только contracts; проверка ссылки — `RegistrationUrl`; фаза — сервер; коллекция — только
   `CalendarRepository`; `Linking`/`window.open` — только `open-external-url(.web).ts`; без `Platform.OS` в экранах;
   без hex/px; строки — `@pokatim/i18n`; `pnpm check` зелёный; int — реальный MongoDB RS.

## Приложение A. Карта прототипа «Календарь» (кратко, без данных прототипа)

- **Корень вкладки:** верхняя панель → кикер раздела «Календарь» → заголовок «Календарь стартов» → одна строка о
  регистрации у организаторов → три группы чипов («Дата» — месяцы, «Дисциплина», «Город»; подпись группы колонкой,
  ряд уходит за правый край) → один герой → «Все старты».
- **Герой:** у старта нет геометрии; без обложки — типографский (кикер «Ближайший старт» / «Ближайший по фильтрам» →
  дата крупно с годом → название → ink-линия), с обложкой — фото со скримом (не в этом блоке). Мета: дистанция ·
  дисциплина, строка «До старта N дней.».
- **«Все старты»:** подписи групп по месяцам («{Месяц} {год}»); строка — квадратная рамка даты (день или «26–27» +
  месяц), название, «дистанции · дисциплина · город», шеврон; строки разделены hairline, без коробок.
- **Фильтры применены:** выбранный чип — заливка с галочкой; «Найдено N стартов» + «Сбросить фильтры»; герой — первый
  подходящий.
- **Карточка старта:** простая шапка без медиа («назад» к календарю), кикер раздела, строка «{Дисциплина} · массовый
  старт · вне приложения», название, дата крупно, «Старт в {время} · {место}», стат-блок дистанций под ink-линией,
  единственная primary «Регистрация у организатора» со значком внешней ссылки и пояснением «Откроется сайт
  организатора. Регистрация и оплата — там.»; нет ссылки — кнопки нет; после даты — «Старт прошёл». Ниже — галерея
  «Фото и видео», «О старте», «Этот старт в других разделах» (маршруты похожей дистанции), комментарии с правкой
  своего; при прокрутке шапка сворачивается в title bar с названием.
- **Гость:** карточка только для чтения, без таб-бара, «Войти» в навигации, вместо поля комментария — приглашение
  войти; после входа — возврат к старту.
- **Не показано в прототипе:** «Сообщить о нарушении», «Комментариев пока нет», подтверждение удаления комментария.
