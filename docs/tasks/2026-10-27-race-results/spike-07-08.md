## 1. Чем «Покатим» отличается от виртуальных гонок

Почти все системы ниже (Zwift, ZwiftPower, MyWhoosh, Rouvy) работают в помещении: мощность меряет станок, вес
задаёт скорость в игре, все едут одновременно. У «Покатим» гонка — индивидуальная разделка на улице в окне дат:

- **Мощность есть не у всех.** У любителя обычно есть GPS и пульс (часы или ремень), измеритель мощности — у
  меньшинства. Кластеры по Вт/кг отсекли бы большинство.
- **Вес не влияет на результат напрямую.** Время показывает сама дорога, вес в формуле не участвует. Стимула
  занижать вес почти нет, в отличие от Zwift («weight doping»).
- **Каждый едет в свой день.** Ветер и погода разные, поэтому время шумит сильнее, чем в масс-старте. Места
  устойчивее к шуму, чем разрывы по времени.
- **Сообщество небольшое** (сотни райдеров). Групп должно быть мало, иначе в группе по 2–3 человека.
- **Биометрию не храним** (ADR-0011 R9). Флаги по пульсу и мощности считает worker из исходника. В БД — только
  код флага и безразмерная метрика (доля, отношение), без значений пульса и мощности.

Выводы для «Покатим»:

1. Категории по Вт/кг работают, когда мощность меряют у всех. У нас её меряют не у всех, поэтому кластеры лучше
   строить по **собственным результатам райдера** (как Racing Score и ZwiftPower ranking), а не по
   физиологии.
2. Общая схема переходов: вверх сразу по факту, вниз медленно. Ехать выше своей группы можно, ниже нельзя.
3. Новичок без истории — отдельный случай. В Zwift его ставят в E, в Racing Score считают стартовый балл.
4. Подтверждение веса видео (MyWhoosh, ZwiftPower) нужно, когда вес влияет на результат. У нас не влияет, так что
   хватит самодекларации и проверки при споре.
5. Обязательный пульс — частая норма (Rouvy, часть гонок Zwift). Пропуски пульса — сигнал для разбора, но не
   автоматический DQ.
6. Сезонные зачёты почти всегда устроены так: таблица очков за место плюс «лучшие N из M». Дисквалификацию за
   нарушение выбросить нельзя (DNE в парусе).

## 3. Слайс 07

### 3.1 Verified и START: что дают и как подтверждаются

**Что даёт уровень** (решение, общее для вариантов ниже):

| | Verified | START |
|---|---|---|
| Проезд, время, статус попытки | да | да |
| Место в таблице гонки | да, в своей группе (пол × возраст, §3.2) | нет: «Финишёр», время, без места |
| Очки сезона (08) | да | нет |
| Подать спор / быть оспоренным | да, внутри своей группы | нет |
| Флаги «Требует внимания» | да | считаются, но не мешают |
| Данные | пол, год рождения, вес, рост, (FTP) — `rider_verified_profiles` | ничего |

START — участие без зачёта: проехать коридор и получить своё время, без анкеты и без мест. Похоже на «финишёра»
гран-фондо и бревета или «без категории» в Zwift.

**Варианты подтверждения Verified:**

| | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **V1** (решение) | **Самодекларация + пульс в треке.** Райдер заполняет пол, год рождения, вес, рост (FTP — по желанию) и согласие; попытка Verified засчитывается в места, если в исходнике есть пульс; без пульса — засчитана как START-строка («Без пульса — вне зачёта»). Команда может запросить подтверждение на разборе спора | без трения; пульс есть почти у всех (часы); вес не влияет на время, стимула врать почти нет; соответствует Rouvy | самодекларацию можно подделать (но она ни на что, кроме разбора спора, не влияет) |
| V2 | **Самодекларация без требования пульса** | ещё проще | флаги пульса не работают для половины зачёта; антифрод только по скорости |
| V3 | **Проверка командой** (фото/видео взвешивания по запросу при первом Verified, как MyWhoosh/ZwiftPower) | надёжно | ручная работа команды, хранение медиа ПДн (модуля `media` нет, A10), трение на входе |
| V4 | **Verified по истории:** после 2 засчитанных START-заездов с пульсом | автоматически, без анкеты | новичок первые гонки без мест; анкета всё равно нужна для D-06 |

**Переход между уровнями:** уровень выбирается в заявке. START → Verified — пока окно открыто (заполнил данные —
заявка стала Verified, места пересчитываются при чтении). Verified → START — нельзя: защита от «ухода из зачёта»
перед спором. После закрытия окна уровень не меняется.

**Влияние на модель (V1):**

- `packages/contracts`: `ENTRY_TIERS = ['verified', 'start']` (tolerant enum), `tier` в ответах заявки и строки
  таблицы; новые причины попытки «без пульса — вне зачёта» — в конец перечисления.
- `race_entries.tier: 'verified' | 'start'` (был `null`). Миграция `00NN_entry_tier`: существующие заявки →
  `'verified'`, потому что в v1 у всех были места; опубликованные протоколы не меняются. Индекс мест
  `race_entries_ranking_idx` — новый частичный с `tier: 'verified'` (создать новый, затем удалить старый, обе
  операции идемпотентны).
- Попытка: `sensors: { hr: boolean, power: boolean }` — признак наличия канала (не значения). Пишет worker в
  `analyzeAttempt`; `engineVersion` не меняется, флаги версионируются отдельно (`flagsVersion`).
- Новая коллекция `rider_verified_profiles` (модуль `profile` или `results` → рекомендация: `profile`, порт
  `VerifiedProfileReader` для `results` и `disputes`): `{ _id: userId, weightKg, heightCm, ftpW | null, gender,
  birthYear, consentAt, updatedAt, version }`. Без истории значений; журнал — «изменено» без цифр. Удаляется вместе с аккаунтом
  (хук account-deletion, ADR-0015). В логи и outbox не попадает (`pokatim-security`).
- `race_protocol_rows`: START-строки в снимок не входят (мест нет); таблица START — при чтении из заявок.

### 3.2 Кластеры (группы зачёта)

**Признак — варианты:**

| | Признак | Плюсы | Минусы |
|---|---|---|---|
| K1 | **Индекс результата райдера:** медиана отношений `время / медиана Verified-финишёров гонки` по последним ≤ 5 опубликованным результатам за 12 месяцев (как «лучшие 5» в ZwiftPower, но медиана меньше страдает от одной неудачи); три группы A < 0,92, B 0,92–1,04, C ≥ 1,04 | не нужен измеритель мощности; нормирует трассу; группы по силе | холодный старт; зависит от состава поля; шум погоды; нужна коллекция индексов и пересчёт после каждого протокола |
| K2 | **Вт/кг по FTP из Verified** (пороги Zwift) | понятно велосипедистам | FTP — самодекларация; измерителя у большинства нет; на улице Вт/кг ≠ скорость |
| **K3** (решение) | **Пол и возраст** (как UCI Gran Fondo, Strava) | просто и прозрачно; нет холодного старта; данные — из анкеты V1; не нужен пересчёт индексов | не уравнивает силу внутри группы; группы меньше |
| K4 | **Кластеры по времени внутри гонки** (k-means после закрытия окна) | без истории | группы меняются с каждой загрузкой; неизвестны в заявке; поощряет «придержать» темп |

Рекомендация спайка была K1. Автор выбрал **K3**: понятность и отсутствие холодного старта для сообщества важнее
выравнивания по силе.

**Группы (решение):** пол × возраст, **6 групп**: М до 39, М 40–49, М 50+, Ж до 39, Ж 40–49, Ж 50+. Возраст
считается на 31 декабря года гонки (как UCI Gran Fondo [13]). Год берётся по концу окна (`windowEndsAt`) по Минску.
Отклонённые варианты: только М/Ж (2 группы); шаг 10 лет как в Gran Fondo (до 10 групп по 2–3 человека); абсолют +
возраст (два места и два зачёта на райдера).

**Переходы и выбор группы (решение):**

- Группу по анкете считает сервер при заявке и **фиксирует в заявке** (`groupKey`, как поля гонки по V-12). Место,
  спор и очки сезона считаются по этой группе.
- Райдер может заявиться в **более молодую группу своего пола** (она сильнее), в старшую — нельзя. Так в K3
  остаётся ответ «выбирает сам» (N1).
- Переход в следующую возрастную группу — автоматически с новым календарным годом. Старые заявки не меняются.
- Пол и год рождения райдер заполняет сам до первой Verified-заявки. Потом их меняет только команда платформы в
  панели, с причиной и записью в журнал без значений. Вес, рост и FTP райдер правит сам.
- Новичок сразу попадает в свою группу: холодного старта нет, вопрос N1–N3 для K3 снят.

**Влияние на модель (K3):**

- `packages/contracts`: `RESULT_GROUP_KEYS = ['overall', 'm_u40', 'm_40_49', 'm_50p', 'w_u40', 'w_40_49',
  'w_50p']`, новые значения — в конец (tolerant enum: старые сборки видят `unknown`). Подписи групп — i18n.
  Заявка принимает необязательный `groupKey`, сервер проверяет «свой пол, не старше своей группы».
- Гонки до 07 остаются одной группой: у гонки поле `races.groupScheme: 'overall' | 'gender_age'`, выставляется при
  первой заявке вместе с `lockedAt` (V-12). Миграция: гонки с `lockedAt` → `'overall'`, остальные получают схему при
  первой заявке. START-заявки — `groupKey: 'overall'`, `tier: 'start'`, в места не входят.
- `rider_verified_profiles` (§3.1) дополняется полями `gender: 'm' | 'w'` и `birthYear`. После первой
  Verified-заявки они только для чтения райдера, правка — порт панели `profile`.
- Индекс мест `race_entries_ranking_idx (raceId, groupKey, …)` уже содержит группу; меняется только частичный
  фильтр (`tier: 'verified'`, §3.1).
- Споры: «участник той же группы зачёта» — тот же `groupKey` и `tier: 'verified'`. Порт `ResultsForDisputes` уже
  отдаёт `groupKey`.
- Коллекция индексов `rider_ratings` (K1) не нужна.

### 3.3 Флаги «Требует внимания» (FR-11)

Флаг не блокирует публикацию (D-22) и не даёт DQ. Его видит только команда в панели, решение принимает человек.
Флаги по датчикам считает worker из исходника вместе со сверкой. `SPEED_CLUSTER_HIGH` зависит от других
результатов, поэтому считается при чтении (как места) и фиксируется снимком при публикации.

Решение — **умеренные пороги**. Строгие и мягкие варианты для сравнения:

| Код | Когда | Умеренные (решение) | Строгие | Мягкие | Что хранится |
|---|---|---|---|---|---|
| `SPEED_CLUSTER_HIGH` | **выброс в своей группе** (решение автора для K3): е-байк, езда за машиной, неверный пол или возраст | (а) в группе ≥ 5 Verified-финишёров и время < **0,80** × медианы группы в этой гонке; или (б) в гонке ≥ 5 Verified-финишёров и абсолютно лучшее время у райдера не из группы «до 39» своего пола или у женщины | 0,85 | 0,75 | код, отношение к медиане группы (до 0,001) |
| `HR_POWER_DECOUPLED` | есть оба канала, сегмент ≥ 20 мин, ≥ 80 % отсчётов | (а) Pw:HR первой и второй половины сегмента расходятся больше чем на **15 %** (у TrainingPeaks [19] > 10 % — уже выше порога, у гонки интенсивность выше); или (б) пульс «не отвечает»: из ≥ 5 рывков мощности > 150 % средней за 60 с в > 70 % нет роста пульса ≥ 5 уд/мин за следующие 90 с | 10 % | 25 % | код, расхождение в целых % |
| `HR_GAPS` («Пропуски пульса») | канал пульса есть | без пульса > **10 %** времени сегмента или один пропуск > **120 с** | 5 % / 60 с | 20 % / 300 с | код, доля пропусков в % |

Отклонённые варианты для `SPEED_CLUSTER_HIGH`: «резкий рост против своей истории» — новичков не ловит и требует
хранить историю отношений; «оба правила» — то же хранение.

Отсутствие пульса — не флаг, а правило уровня: без пульса попытка вне зачёта (V1). Пороги — политика сервера, их
смена повышает `flagsVersion`. Перед слайсом 07 их калибруют на фикстурах реальных заездов (по образцу
`corridor-golden.json`).

**Влияние на модель:**

- `race_attempts.flags: { code, metric }[]` и `flagsVersion` пишет worker. `race_protocol_rows.flags` — снимок при
  публикации, включая `SPEED_CLUSTER_HIGH`.
- Панель: колонка и фильтр «Требует внимания» в «Результатах» (KPI уже есть), на разборе спора — флаги цели.
- Ряды пульса и мощности не сохраняются (R9). Метрики флагов — проценты и отношения, без уд/мин и ватт.

## 4. Слайс 08 — рейтинг сезона

### 4.1 Пример (класс «Шоссе», группа «М до 39», сезон из 4 гонок)

Г3 отменена. Ничья «1, =2, =2, 4». Д дисквалифицирован в Г2 по спору.

| Боря | 1:02:00 — =2 | 0:58:00 — 1 | — | — |
| Вера | 1:02:00 — =2 | 1:04:00 — 4 | — | 1:20:00 — 1 |
| Гена | 1:05:00 — 4 | 1:01:00 — 3 | — | 1:21:00 — 2 |
| Дима | 1:10:00 — 5 | DQ | — | 1:25:00 — 3 |

M = 3 (отменённая не считается), в зачёт — **2 лучших** (выброс одного худшего).

### 4.2 Формулы

**Ф1 — таблица очков за место** (решение). 1 → 100, 2 → 85, 3 → 75, 4 → 67, 5 → 60, 6 → 54, 7 → 49, 8 → 45, 9 → 41,
10 → 38, дальше −2 за место до 2 (28-е), 29-е и ниже → 1. Ничья «=N» — каждый получает очки места N.

| | Г1 | Г2 | Г4 | Лучшие 2 | Место |
|---|---|---|---|---|---|
| Аня | 100 | 85 | 0 | 185 | =1 ¹ |
| Боря | 85 | 100 | 0 | 185 | =1 ¹ |
| Вера | 85 | 67 | 100 | 185 | =1 ¹ |
| Гена | 67 | 75 | 85 | 160 | 4 |
| Дима | 60 | **DQ 0** | 75 | 135 (DQ выброшен) / **75** (DQ не выбрасывается — решение) | 5 |

¹ Разбивка по лучшим местам среди засчитанных (решение): у каждого из троих одно 1-е и одно 2-е место («=2»
считается 2-м) — ничья не разбилась, общее «=1».

Плюсы: стандарт кубков, легко объяснить в приложении («за 1-е место — 100»), устойчиво к погоде и шуму времени,
очко за любой финиш поощряет участие. Минусы: тройная ничья в примере — без правила разбивки ничьих она реальна;
место в гонке из 3 человек весит как в гонке из 50.

**Ф2 — доля поля:** `100 × (N − место + 1) / N`, где N — классифицированные в группе.

| | Г1 (N=5) | Г2 (N=4) | Г4 (N=3) | Лучшие 2 |
|---|---|---|---|---|
| Аня | 100 | 75 | 0 | 175 |
| Боря | 80 | 100 | 0 | 180 |
| Вера | 80 | 25 | 100 | 180 |
| Гена | 40 | 50 | 66,7 | 116,7 |
| Дима | 20 | 0 | 33,3 | 53,3 |

Плюсы: учитывает размер поля, последний всегда получает больше 0. Минусы: победа в гонке из трёх стоит столько же,
сколько в гонке из пятидесяти (100); дробные очки; при ничьих появляются странные доли.

**Ф3 — время относительно победителя:** `round(1000 × T_победителя / T_райдера)` (как процент от победителя в
ориентировании).

| | Г1 | Г2 | Г4 | Лучшие 2 |
|---|---|---|---|---|
| Аня | 1000 | 983 | 0 | **1983** |
| Боря | 968 | 1000 | 0 | 1968 |
| Вера | 968 | 906 | 1000 | 1968 |
| Гена | 923 | 951 | 988 | 1939 |
| Дима | 857 | 0 | 941 | 1798 |

Плюсы: учитывает разрыв, точных ничьих почти нет, естественен для разделки. Минусы: разрыв сжат (последний
получает ≈ 850), участие весит больше скорости; шум погоды в разные дни окна прямо попадает в очки; один
«попутный» победитель снижает очки всем.

**Ф4 — рейтинг силы поля** (Elo, Racing Score, IOF WRE): очки зависят от рейтингов соперников. Плюсы: учитывает силу
поля. Минусы: непрозрачно для райдера («почему у меня 412?»), нужна история, на сотне райдеров нестабильно. Для
сезонного зачёта не рекомендуется. Похожая идея — индекс K1 (§3.2), его отклонили.

### 4.3 Правила зачёта

| Вопрос | Варианты | Решение автора |
|---|---|---|
| **N из M** | (а) все гонки; (б) фиксированные лучшие N (как ZwiftPower — 5); (в) выброс худшей трети: `N = M − ⌊M/3⌋` | **(в)** (рек. = решение): работает при любом числе гонок сезона (1–2 → все, 3–5 → минус 1, 6–8 → минус 2), прощает пропуск; без настройки в панели |
| **Ничья в гонке** «1, =2, =2, 4» | (а) каждому очки места N; (б) среднее очков занятых мест (85 + 75) / 2 = 80 | **(а)** (рек. = решение): совпадает с показанным «=2», без дробей |
| **Ничья в сезоне** | (а) общее место «=N» (как A7); (б) разбивка: больше лучших мест среди засчитанных, затем «=N»; (в) по последней гонке (BC Cup) | **(б)** (рек. = решение), если и это не разбило — «=N» |
| **DQ** | (а) 0, выбрасывается как пропуск; (б) **0 и не выбрасывается** (DNE в парусе) | **(б)** (рек. = решение): DQ занимает один из N слотов с нулём, нарушение не «лечится» выбросом |
| **Отменённая гонка** | не входит в M, очков нет ни у кого | единственный разумный |
| **dns, отмена участия, не засчитано, START** | 0, выбрасывается | — |
| **Разделение таблиц** | (а) класс × группа; (б) только группа, классы вместе; (в) только класс, группа — фильтр | **(а)** (рек. = решение): очки за место в группе имеют смысл только внутри группы; заявка в младшую группу или переход по возрасту — очки остаются там, где заработаны, райдер виден в обеих таблицах |
| **Минимум участия** | (а) нет; (б) ≥ 2 гонок для места в итоговой таблице | **(а)** — по рекомендации (автору не задавался): сообщество маленькое |

**Влияние на модель (08):**

- Модуль `standings`, коллекция `season_standings` (снимок пересчёта): `{ seasonId, bikeClass, groupKey, rows: […],
  computedAt, sourceEventId, version }`, полный пересчёт сезона на `results.protocol-published` и
  `results.result-revised` (маршрут outbox — в `standings`; накопленные события заберутся, RC-4), `jobId =
  standings:<seasonId>:<eventId>`. Строки: `userId`, очки, места по гонкам, засчитано, выброшено, место, ничья.
- Ключ таблицы — `(seasonId, bikeClass гонки, groupKey заявки)`.
- Источник — только `race_protocol_rows` текущей ревизии (через порт `results`), `tier: 'verified'`. Таблица очков —
  константа сервера с версией (`formulaVersion` в снимке).
- Миграций старых данных нет: гонки до 07 (`groupKey: 'overall'`) идут в таблицу «класс × общая» (`overall`). Если в сезоне
  есть обе схемы — `overall` отдельной таблицей (до 07 на dev гонок с публикацией немного).

**Что меняется по сравнению с рекомендацией:** кластеры строятся по полу и возрасту, а не по силе. Поэтому:

- Коллекции индексов `rider_ratings` и пересчёта индексов после протоколов нет.
- Флаг `SPEED_CLUSTER_HIGH` ловит выброс внутри группы, а не «слишком сильного для кластера».
- В анкету Verified добавлены пол и год рождения.
- Внутри группы сила по-прежнему разная. Если сообщество вырастет, K1 можно добавить позже как деление групп по
  силе: в модели это просто новые значения `groupKey`.

и `tier` из 07).
