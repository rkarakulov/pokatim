## Результаты гонки, слайс 05: протокол в панели

Эпик `docs/tasks/2026-10-27-race-results/epic.md` (§3.4, §4, §7), spec и план — `task.md`, ревью — `findings.md`.

### Что сделано
- **Панель → гонка → «Результаты»** (`apps/admin`). Экран показывает:
  - KPI;
  - чек-лист публикации из 5 строк (D-23). Пока он не пуст, кнопка неактивна, рядом — причина и количество; «Требует внимания» публикацию не блокирует (D-22);
  - участников с местами «1, =2, =2, 4»;
  - попытки с фильтром по статусу.

  Все действия требуют причину (`ReasonDialog`).
- **До публикации:**
  - «Исключить трек», в том числе для dead-letter `failed`;
  - «Вернуть в обработку» — новая `checkRevision`; запись `race_attempt_reviews` только добавлением (D-24);
  - исключение действует на всю группу дублей;
  - «Перепроверить треки».
- **Публикация:**
  - `races.protocolPublishedAt`, фаза `final` добавлена в конец `RACE_PHASES`;
  - снимок `race_protocol_rows` по ревизиям, результаты `final`;
  - outbox `results.protocol-published`;
  - отмена гонки после публикации недоступна — новая причина `results_final` (D-19).
- **Экстренный пересчёт** (D-27/D-28):
  - DQ, отмена DQ, перепроверка по сохранённым трекам: worker перепоставляет попытки, затем нужно нажать «Применить пересчёт»;
  - `race_recalculations` пишется только добавлением, плюс событие `results.result-revised`.
- **Сериализация и журнал:** замок результатов `RaceRegistry.lockResults` (запись в документ гонки) — первая операция каждой транзакции панели. `PanelAudit.append` пишется в той же транзакции.
- **Права:** `results.manage` (admin, organizer — только свои гонки), `results.revise` (admin). Миграция `0016_protocol` (expand).
- **Приложение** (совместимость со слайсом 04): статусы `excluded`, `final`, `dq`, `revised`; таблица результатов показывается и в фазе `final`.
