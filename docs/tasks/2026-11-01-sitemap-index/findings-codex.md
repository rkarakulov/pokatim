### [HIGH] Дочерние карты расположены вне области перечисляемых URL
- **file:** apps/app/src/lib/seo.ts
- **location:** 102–105, 140–158
- **problem:** `/sitemap/static.xml` перечисляет `/welcome`, а `/sitemap/race/1.xml` — `/races/<id>`. Эти URL находятся вне родительских каталогов соответствующих карт. Аналогичная проблема есть у остальных видов.
- **why_it_matters:** Заявленное соответствие sitemaps.org нарушено: краулер, соблюдающий ограничение области карты, может отбросить перечисленные URL. Корневой индекс сам по себе не устраняет это ограничение.
- **evidence:** [Sitemaps.org, Sitemap file location](https://www.sitemaps.org/protocol.html#location) ограничивает URL каталогом карты. [Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap#sitemap-best-practices) также указывает это ограничение с исключением для отправки через Search Console. В реализации предусмотрено обнаружение через `robots.txt`, обязательная отправка через Search Console не описана.
- **recommended_fix:** Согласовать исправление формы URL в спецификации: разместить дочерние карты в корне сайта либо внутри соответствующих разделов (`/races/…`, `/routes/…`), статическую — в корне. Обновить маршруты, генератор индекса, тесты и документацию.

### [MEDIUM] Мемо страниц переживает окно индекса при неизменных границах
- **file:** apps/api/src/modules/sharing/sitemap.service.ts
- **location:** 74–82, 147–158
- **problem:** Ключ мемо страницы содержит только границы и признак последней страницы, а срок жизни начинается при чтении страницы. После обновления индекса с прежними границами возвращается содержимое предыдущего окна.
- **why_it_matters:** Новый индекс уже объявляет обновлённый `lastmod`, но дочерняя карта продолжает отдавать старые даты и состав объектов. Объект, опубликованный внутри прежнего диапазона, может отсутствовать почти ещё десять минут после пересборки индекса. Это расходится с требованием общего окна мемо и AC5.
- **evidence:** Воспроизведено на исходном `SitemapService` с подставленными портами и часами: индекс собран в минуту 0, страница прочитана в минуту 9, затем добавлен объект внутри диапазона. В минуту 10 индекс пересобрался с новой датой, но страница вернулась без добавленного объекта. `remember()` назначает странице собственный `now + memoMs`; поколение индекса в ключ не входит.
- **recommended_fix:** Привязать мемо страниц к поколению и сроку действия индекса. Добавить тест с отложенным первым чтением страницы и изменением объекта внутри неизменных границ.
