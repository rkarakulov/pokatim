## Модерация профиля, follow-up: очередь по причине, уведомление о сбросе, запрет загрузки фото

Спецификация — `docs/tasks/2026-10-30-profile-moderation-followups/task.md`. Закрывает follow-up `docs/product/profile.md`:
«Жалобы райдеров на имя и очередь модерации имён», «Уведомление райдеру о сбросе, бан загрузки фото».

### Что сделано
- **Очередь по причине (API):** `GET /v1/admin/rider-profiles?reason=<причина>` — только профили с открытой жалобой
  этой причины (порядок и курсор — как у общей очереди, неверная причина — 400); строка — `openReasons` (порядок
  справочника). Причины денормализованы на профиле (`profiles.openReasons`), индекс
  `profiles_report_reason_queue_idx`.
- **Уведомление о сбросе:** сброс имени, фото или клуба модератором (`reset: true`) пишет в той же транзакции
  outbox-событие `profile.field-reset` (id, поле, время, дата запрета — без причины и значения); `notifications`
  создаёт `profile_name_reset` / `profile_avatar_reset` / `profile_club_reset`, группа «Райды» (`[ASSUMPTION]`), цель
  `profile-edit` → «Редактировать профиль» (приложение и service worker).
- **Запрет загрузки фото:** 3-й сброс фото за 180 дней — запрет на 30 дней от сброса (`PROFILE_POLICY.avatarBan`,
  `[ASSUMPTION]`). `PUT /v1/profile/avatar` — `409 PROFILE_INVALID_STATE { reason: 'avatar_blocked', until }` до слота,
  лимита и тела; транзакция замены проверяет запрет по документу профиля (гонка с третьим сбросом — 409, отрицательное
  доказательство в task.md §12). `avatarUploadBlockedUntil` — во всех ответах профиля.
- **«Снять запрет»:** `POST /v1/admin/rider-profiles/:userId/avatar-unblock` (`profiles.moderate`, причина), журнал
  `profile.avatar_unblocked`; запрета нет — `{ unblocked: false }` без журнала. История сбросов не очищается.
- **Панель «Профили райдеров»:** вкладки «Все / Имя / Фото / Клуб» (`?reason=` в адресе, «Показать ещё» внутри
  вкладки, пустое состояние по вкладке), строка «Причины: …» при нескольких причинах; карточка — «Сбросов фото за 180
  дней», «Загрузка фото запрещена до <дата, время>», «Снять запрет» (`ReasonDialog`).
- **Приложение, «Редактировать профиль»:** при запрете «Выбрать фото» неактивна, под ней — «Загрузка фото недоступна
  до <дата, время> после нарушений правил»; «Удалить фото» доступна; 409 `avatar_blocked` на загрузке — тот же текст
  баннером и перечитывание профиля (native и web).

### Миграция
- `0042_profile_report_reasons` — expand-only: частичный индекс `profiles_report_reason_queue_idx { openReasons: 1,
  lastReportAt: -1, _id: -1 }` (`openReportCount > 0`) и бэкфилл `openReasons` по открытым `profile_reports`.
  Идемпотентна, без транзакции. Полей запрета не трогает (нет поля — нет запрета).

### Риски
- **RC-F11 — окно миграции.** Миграция идёт до переключения API: жалоба, принятая старым API между бэкфиллом и
  переключением, не попадёт в `openReasons` — вкладка причины её не покажет до закрытия жалобы, «Все» покажет.
  Принято (dev, единицы жалоб); при необходимости — ручной повтор функции бэкфилла.
- Правило запрета 3/180/30 и группа уведомления «Райды» — допущения исполнителя (`[ASSUMPTION]`), пересмотр — product.
- «Снять запрет» до приёма события уведомления — текст «недоступна до …» в уведомлении устарел (секунды); экран
  приложения показывает актуальное поле.
- Конфликт с параллельной сессией «билеты-напоминания» в общих списках уведомлений — разрешается добавлением обоих
  наборов в конец.
