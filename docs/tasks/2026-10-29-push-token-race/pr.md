# notifications: поздняя регистрация push-токена и порядок схлопывания

Закрывает два MEDIUM-follow-up `docs/tasks/2026-10-27-notifications/pr.md` (Codex pass 3/4).

## Что изменено

- **Push-токены (Expo и Web Push).** `registerToken` переписывает токен только сессией не старше записанной
  (`sessionId $lte`; без `sessionId` — до привязки). Поздняя регистрация прежней сессии устройства после выхода или
  смены аккаунта токен новой не перехватывает: `204` без записи, лог `notifications.token_stale`.
- **Схлопывание N7.** Порядок — номер события в объекте (`collapseSeq`), не `sourceEventId` (uuidv7 внутри
  миллисекунды не упорядочен): райд — `rides.noticeSeq` (`+1` в `join` и `update`) в payload события (`seq`), маршрут —
  `decidedAt` события. Повтор задачи несёт тот же номер — прочитанное уведомление не открывается и push не повторяется,
  даже если объект изменился. Уведомления и события без номера — прежнее правило `sourceEventId $lt`.
- Без миграций и новых индексов; контракты и ответы API не меняются.
