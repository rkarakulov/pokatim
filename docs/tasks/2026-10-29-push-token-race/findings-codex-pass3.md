### [MEDIUM] Разные события старого формата становятся повторами после первой обработки
- **file:** apps/api/src/modules/notifications/notifications.repository.ts
- **location:** 143–149, `writeNotices`
- **problem:** Все события райда без `seq` получают `collapseSeq: 0`. После первой записи следующему самостоятельному событию старого формата уже не соответствует ни одна ветка фильтра: `0 < 0` ложно, поле существует. Более новый `sourceEventId` не помогает.
- **why_it_matters:** При обработке накопленных событий или обновлении worker раньше API последующие переносы и присоединения старого формата перестают обновлять уведомление и инициировать доставку. Совместимость обеспечена для старых документов уведомлений, но не для старых payload событий.
- **evidence:** `NotificationIntake.ride` использует `event.data.seq ?? 0` для обоих схлопываемых типов. `writeNotices` сохраняет этот ноль в документе; сравнение `sourceEventId` применяется только при отсутствии `collapseSeq`. При следующем событии upsert получает дубль уникального индекса, а повтор без upsert ничего не меняет. Новые тесты совместимости удаляют поле уведомления, но используют события уже с `seq`.
- **recommended_fix:** Сохранить отсутствие номера для legacy-событий и прежнее сравнение `sourceEventId` между ними. После перехода документа на настоящий номер не разрешать legacy-событиям его заменять. Добавить тест с двумя различными событиями без `seq`: второе обновляет уведомление, повтор каждого ничего не меняет.
