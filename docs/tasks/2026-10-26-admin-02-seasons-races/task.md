# 1. Title

Админка «Протокол», слайс 2: сезоны, гонки по коридору (создание, правка, публикация, отмена) и календарь стартов
в панели; read-модель опубликованных сезонов, гонок и стартов для приложения (контракты + API чтения)

# 2. Goal

Первый доменный модуль pokatim. Команда платформы в панели «Протокол»:

- ведёт **сезоны** (название, даты начала и конца по Минску; без пересечений; завершённый — даты только для чтения);
- создаёт и ведёт **гонки по GPS-коридору** (название, класс велосипеда, покрытие, описание, окно дат с явным временем,
  плановая дата протокола ≥ конец окна + 48 ч, сезон вычисляется по концу окна): черновик → опубликована → отменена с
  шаблонной причиной; организатор работает со своими гонками, администратор — со всеми;
- ведёт **календарь стартов** — внешние массовые старты с регистрацией у организатора (отдельная сущность, без окна
  и протокола), публикуются сразу.

Каждое изменение пишет запись в журнал действий панели (`PanelAudit`, admin-01) в транзакции действия. Приложение
райдера получает **read-модель** опубликованного (контракты и публичные `GET`), на которую опирается блок 02
«Главный экран» (§13) и будущие разделы «Гонки» и «Календарь».

Чего в слайсе нет (и почему важно для модели): библиотеки маршрутов (эталонный коридор — опубликованный маршрут,
§8.1 Q4), участия и загрузки треков (фиксация полей с первой записи, V-12), результатов и споров (блокировки отмены,
D-19), медиа (обложки), уведомлений. Модель оставляет им место без полей «на вырост» (`AGENTS.md` §4.9).

Источники: `AGENTS.md` §1, §4; `.claude/rules/{backend,pokatim-backend,db,pokatim-db,contracts,pokatim-contracts,web,
pokatim-web,security,pokatim-security,tests,pokatim-tests}.md`; ADR-0007 (данные, R11 геометрия), ADR-0008, ADR-0009
(панель); `docs/product/admin-panel.md`; task admin-01 (Приложение A «Карта прототипа»); прототипы автора панели
(`key-web-panel-3` — сезоны, форма гонки, отмена; `key-web-panel-2` — создание гонки, календарь; `key-web-panel` —
результаты и спор, для контекста) и приложения (`key-home`, `key-races`, `key-rides`, `key-calendar`) —
**конфиденциальны**, в репозиторий не копируются; здесь только краткие описания и нужные UI-тексты (Приложение A).

# 4. Out of Scope

  до него у гонки нет коридора, дистанция вводится вручную. Загрузка GPX в форме гонки — нет (прототип запрещает).
- Участие («Участвовать»), загрузка треков, фиксация полей с первой записи (V-12), плашки «ждём трек».
- Результаты, протокол, споры, экстренный пересчёт; блокировки отмены «финальный результат» и «открыт спор» (D-19) —
  добавят слайсы admin-04/05.
- Сезонный рейтинг и таблица сезона (FR-4 — открыт, spike), место в сезоне.
- Обложки гонок и медиа записей календаря (нет `media`/S3), комментарии к стартам календаря.
- Уведомления участникам об отмене, баннер «Публикация протокола задерживается».
- Кофе-райды — UGC приложения (модуль `rides`, свой блок), не панель; повторяющиеся райды — нет.
- Экраны приложения «Гонки», «Календарь», «Главная» — блоки приложения (здесь — только контракты и API чтения).
- Удаление сезона (прототип: «сезон с гонками не удаляется»; пустой сезон правится, удаление — по запросу).
- Месячная сетка календаря в панели — только таблица-список (§8.1 Q15).
- Передача гонки другому организатору, отображение организатора в приложении.
- 2FA, CSP web приложения (обязательны до прода, admin-01) — не здесь.

# 5. Architecture Context

- **Три сущности, не один «тип события»** (прототипы): гонка по коридору (окно дат, протокол, сезон — создаёт команда в
  панели), кофе-райд (время и место старта, лимит, «Я иду» — создаёт райдер в приложении, модуль `rides`), старт
  календаря (внешнее событие с регистрацией у организатора — панель, модуль `calendar`). Общего поля `type` нет: у
  сущностей разные жизненные циклы и владельцы.
- **Модуль `races` = сезоны + гонки** (R1): «конец окна гонки попадает ровно в один сезон» и «нельзя сжать сезон,
  выбросив его гонки» — инвариант в обе стороны; отдельные модули `seasons` ↔ `races` дали бы цикл зависимостей.
  Будущий сезонный рейтинг (FR-4) — свой модуль, читает сезоны и результаты через порты.
- **Модуль `calendar`** — отдельный контекст (`pokatim-backend.md`), с гонками не связан.
- **Зависимости:** `races`, `calendar` → `panel` (только `modules/panel/index.ts`: `PanelModule`, `PanelGuard`,
  `RequirePermission`, `CurrentPanelUser`, `PanelAudit`, `PanelDirectory`); `panel` о них не знает (журнал хранит
  снимок `subject.label`, R7). Identity не затрагивается.
- **Время** (R4): в БД и API — UTC; сезоны и старты календаря — календарные даты Минска (`LocalDate`), сервер хранит и
  их, и границы-моменты (`startsAt` = 00:00 Минска дня начала, `endsBefore` = 00:00 Минска дня после конца) для
  запросов. Окно и протокол гонки — моменты с точностью до минуты; панель вводит «настенное» время Минска и переводит
  в UTC функцией контрактов независимо от пояса браузера.
- **Фаза гонки — вычисляет сервер** по `CLOCK` (R5): `draft`, `upcoming` (до начала окна), `open` (окно идёт),
  `closed` (окно закрылось), `cancelled`. Хранится только `status`; фазы результатов (`provisional`, `final`) добавит
  admin-04 в конец enum.
- **Сериализация расписания** (R2): «сезоны не пересекаются» и «опубликованная гонка — внутри своего сезона» —
  условия по другим документам (write skew). Каждая транзакция, создающая/меняющая даты сезона, публикующая гонку или
  меняющая конец окна опубликованной гонки, первой операцией пишет `race_meta.schedule` (`$inc version`,
  `lockSchedule`). Правки панели редки — общий замок не мешает.
- **Конкурентная правка** (R3): у сезона, гонки и записи календаря — `version`; изменяющий запрос несёт ожидаемую
  `version`, обновление — `findOneAndUpdate({ _id, version })` → нет совпадения → `409 CONFLICT` («Запись изменили —
  обновите страницу»).
- **Владение** (R8): `races.ownerUserId` = создатель. Без `races.manage_any` чужая гонка — `404 NOT_FOUND` (не
  раскрываем существование), список — только свои. Проверка — в сервисе, по `PanelPrincipal` из сессии.
- **Что можно менять** (R10) считает сервер и отдаёт в `PanelRace.editable` (поля, `canPublish`, `canCancel`,
  `canDiscard`, причины недоступности); UI только отображает.
- **Журнал**: каждое изменение — `PanelAudit.append(tx, { action, subject, details })` в транзакции действия; без
  значений полей (только имена изменённых), без e-mail.
- **Публичное чтение** — те же модули, отдельные контроллеры без гарда (`/v1/races`, `/v1/seasons`, `/v1/calendar`);
  отдают только `published`/`cancelled` гонки и `published` старты; `Cache-Control: public, max-age=60`.
- **Геометрия:** в слайсе нет (нет коридора; у старта календаря — город текстом). GeoJSON + `2dsphere` (ADR-0007, R11)
  придут с маршрутами.
- **Очереди/outbox:** не нужны (нет писем, уведомлений и подписчиков событий). Событие `race.cancelled` для
  уведомлений — в слайсе уведомлений (outbox).
- **Контракты:** только добавления; приложение получает новые эндпоинты, старые не меняются.

# 7. Implementation Notes

**Права (`ROLE_PERMISSIONS`)** — §8.1 Q2, Q3, Q13:

| Право | admin | moderator | organizer |
|---|---|---|---|
| `races.read` — «Гонки», «Сезоны» (чтение) | ✓ | ✓ | ✓ (только свои гонки) |
| `races.manage` — создать, править, опубликовать, отменить, удалить черновик | ✓ | | ✓ (свои) |
| `races.manage_any` — то же для чужих гонок | ✓ | | |

**Сезоны**
- Документ: `{ _id, name, startsOn, endsOn (LocalDate, включительно), startsAt, endsBefore (Date), createdAt,
  updatedAt, version }`. Статуса нет: фаза по `CLOCK` — `upcoming` (`now < startsAt`), `current`, `finished`
  (`now ≥ endsBefore`). Название обязательно (Q16), 2–60 символов, без управляющих.
- Создание (транзакция): `lockSchedule` → `endsOn < startsOn` → `DATE_ORDER` (поле `endsOn`); `endsBefore ≤ now` →
  `SEASON_IN_PAST` → пересечение с любым сезоном (`startsAt < other.endsBefore && other.startsAt < endsBefore`) →
  `SEASON_OVERLAP` на поле, которое попало внутрь (оба — на `startsOn`) → вставка → аудит `season.created`.
- Изменение: `lockSchedule` → `findOne` + сверка `version` → завершённый: даты не меняются (`SEASON_FINISHED`), имя —
  можно → пересечение (кроме себя) → **гонки сезона остаются внутри** (`races.countDocuments({ seasonId, windowEndsAt
  вне новых границ })` > 0 → `SEASON_EXCLUDES_RACES`) → `updateOne({ _id, version }, { $set, $inc: { version: 1 } })`
  → аудит `season.updated { changedFields }`.
- Список панели — все сезоны (их десятки) + `raceCount` (опубликованные и отменённые) одной агрегацией по `seasonId`.
- Ошибки правил — `400 VALIDATION_FAILED` с `details.fields` (путь поля + код): форма показывает под полем. Имя и
  диапазон пересёкшегося сезона UI берёт из уже загруженного списка.

**Гонки**
- Документ (`races`): `{ _id, ownerUserId, status, title, bikeClass, surfaces[], distanceKm, description | null,
  windowStartsAt, windowEndsAt, protocolPlannedAt, seasonId | null, cancelReason | null, createdAt, updatedAt,
  publishedAt | null, cancelledAt | null, version }`.
- Моменты — с точностью до минуты (секунды и мс = 0; иначе `400 INVALID`). Окно — `[windowStartsAt, windowEndsAt]`
  включительно до конца минуты: `open`, пока `now < windowEndsAt + 1 мин` (R12; «до 23:59» прототипа).
- Правила формы (сервер, на создании и каждом изменении): `windowEndsAt > windowStartsAt` (`DATE_ORDER`),
  `protocolPlannedAt ≥ windowEndsAt + 48 ч` (`PROTOCOL_TOO_EARLY`), длина окна ≤ 60 суток (`INVALID`,
  `[ASSUMPTION]`), `distanceKm` 1–1000 шаг 0,1, `surfaces` — 1…N разных, `title` 3–120, `description` ≤ 2000.
- **Сезон черновика не хранится** (R9): `PanelRace.season` черновика — предпросмотр по текущим сезонам. Публикация и
  изменение конца окна опубликованной гонки (под `lockSchedule`) находят сезон, где `startsAt ≤ windowEndsAt <
  endsBefore`; нет — `OUTSIDE_SEASON` (поле `windowEndsAt`); найден — `seasonId` записывается.
- **Публикация** (`draft → published`, `races.manage` + владение): `lockSchedule` → сверка `version` и `status =
  'draft'` (иначе `409 RACE_INVALID_STATE`) → `windowEndsAt + 1 мин ≤ now` → `WINDOW_IN_PAST` → правила формы →
  сезон → `findOneAndUpdate({ _id, version, status: 'draft' }, …)` → аудит `race.published`. Организатор публикует
  сам, без согласования (Q6).
- **Правка опубликованной** (V-11, прототип 3d): пока окно не началось — все поля; окно открыто — `windowStartsAt`
  зафиксировано (`FIELD_LOCKED`); окно закрыто — только `description` и `protocolPlannedAt`, причём только **позже**
  текущего (`PROTOCOL_ONLY_LATER`), правило 48 ч действует всегда. Фиксация с первой записи участника — слайс участия.
- **Отмена** (`published → cancelled`): причина — только шаблон `RaceCancelReason` (без свободного текста, D-20);
  `findOneAndUpdate({ _id, version, status: 'published' })` → аудит `race.cancelled { cancelReason }`. Черновик не
  отменяется (`RACE_INVALID_STATE`) — он удаляется. Отменённая — только чтение. Блокировки D-19 — слайсы результатов и
  споров добавят в `editable.cancelBlockers`.
- **Удаление черновика** — `deleteOne({ _id, version, status: 'draft' })` + аудит `race.discarded` (с `label` —
  названием). Опубликованная не удаляется.
- **`editable`** (R10) в `PanelRace`: `fields: RaceField[]` (что можно менять сейчас), `canPublish`, `canCancel`,
  `canDiscard`, `reasons` (коды: `window_closed`, `window_open`, `cancelled`, `outside_season`; чужая гонка без права — 404, не причина) — UI
  показывает зафиксированные поля с замком и причину под неактивной кнопкой.
- **Список панели** `GET /admin/races`: `status?`, `seasonId?`, `bikeClass?`, `mine?`, курсор по `(windowStartsAt
  desc, _id desc)`, `limit` ≤ 100; организатор — `ownerUserId = self` всегда; ответ — имя организатора через
  `PanelDirectory` (без e-mail).

**Календарь стартов**
- Документ (`calendar_starts`): `{ _id, status, title, startsOn, endsOn | null, startTime | null, discipline, city,
  cityKey, place | null, distancesKm[], registrationUrl | null, description | null, createdByUserId, createdAt,
  updatedAt, unpublishedAt | null, version }`. `cityKey` — `city` в нижнем регистре со схлопнутыми пробелами
  (фильтр и уникальный список городов).
- Правила: `endsOn ≥ startsOn` и ≤ 14 дней (`DATE_ORDER`, `[ASSUMPTION]`); `distancesKm` 1–5 значений 1–1000;
  `registrationUrl` — только `https:`, ≤ 500, без учётных данных в URL (Q12 — необязательна); `city` 2–60;
  `place` ≤ 200; `description` ≤ 4000.
- Создание — сразу `published` (прототип 2b) + аудит; «Снять с публикации» — причина (`ActionReason`) в журнал,
  `status: 'unpublished'`; «Вернуть в календарь» — обратно. Прошедшие старты не скрываются в панели; приложение по
  умолчанию запрашивает `from = сегодня (Минск)`.

**Публичное чтение (приложение)** — §13
- `GET /v1/races?scope=current|past&bikeClass=…&month=YYYY-MM&cursor&limit`: `current` — `published` и окно не
  закрылось, по `windowStartsAt` возр.; `past` — закрытые и отменённые, по `windowEndsAt` убыв. Внутри группы фильтра
  — ИЛИ, между группами — И (прототип «Гонки»). Месяц — окно пересекает месяц по Минску. `bikeClass` ≤ 4,
  `month` ≤ 12, `limit` ≤ 50 (по умолчанию 20). Курсор — непрозрачная base64url-строка `{ k, id }`, после декодирования
  — zod (`UtcMinute`, `Uuid`); мусор — `400`.
- `GET /v1/races/:id` — опубликованная или отменённая; черновик и неизвестная — `404`.
- `GET /v1/seasons/current` — `{ season: SeasonCard | null }` (сезон, в который попадает `now`).
- `GET /v1/calendar?from&discipline&city&month&cursor&limit` — `published`, `endsOn ?? startsOn ≥ from`, по
  `(startsOn, _id)`; `city` — по `cityKey`; `GET /v1/calendar/:id`; `GET /v1/calendar/cities` — `{ cities: string[] }`
  (отличающиеся по `cityKey` города будущих опубликованных стартов, по алфавиту ru, ≤ 200).
- Без `AuthGuard` (Q14), `Cache-Control: public, max-age=60`, IP-лимит `public-read` (`RateLimiter`, 300/мин,
  `[ASSUMPTION]`), владелец и служебные поля (`version`, `ownerUserId`, `createdByUserId`) наружу не выходят.

**Журнал**
- `PanelAuditDoc` + `subject: { kind: 'season' | 'race' | 'calendar_start'; id; label } | null` (`label` — название
  на момент действия, R7), `details` + `changedFields?: string[]`, `cancelReason?`. Старые записи без `subject` —
  `null` при чтении. Индекс `panel_audit_subject_idx` (`{ 'subject.id': 1, _id: -1 }`). «Журнал действий» показывает
  объект и фильтр по действиям новых видов; ссылка из строки на гонку/сезон — `[ASSUMPTION]`.

**Admin — ввод времени.** `DateTimeField` — нативный `<input type="datetime-local">` + метка «Europe/Minsk» у подписи;
значение формы — строка настенного времени, в запрос — `minskWallTimeToUtc` (не `new Date(value)` — это пояс
браузера). Отображение — `src/format.ts` (`Intl`, Europe/Minsk). Тесты admin — `TZ=Europe/Minsk` **и** прогон функций
времени при `TZ=America/New_York` (unit contracts).

**Admin — формы.** RHF + zod-схема контракта (`RaceInput` и т. п.) для формы; ошибки сервера `details.fields` →
`setError` по пути поля; `409 CONFLICT` — баннер «Запись изменили — обновите страницу» с действием «Обновить».
Подсказки правил (ближайшая допустимая дата протокола, вычисляемый сезон) — из `RACE_PROTOCOL_MIN_DELAY_HOURS` и
загруженного списка сезонов, только для отображения.

**Тексты** — из прототипа (кратко, Приложение A); `[ASSUMPTION]` — экраны вне макетов: таблица «Гонки» и её
фильтры, «Удалить черновик», «Опубликовать» и её последствия («Гонка появится в приложении»), календарь — таблица,
«Снять с публикации» / «Вернуть в календарь», статус сезона «Предстоящий», строка последствий отмены без участников
(«Гонка будет отменена для всех, причина появится в карточке гонки. Отменить это действие нельзя.»), «Дистанция, км»
гонки, «Запись изменили — обновите страницу».

# 8. Risks / Assumptions / Open Questions

- **Гонка без коридора** (Q4). Пока нет библиотеки маршрутов, опубликованная гонка — анонс без коридора, дистанция
  введена руками; участвовать ещё нельзя (нет загрузки треков). Риск — опубликовать в проде гонку без коридора.
  Компенсация: слайс маршрутов делает коридор обязательным для публикации (expand: поле `corridorRouteId`, правило
  публикации, миграция данных — без коридора гонки остаются анонсами до выбора маршрута) и **до участия**.
- **Организатор с правом публикации** (Q2): видимый пользователям контент без согласования. До 2FA (admin-01 §8)
  внешних организаторов в панель не пускаем — роль `organizer` выдаётся только команде.
- **Фаза по часам сервера**: кэш публичного списка 60 с — переход `upcoming → open` виден с задержкой до минуты.
- **Минск без перехода на летнее время** (UTC+3 с 2011): функции времени всё равно через `Intl`/tz-базу — смена правил
  не потребует правки кода.
- **Общий замок расписания** сериализует все правки сезонов и публикации гонок — принято (единицы правок в минуту).
- **Enum ответов приложения**: старые сборки увидят `'unknown'` для новых значений — UI приложения обязан иметь
  нейтральный вариант (правило в `pokatim-contracts.md`).
- **Данные публичных эндпоинтов** — без персональных данных (имя организатора не отдаётся).
- `[ASSUMPTION]` Значения справочников (Q10), длина окна ≤ 60 суток, старт календаря ≤ 14 дней, IP-лимит 300/мин,
  тексты вне макетов (§7).

# 8.1 Requirements Consistency

Architecture Review — admin-02-seasons-races. **Status: CONCERNS** — блокеров нет: по каждому вопросу ниже выбран
вариант по умолчанию (рекомендация), coder может стартовать; ответы автора, отличные от рекомендаций, меняют scope
до S3. R — решения архитектора, оркестратор может переиграть.

**Конфликты и недоопределённость**

- **C1. Кто создаёт гонки.** Прототип (EPICS 5.1): «Гонки создаёт только команда платформы — роли участника или
  организатора здесь нет»; постановка слайса: «создание гонок организатором, организатор — свои». Не противоречие, если
  `organizer` — роль команды платформы (admin-01 C2), а не внешний организатор. Решение — Q2.
- **C2. Эталонный коридор обязателен** (прототип 2a, 3d: «только опубликованный маршрут из библиотеки, без него форма
  не сохранится»), а библиотеки маршрутов нет. Решение — Q4.
- **C3. Модель «старт гонки» из постановки** (дата-время старта, место/координаты, лимит, регистрация открыта/закрыта)
  **не совпадает с прототипами**: гонка — окно дат (проехать коридор в любой день окна), место старта — у маршрута,
  лимита и регистрации нет (участие — «Участвовать» в анонсе и окне). Старт, место и лимит — у кофе-райда (приложение)
  и у старта календаря (без лимита). Модель — по прототипам; Q1, Q8.
- **C4. Нумерация слайсов.** `docs/product/admin-panel.md`: сезоны и гонки — admin-03, календарь — admin-06. Этот
  слайс — admin-02 и включает календарь (Q11). Карту в product-документе обновить (§10).
- **C5. Фиксация полей с первой записи (V-12), блокировки отмены (D-19), уведомление участников при отмене** — нечего
  проверять (нет участия, результатов, споров, уведомлений). Модель оставляет точки расширения (`editable.reasons`,
  enum фаз и причин — в конец), без полей «на вырост».
- **C6. Модератор в прототипе** ведёт гонки и сезоны (подпись «Ольга Н. Модератор»), а решение автора Q2 (admin-01):
  у модератора — только журнал. Решение — Q13.
- **C7. Статусы сезона.** Постановка: «черновик / опубликован / завершён»; прототип: «Текущий / Завершён» без
  публикации. Сезон без гонок в приложении не влияет ни на что — отдельная публикация лишняя. Q5.
- **C8. «Пробел между сезонами отклоняется»** (заметка прототипа 3c) читается двояко. Принято: промежутки между
  сезонами допустимы, но конец окна опубликованной гонки обязан попасть в сезон (D-84).
- **C9. Регистрация на старт календаря**: панель (2b) — ссылка обязательна, приложение («Кнопка скрывается, если у
  организатора нет ссылки») — необязательна. Q12.

**Решения архитектора**

- **R1. Сезоны внутри модуля `races`.** (а) **Один модуль: сезоны и гонки** — двусторонний инвариант «гонка в сезоне ↔
  сезон не выбрасывает гонки» в одной транзакции без цикла модулей; (б) модули `seasons` и `races` с портами — цикл
  (сезону нужны гонки, гонке — сезон) или событийная согласованность с окном нарушения; (в) счётчик/диапазон гонок,
  денормализованный в сезон, — хрупко при правках и отменах. **Рекомендую (а)**; рейтинг сезона — отдельный модуль
  позже. `pokatim-backend.md`: «seasons» в списке контекстов — определение сезона живёт в `races`.
- **R2. `lockSchedule`** (`race_meta.schedule`, `$inc version` первой операцией) — образец `lockAdmins` (admin-01 R7).
  Альтернативы: уникальный индекс по дню (не ловит пересечение диапазонов), Redis-лок (вне транзакции БД). Int-тест с
  воротами и **отрицательным доказательством**.
- **R3. Оптимистичная `version`** в запросе изменения → `409 CONFLICT`; без неё две вкладки молча перезаписывают
  друг друга (last write wins). Повторный запрос с той же `version` после успеха — тоже 409 (не идемпотентен; клиент
  перечитывает).
- **R4. Время.** Окно и протокол — моменты UTC (минута); сезоны и старты календаря — `LocalDate` Минска + границы-
  моменты на сервере. Альтернатива «всё моментами» для сезонов — даты «1 апреля — 31 октября» превращаются в
  `23:59:59.999` и ошибки на границе дня. Перевод — одна реализация в `contracts/src/time.ts` (≥ 3 потребителя: api,
  admin, app).
- **R5. Фаза — вычисляемая, не хранимая**: хранимый статус «открыто/закрыто» потребовал бы планировщика переходов и
  расходился бы с часами. Публичный список фильтрует по моментам окна (индекс), а не по фазе.
- **R6. `tolerantEnum` в ответах приложения**: установленные сборки живут долго (`contracts.md`); строгий `z.enum` в
  ответе роняет разбор всего списка на новом значении (новый класс, фазы `provisional`/`final` admin-04).
  Альтернатива — отдавать строки без enum (теряются типы). Панель — строгие enum (SPA деплоится с API).
- **R7. Объект журнала — снимок `label`**: `panel` не зависит от доменных модулей (иначе цикл); название на момент
  действия — честная история. Альтернатива — порт «имя объекта» в каждом модуле, регистрируемый в `panel`, — сложнее.
- **R8. Чужая гонка без `races.manage_any` — 404**, не 403: организатор не узнаёт о чужих черновиках.
- **R9. Черновик без `seasonId`** — сезон фиксируется при публикации под `lockSchedule`; иначе правка сезона ломала бы
  черновики, а организатор (без `seasons.manage`) не мог бы сохранить черновик до появления сезона.
- **R10. `editable` считает сервер** — UI не дублирует правила V-11, фазы и владения (§4.1).
- **R11. Без геометрии в слайсе** — нет коридора и координат старта; «рядом» для календаря в прототипе нет (фильтр —
  город).
- **R12. Конец окна включает последнюю минуту** (`now < windowEndsAt + 1 мин`): «до 23:59» прототипа, правило 48 ч
  сравнивает минуты (конец 25.10 23:59 → протокол ≥ 27.10 23:59, как в макете).
- **R13. Нумерация** — миграции `0006_panel_audit_subject`, `0007_races`, `0008_calendar`; ADR-0010. Параллельный блок
  app-02 миграций не добавляет (UI приложения) — если добавит, согласовать номера до слияния.

**Конфликтов с инвариантами `AGENTS.md` §4 нет**: §4.1 — фазы, сезон, `editable`, права считает сервер; §4.2 —
контракты первыми (S1); §4.3 — `races`/`calendar` → `panel/index.ts`, обратной связи нет; §4.4 — пакетов нет;
§4.5 — асинхронной работы нет; §4.6 — миграции шагом деплоя, expand-only; §4.7 — UTC в БД, Минск на вводе и
отображении; §4.8 — секретов нет; §4.9 — без коридора, обложек, участия «на вырост»; §4.10 — журнал append-only через
`PanelAudit`; §4.11 — компоненты `src/ui` (исключение до F6); §4.12 — скелетоны таблиц и форм; §4.13 — панель desktop,
read-модель — для всех платформ приложения.

**S3–S7 (API):**

- `PanelAuditDoc.subject` — необязательное поле документа (записи admin-01 его не имеют; чтение `?? null`).
- `PanelDirectory.displayNames` возвращает имя для каждого запрошенного id: нет члена команды — «Удалённый участник».
- `raceEditable(race, now, { canManage, seasonFound })` — вместо `canManage: boolean`: причина `outside_season` и
  `canPublish` черновика требуют предпросмотра сезона.

- Видимость по правам (без проверки роли, §5.1): `races.manage` без `races.manage_any` (организатор) — только свои
  (список и карточка, чужая — 404); только `races.read` (модератор) — все на чтение.
- Проверки статуса — до сверки `version`: повтор публикации/отмены — 409 `RACE_INVALID_STATE` при любой версии (AC4).
- Сезон: изменение без фактических изменений — ответ без записи и журнала; `SEASON_IN_PAST`/`DATE_ORDER` — на

- `createApiClient`: публичные методы идут через отдельный HTTP-клиент без `getAccessToken` — токен в них не уходит
  даже у вошедшего пользователя.

# 8.3 Security checklist

Затронуты роли и права (новые права, владение), конфигурация API (`app.module.ts`, `error-messages.ts`), миграции
(`db/**`), новые **публичные** эндпоинты, журнал — `security.md`, `pokatim-security.md` (дополнить `paths:`
`modules/races/**`, `modules/calendar/**`).

1. **AuthN/AuthZ.** Все `/v1/admin/*` новых модулей — `PanelGuard` + `@RequirePermission` (тест уровня приложения
   обходит контроллеры с путём `admin/*` во всех модулях: без гарда — красный). Владение гонкой — в сервисе по
   `@CurrentPanelUser()`: без `races.manage_any` чужая — `404`, список — только свои (фильтр по `ownerUserId` ставит
   сервер, не параметр). `ownerUserId`, `seasonId`, `status`, фаза, `editable` — только сервер; в схемах запросов
   их нет. Публичные `GET /v1/{races,seasons,calendar}` — без входа, только `published`/`cancelled` гонки и
   `published` старты (int: черновик и снятый старт — 404 и нет в списках). Мутаций без гарда нет; CSRF — глобальный
   (мутации только `POST`).
2. **Входные данные.** Тела — `z.strictObject` контрактов; enum-ы; даты — `LocalDate`/`UtcMinute` (невалидная дата
   `2026-02-30` — 400); числа с границами; строки — длины, без управляющих символов; `registrationUrl` — `https:`,
   без `user:pass@`, ≤ 500; `:id` — `Uuid`; query — `z.strictObject` (лишний ключ, `bikeClass[$ne]=x` — 400), массивы
   фильтров ограничены по длине; курсор — base64url → JSON → zod, в фильтр Mongo — только примитивы; поиска по
   регулярным выражениям нет. Int-тест инъекции: `{ "title": { "$ne": null } }`, `?city[$gt]=`, мусорный курсор.
3. **Данные наружу.** Публичные ответы — без `ownerUserId`, имён сотрудников, `version`, служебных дат; панель — имя
   организатора (`displayName`), без e-mail. Тексты (название, описание, город, место) — только как текст (React
   экранирует; HTML/Markdown не рендерятся — важно для принятого риска того же домена, admin-01 C3). Ссылка
   регистрации открывается с `rel="noopener noreferrer"`, `target="_blank"`. `no-store` на `/v1/admin/*` (гард);
   публичное — `public, max-age=60`.
4. **Злоупотребления.** Публичное чтение: `limit` ≤ 50, фильтры ≤ 12 значений, запросы — по индексам (`explain` в
   int-тесте не обязателен, индексы — миграцией), IP-лимит `public-read` (429 с `Retry-After`). Панель: правки только
   у членов команды; организатор не видит и не меняет чужое; опубликованная гонка не удаляется, отмена необратима и
   журналируется.
5. **Секреты и логи.** Новых секретов и env нет. Логи — `uid` сотрудника, id объекта, действие; без названий и
   описаний (могут содержать ПДн), без e-mail.
6. **Аудит.** Каждая мутация сезона, гонки, записи календаря — ровно одна запись `PanelAudit.append` в транзакции
   действия (откат — нет записи): кто, что, когда, объект (`subject` со снимком названия), изменённые поля, причина
   отмены (шаблон) / снятия (текст). Append-only — тест-сторож `panel.repository.test.ts` остаётся.

# 9. Acceptance Criteria

1. **Права:** admin — все маршруты; moderator — `GET` гонок и сезонов 200, мутации 403, календарь 403; organizer —
   гонки (свои) 200, сезоны чтение 200 / мутации 403, календарь 403; без сессии — 401. Тест «все `admin/*` под
   гардом» зелёный для `races` и `calendar`.
2. **Сезоны:** создание с непересекающимися датами → 201, журнал `season.created`; пересечение → 400
   `SEASON_OVERLAP` на поле; конец раньше начала → `DATE_ORDER`; целиком в прошлом → `SEASON_IN_PAST`; завершённый —
   смена дат `SEASON_FINISHED`, имя меняется; сжатие, выбрасывающее опубликованную гонку, → `SEASON_EXCLUDES_RACES`;
   устаревшая `version` → 409 `CONFLICT`. Два параллельных создания пересекающихся сезонов → ровно один 201
   (**отрицательное доказательство:** без `lockSchedule` — два сезона).
3. **Гонка — черновик:** организатор создаёт (201, `status: draft`, `phase: draft`, `season` — предпросмотр,
   `ownerUserId` = он); правило 48 ч → `PROTOCOL_TOO_EARLY`; окно наоборот → `DATE_ORDER`; моменты с секундами → 400;
   правка своей → 200 + журнал `race.updated { changedFields }`; чужая без `manage_any` → 404 (и в списке её нет);
   admin правит чужую → 200; удаление черновика → 204, журнал `race.discarded`.
4. **Публикация:** конец окна внутри сезона → 200, `seasonId` записан, журнал `race.published`; вне сезонов →
   `OUTSIDE_SEASON`; окно уже прошло → `WINDOW_IN_PAST`; повтор → 409 `RACE_INVALID_STATE`. Гонка «публикация ↔ сжатие
   сезона» (ворота перед записью) → либо публикация отклонена, либо сжатие отклонено; опубликованной гонки вне сезона
   нет (**отрицательное доказательство** без `lockSchedule`).
5. **Правка опубликованной** (CLOCK): до окна — все поля; окно открыто — `windowStartsAt` → `FIELD_LOCKED`; окно
   закрыто — только описание и протокол, перенос раньше → `PROTOCOL_ONLY_LATER`, позже → 200; `editable` в ответе
   соответствует фазе. Две вкладки с одной `version` → 200 и 409.
6. **Отмена:** опубликованная + шаблонная причина → 200, `phase: cancelled`, журнал `race.cancelled
   { cancelReason }`; свободный текст / неизвестная причина → 400; черновик → 409 `RACE_INVALID_STATE`; отменённую не
   править (409).
7. **Календарь:** admin создаёт → 201 `published`, журнал; `http://` и `javascript:` ссылка → 400; конец раньше
   начала → `DATE_ORDER`; «Снять с публикации» с причиной → 200, из публичного списка исчезает; «Вернуть» → снова виден.
8. **Публичное чтение:** `GET /v1/races?scope=current` — только опубликованные с незакрытым окном, по началу окна;
   `past` — закрытые и отменённые; фильтры класса и месяца (ИЛИ внутри, И между) и курсор без дублей и пропусков на
   45 гонках; черновик по id → 404; `GET /v1/seasons/current` — сезон по CLOCK или `null`; `GET /v1/calendar` — с
   `from` по умолчанию «сегодня по Минску», фильтры дисциплины и города (без учёта регистра), `cities` — уникальные;
   ответы проходят схемы контрактов; нет `ownerUserId`/`version`; `Cache-Control: public, max-age=60`; инъекции → 400.
9. **Журнал:** каждое действие AC2–AC7 — ровно одна запись с `subject` (`kind`, `id`, `label`); откат — без записи;
   фильтр `subjectId`; старые записи (admin-01) читаются с `subject: null`.
10. **Панель — «Сезоны»:** таблица (сезон, начало, конец по Минску, гонок, статус-метка), форма справа («Новый
    сезон» / «Изменить»), ошибка пересечения под полем с названием и датами пересёкшегося сезона, «Создать сезон»
    неактивна с причиной; без `seasons.manage` — таблица без кнопок; скелетон под видимой шапкой; ошибки §4.12.
11. **Панель — «Гонки»:** таблица с фильтрами (сезон, статус, класс, «Мои»), «Показать ещё»; «Новая гонка» — форма
    одной колонкой, метки «Europe/Minsk», чипы покрытия, вычисляемый сезон только для чтения, подсказка и ошибка 48 ч с
    ближайшей допустимой датой; редактирование — зафиксированные поля с замком по `editable`, причина недоступности под
    кнопкой; «Опубликовать»; «Отменить гонку?» — радиогруппа шаблонов, превью «Участники увидят «Гонка отменена.
    Причина: …»», подтверждение неактивно без выбора, Esc, фокус на первом варианте и возврат фокуса; 409 — баннер
    «Запись изменили — обновите страницу».
12. **Панель — «Календарь»:** таблица (дата, название, дисциплина, город, статус), форма записи, «Снять с публикации»
    с причиной, «Вернуть в календарь».
13. **Время:** ввод «25.10.2026 23:59» в форме при поясе браузера `America/New_York` уходит как `2026-10-25T20:59:00Z`;
    показ — по Минску.
14. **Миграции** `0006`–`0008` на чистой БД и повторно — без ошибок; коллекции, индексы, документ `race_meta.schedule`.
15. **E2E** (Playwright, `/admin/`): admin (CLI) выдаёт `organizer` второму → admin создаёт сезон → организатор
    создаёт и публикует гонку → `GET /v1/races` (fetch из теста) содержит её → admin отменяет с причиной → «Журнал
    действий» содержит записи сезона и гонки; ошибок консоли нет.
16. Регрессия: int-тесты панели admin-01 (`panel-*.int.test.ts`) зелёные без правок ожиданий; `pnpm check` зелёный.
