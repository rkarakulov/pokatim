### [HIGH] При переходе из своей строки теряется группа зачёта

- **file:** apps/app/src/features/races/race-detail.tsx
- **location:** 184–187, `ownRowAction`
- **problem:** `rivalPath` вызывается без группы выбранной строки. Для участника из группы, отличающейся от серверной группы по умолчанию, экран своего результата открывает другую таблицу.
- **why_it_matters:** Например, участница видит свою строку в женской группе, нажимает её и получает «Результат не найден» вместо результата и кнопки шаринга. Нарушен AC1.
- **evidence:** `RaceResultsTable` выбирает собственную группу через `ownGroup`, но `RivalCardScreen` читает `useRaceResults(raceId, valid, group)` и ищет строку только в этих страницах через `findRow`. Без `group` сервер выбирает `defaultGroup`, а не группу пользователя. Для чужих строк группа уже передаётся корректно.
- **recommended_fix:** Передавать текущую группу в `ownRowAction` и далее в `rivalPath`, аналогично `rowAction`. Добавить тест перехода из своей строки группы, отличающейся от серверной группы по умолчанию.

### [HIGH] Ошибка фонового обновления скрывает готовую карточку

- **file:** apps/app/src/features/races/story/queries.ts
- **location:** 59–66, формирование `state`
- **problem:** Условие `!query.isError` удаляет готовые данные из состояния для `AsyncContent`, когда фоновый запрос завершается ошибкой.
- **why_it_matters:** После возврата в приложение или вкладку при сбое сети готовое превью и действие шаринга исчезают. Это нарушает AGENTS.md §4.12: при ошибке обновления данные должны оставаться с баннером и повтором.
- **evidence:** `const ready = !query.isError && query.data?.status === 'ready' ? query.data : undefined`. Проверка через установленный `QueryObserver` подтвердила: после неудачного refetch `isError === true`, сохранённые данные `ready` доступны, но это выражение возвращает `undefined`. `AsyncContent` умеет сохранять контент при ошибке, если ему передать данные.
- **recommended_fix:** Передавать сохранённый ответ `ready` независимо от ошибки фонового запроса, сохранив `isError`, `error` и `refetch` для баннера. Добавить тест `ready → ошибка refetch` с сохранением превью.

### [HIGH] После ошибки скачивания PNG нет доступного повтора

- **file:** apps/app/src/features/races/story/story-card-screen.tsx
- **location:** 43–64, 81–92, `ShareAction` и `ReadyCard`
- **problem:** При ошибке `useStoryFile` экран показывает баннер, но не предоставляет повтор загрузки. Кнопка шаринга остаётся выключенной, поскольку файла нет.
- **why_it_matters:** После исчерпания автоматических ретраев пользователь не может завершить шаринг с этого экрана, даже если соединение восстановилось. Нарушен AGENTS.md §4.12: ошибка загрузки всегда должна иметь повтор.
- **evidence:** В `ShareAction` передаются только `file.data` и `file.isError`; `file.refetch` не передаётся. При `error === true` отображается только `Banner`, а единственная кнопка имеет `disabled={!file}`.
- **recommended_fix:** Добавить действие «Повторить», вызывающее `file.refetch`, и различать сетевую ошибку и ошибку сервера. Проверить сценарий неудачного скачивания с последующим успешным повтором.

### [MEDIUM] Финишёры до публикации протокола получают карточку без предварительного статуса

- **file:** apps/api/src/modules/sharing/story-card.texts.ts
- **location:** `storyCardTexts`, поле `kicker`
- **problem:** Метка «Предварительный» выбирается только при `facts.status === 'provisional'`, хотя статус `finisher` используется и до публикации протокола.
- **why_it_matters:** Карточки START и Verified без пульса во время открытой гонки не обозначают предварительность результата, вопреки R4 и RC-3 задачи.
- **evidence:** `resultStatus` в `results.policy.ts` возвращает `finisher` для `entry.best.ranked === false` до проверки публикации. `StoryCardFacts` не содержит отдельного признака публикации, а `storyCardTexts` для `finisher` всегда выводит «Гонка».
- **recommended_fix:** Передать из results признак предварительности по состоянию протокола, включить его в хэш и использовать для метки. Добавить тесты финишёра до и после публикации.
