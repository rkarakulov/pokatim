### [HIGH] При отсутствии сети подготовка PNG остаётся скелетоном без сообщения и повтора

- **file:** apps/app/src/features/races/story/story-card-screen.tsx
- **location:** 119–145, `ReadyCard`
- **problem:** Состояние `file.fetchStatus === 'paused'` не обрабатывается. Если статус карточки уже `ready`, а PNG ещё не подготовлен, при отсутствии сети экран показывает скелетон и выключенную кнопку без сообщения «Нет соединения» и действия «Повторить».
- **why_it_matters:** Нарушен AGENTS.md §4.12. Сценарий возникает при потере соединения между получением токена и скачиванием PNG либо при открытии сохранённого `ready`, когда файла в кэше ещё нет.
- **evidence:** `failure` учитывает только `(file.isError && !story) || previewFailed`; при отсутствии `uri` выводится `PreviewSkeleton`. Проверка установленного `QueryObserver` с `onlineManager.setOnline(false)` дала `isPending: true`, `isError: false`, `fetchStatus: 'paused'`, данные отсутствуют. На native состояние сети подключено через `lib/online-manager.ts`. Внешний `AsyncContent` отслеживает запрос статуса карточки, а не файла.
- **recommended_fix:** Обрабатывать приостановленную загрузку файла без данных как «Нет соединения» с повтором, аналогично `AsyncContent`. Добавить тест: статус `ready`, файл отсутствует, сеть отключена → сообщение с повтором; восстановление соединения → превью и доступный шаринг.

### [MEDIUM] Ошибка превью переносится на другой готовый шаблон

- **file:** apps/app/src/features/races/story/story-card-screen.tsx
- **location:** 122–129, 194–199
- **problem:** `previewFailed` сохраняется при смене `template` или `token`. Если оба шаблона уже находятся в кэше, переключение после ошибки изображения сохраняет тот же экземпляр `ReadyCard`, поэтому исправная карточка другого шаблона тоже показывает ошибку и блокирует шаринг.
- **why_it_matters:** Ошибка одного PNG мешает использовать другой подготовленный PNG до дополнительного нажатия «Повторить».
- **evidence:** Состояние сбрасывается исключительно после `file.refetch()`; `ReadyCard` рендерится без `key`. При переходе между двумя ответами `ready` компонент остаётся на прежней позиции внутри `AsyncContent`.
- **recommended_fix:** Привязать состояние превью к идентичности карточки, например задать `ReadyCard` ключ из шаблона и токена. Проверить переключение на ранее подготовленный шаблон после `onError`.
