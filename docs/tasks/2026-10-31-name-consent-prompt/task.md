# 1. Title

Имя в результатах: согласие в момент записи на гонку и различимая заглушка «Райдер #N» (name-consent-prompt)

# 2. Goal

Сейчас (P1, `docs/product/profile.md`) имя в публичных таблицах — только при `showNameInResults` (opt-in, переключатель
спрятан в «Редактировать профиль»). Почти никто его не включает — в таблицах сплошное «Участник». Opt-in остаётся
(закон РБ о ПДн, журнал Q1), но:

1. согласие спрашиваем в момент пользы — сразу после записи на гонку;
2. вместо одинакового «Участник» — различимая подпись «Райдер #N» по стабильному номеру заявки в гонке.

Уровень — task3 (контракт ответа, миграция, новый UI-шаг, правка текста согласия).

# 3. Scope

## 3.1 Решения (N1–N8, автор задачи — сессия-оркестратор; human gate — по отчёту)

- **N1 — где спрашиваем:** только после **новой** активной заявки на гонку (`useEnterRace`, как подсказка push N5; не
  после повышения до Verified). Райды и заезды по маршруту — нет: там имени в публичных таблицах нет (райд — K3/K4
  «Свои», заезды по маршруту — личные).
- **N2 — когда показываем:** профиль известен (`['profile']` в кэше или загружен) и **нет публичного показа** (имени нет
  или `showNameInResults: false`) и не действует пауза N3. Профиль не загрузился — не показываем (без ошибки).
- **N3 — правило повтора:** «Не сейчас», закрытие шита или «Сохранить» с выключенным переключателем — пауза **90 дней**
  на устройстве (`pokatim.nameConsentPrompt`, SecureStore / `localStorage`, как `pokatim.pushSoftPrompt`). Не чаще
  одного раза за запуск приложения. Включил показ — больше не показываем (условие N2). Пауза — флаг устройства, не
  аккаунта: выход её не стирает (как у push-подсказки) — принято.
- **N4 — шит «Как вас показывать в результатах?»** (`ModalSheet`): поле имени (`RiderPublicName`, P2, предзаполнено
  текущим `publicName`), переключатель «Показывать имя в таблицах результатов» — **предзаполнен «вкл»**, пояснение
  (тот же текст, что в профиле), «Сохранить» и «Не сейчас». Включённый переключатель с пустым именем — ошибка под полем
  «Введите имя» (в шите показ без имени бессмыслен; в профиле прежнее правило P1 не меняется).
- **N5 — согласие явное:** согласие = только «Сохранить» с включённым переключателем → `PATCH /v1/profile`
  `{ publicName, showNameInResults }` (существующий API, событие Q1 пишет сервер при фактической смене флага).
  Пропуск, закрытие, фон — согласия нет, запросов нет. Предзаполненный переключатель без «Сохранить» ничего не значит.
- **N6 — версия текста согласия:** пояснение `profile.show.hint` меняется («Участник» → «Райдер #N») —
  `PUBLIC_NAME_CONSENT_VERSION` = `2026-10-31`. Шит и профиль показывают одни ключи (`profile.show.label`/`hint`) —
  один текст, одна версия.
- **N7 — заглушка:** номер заявки в гонке `entryNo` — порядковый номер записи на гонку (значение счётчика
  `races.entryAdmissions` после `admitEntry` в транзакции вставки заявки). Уникален в гонке (транзакционный счётчик;
  возможны пропуски — повышения и откатившиеся транзакции тоже увеличивают счётчик), не меняется (снятие заявки, DQ,
  смена протокола его не трогают), **в другой гонке у того же райдера — другой номер** (нельзя сопоставить человека
  между гонками). Не `userId` и не производная от него. Публичная строка таблицы и финишёров — `riderNo` (число) только
  когда `riderName === null`; приложение: чужая строка без имени — «Райдер #N», `riderNo: null` (старый сервер,
  заявка старого API в окне деплоя) — прежнее «Участник». Своя — «Вы». Раскрытие: номер говорит лишь о порядке записи
  внутри гонки; наблюдатель, видевший имя до отзыва согласия, может связать «#N» с именем в этой гонке — принято (тот
  же номер, что раньше был рядом с именем, не публиковался: `riderNo` уходит только без имени).
- **N8 — сезон и панель:** таблица сезона остаётся «Участник» (строка сквозная по гонкам — номер гонки там не
  применим, сезонный номер связал бы гонки); панель (`Участник ·<id>`) не меняется. Служебные подписи P2: имя не может
  быть «Райдер», «Райдер #N», «Райдер №N», «Райдер N» (без учёта регистра и пробелов вокруг `#`/`№`) — `INVALID`.

## 3.2 Работы

- contracts: `RaceResultRow.riderNo`, `RaceFinisherRow.riderNo` — `z.number().int().positive().nullable().default(null)`;
  `PUBLIC_NAME_CONSENT_VERSION` → `2026-10-31`; запрет служебных имён «Райдер …» в `riderLine`.
- api: `race_entries.entryNo?: number` (пишет `EntriesService.enter` из `race.entryAdmissions` ответа `admitEntry`);
  `RaceForResults.entryAdmissions`; миграция `0048_race_entry_numbers` — бэкфилл `entryNo` по `(createdAt, _id)` в
  гонке и `races.entryAdmissions = max(текущий ?? 0, число заявок)`; публичная таблица (живая и протокол) и финишёры
  отдают `riderNo` при `riderName === null`.
- app: заглушка через общий хелпер (`resultRow`, `finisherRow`, карточка соперника спора); шит согласия
  (`features/profile/name-consent-*`), предложение из `useEnterRace.onSuccess`, место показа — карточка гонки.
- i18n, доки (`profile.md` — решения N1–N8 рядом с P1; `races-and-seasons.md` — таблица), правила `.claude/rules`.

# 4. Out of Scope

- Подсказка на райдах, заездах по маршруту, Главной (есть K3 «Добавьте имя — свои увидят вас»).
- Номер в таблице сезона и в панели; показ `entryNo` самому райдеру («ваш номер»).
- Смена умолчания P1 (opt-out) — нет.

# 8.3 Security checklist

1. **AuthN/AuthZ:** `PATCH /v1/profile` — прежний `AuthGuard`, пользователь из access; новых эндпоинтов нет.
2. **Входные данные:** имя — `RiderPublicName` (P2 + новые служебные подписи); клиент шлёт только флаг согласия,
   версию и время пишет сервер.
3. **Данные наружу:** `riderNo` — порядковый номер в гонке, не `userId`, не связывает гонки; уходит только без имени.
   `entryNo` в «моё участие» и панель не добавляется.
4. **Злоупотребления:** прежний лимит `profile-update` 30/ч; шит не шлёт запросов без нажатия.
5. **Секреты и логи:** логов имени и номера нет.
6. **Аудит:** журнал согласий Q1 (`profile_consent_events`) — без изменений, версия текста поднята.

# 9. Acceptance Criteria

- AC1: после новой заявки на гонку без публичного имени — шит; «Сохранить» с именем и вкл → `PATCH` с
  `showNameInResults: true`, шит закрыт, таблица перезапрошена.
- AC2: «Не сейчас» / закрытие / сохранение с выкл — запроса согласия нет (выкл — `PATCH` без смены флага), пауза 90 дн.
- AC3: при публичном имени, паузе, повышении до Verified, ошибке профиля — шита нет.
- AC4: вкл + пустое имя — ошибка под полем, запроса нет.
- AC5: публичная таблица (живая, протокол) и финишёры — `riderNo` = `entryNo` заявки при `riderName: null`, иначе
  `null`; новые заявки получают возрастающие уникальные номера; миграция нумерует старые.
- AC6: приложение — чужая строка без имени «Райдер #N», `riderNo: null` — «Участник», своя — «Вы»; a11y-подпись строки
  с той же подписью.
- AC7: имя «Райдер», «Райдер #5», «райдер №12» — `INVALID`.
- AC8: `PUBLIC_NAME_CONSENT_VERSION = '2026-10-31'`, новый текст пояснения.
