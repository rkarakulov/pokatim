# 0013. Кофе-райды: райд райдера, участие одной атомарной операцией, лента под входом, публичная карточка

- Статус: Proposed
- Дата: 2026-10-27
- Задача: `docs/tasks/2026-10-27-app-05-rides` (PR 05a; жалобы и модерация — PR 05b)

Перевод в Accepted — после ревью 05a.

## Контекст

Кофе-райд — сущность приложения (ADR-0010 п. 1): создаёт райдер, участвуют райдеры, команда платформы вмешивается
только по жалобам. Нужны: запись с лимитом мест без перебора при одновременных нажатиях, лента, зависящая от
зрителя, публичная ссылка для приглашения, защита от UGC-злоупотреблений. Координат и карты нет (MVP §1, ADR-0007
R11 — «рядом» позже).

## Решение

1. Модуль `rides` (папка API), зависит только от `identity` (index) и общих `src/*`; панель — с модерацией (05b).
2. Участники — встроенный массив документа райда (≤ 100) + `goingCount`; «Я иду» / «Не иду» / правка лимита — по
   одной атомарной операции `findOneAndUpdate` с условием в фильтре (лимит, статус, время, членство): инварианты в
   одном документе, без транзакций и замков. `version` — только для правок организатора (участие её не меняет).
3. Чтение: лента, города и состояние зрителя — под `AuthGuard`, `no-store` (зависят от зрителя); карточка — публичная
   без зрителя (`public, max-age=60`, `public-read`), состояние — `GET /v1/rides/:id/me`.
4. Место — город из справочника `CITY_CODES` + место текстом; координаты, «рядом» и карта — отдельным решением
   (тайлы/геокодер — внешний сервис). Поле точки добавится expand-миграцией (`startPoint: Point | null` + `2dsphere`).
5. Фаза (`upcoming → past`, `cancelled`) — по `CLOCK`, не хранится; запись, правка, отмена — до старта.
6. Отмена — причина из справочника; отменённый будущий райд — в ленте только участникам и организатору.
7. UGC: публичные карточки `noindex`, OG без описания и ПДн, лимиты частоты и квоты; жалобы и скрытие — до прода.
   Реализовано в 05b: жалоба `POST /v1/rides/:id/reports` (одна от пользователя, коллекция `ride_reports`),
   статус `hidden`, раздел панели «Модерация райдов» (`rides.moderate`, `PanelGuard`, журнал `ride.*`); жалоба и
   действия модерации — транзакции, первой записью пишут документ райда (счётчик открытых жалоб без рассинхрона).
8. Подпись организатора — необязательное поле райда «Как вас подписать» (`organizerName`, решение автора): вводит сам
   организатор, данные аккаунта не читаются; в OG и мета её нет.

## Альтернативы

- Коллекция `ride_participants` + транзакция: лимит — условие по другому документу, нужен замок `$inc version` райда;
  больше кода, тот же результат — нет.
- Публичная лента с кэшем: роль зрителя и отменённые свои недоступны, после «Я иду» браузер отдаёт старую страницу до
  60 с — нет.
- Свободный текст города (UGC в чипах фильтра) — нет.
- Карта и геокодер сейчас (внешний сервис, ADR, удвоение scope) — нет.

## Последствия

- Число участников ограничено размером документа (100); список участников с именами потребует профиля (имя, фото) и
  проекции без чужих id.
- Уведомления об отмене и переносе — модуль `notifications` (события `rides.*` добавит он).
- Удаление аккаунта обязано отменить будущие райды организатора и снять его отметки (`pokatim-db.md`).
- Выпуск в прод и сторы — только вместе с 05b (жалобы, скрытие командой) — 05b реализован, ограничение снято.
- `version` райда меняют и «Скрыть»/«Вернуть» модератора (открытая форма правки получит 409); жалобы — неизменны по
  содержанию, закрываются один раз (`resolvedAt`), решения и причины — в журнале панели.
- Удаление аккаунта (будущее) обязано обработать и жалобы пользователя (`ride_reports.reporterUserId`).
