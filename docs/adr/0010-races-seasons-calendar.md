# 0010. Гонки по коридору, сезоны и календарь стартов: границы, время, сериализация расписания

- Статус: Accepted
- Дата: 2026-10-26
- Задача: `docs/tasks/2026-10-26-admin-02-seasons-races` (R1–R13, ответы автора Q2, Q4, Q11)

## Контекст

Первый доменный модуль pokatim. Команда платформы ведёт в панели «Протокол» сезоны, гонки по GPS-коридору (окно дат,
плановая дата протокола, сезон по концу окна) и календарь внешних стартов; приложение райдера читает опубликованное
(Главный экран, будущие «Гонки» и «Календарь»). Инварианты расписания затрагивают несколько документов («сезоны не
пересекаются», «опубликованная гонка — внутри своего сезона», «сжатие сезона не выбрасывает гонки»), правки двух
вкладок не должны молча перезаписывать друг друга, а установленные сборки приложения живут долго.

## Решение

1. **Три сущности, без общего «типа события»:** гонка по коридору (панель, модуль `races`), старт календаря (панель,
   модуль `calendar`), кофе-райд (приложение, будущий модуль `rides`). Разные владельцы и жизненные циклы.
2. **Модуль `races` = сезоны + гонки** (R1): инвариант «гонка в сезоне ↔ сезон не выбрасывает гонки» — в одной
   транзакции без цикла модулей. Сезонный рейтинг (FR-4) — отдельный модуль позже, читает через порты. `calendar` —
   отдельный контекст. Оба зависят только от `modules/panel/index.ts` (`PanelGuard`, права, `PanelAudit`,
   `PanelDirectory`); `panel` о них не знает — журнал хранит снимок объекта `subject: { kind, id, label }` (R7).
3. **Время** (R4): в БД и API — UTC. Окно и протокол гонки — моменты с точностью до минуты; окно включает последнюю
   минуту (`open`, пока `now < windowEndsAt + 1 мин`, R12). Сезоны и старты календаря — календарные даты Минска
   (`LocalDate`); сервер хранит и границы-моменты сезона (`startsAt` = 00:00 Минска дня начала, `endsBefore` = 00:00
   дня после конца). Перевод настенного времени Минска — только функции `packages/contracts/src/time.ts` (`Intl`,
   пояс браузера и устройства не участвует).
4. **Замок расписания `lockSchedule`** (R2): транзакция, создающая или меняющая даты сезона, публикующая гонку или
   меняющая конец окна опубликованной, первой операцией пишет `race_meta.schedule` (`$inc version`) — две такие
   транзакции конфликтуют, `MongoTransactions` повторяет проигравшую на свежем снимке. Отрицательные доказательства —
   int-тесты «два пересекающихся сезона» и «публикация ↔ сжатие сезона».
5. **Оптимистичная версия** (R3): у сезона, гонки и записи календаря — `version`; изменение несёт ожидаемую версию,
   запись — `findOneAndUpdate({ _id, version, status })`; устарело — `409 CONFLICT` («Запись изменили — обновите
   страницу»). Недопустимый статус гонки — `409 RACE_INVALID_STATE`.
6. **Вычисляемые значения — сервер** (R5, R10): хранится только статус гонки (`draft → published → cancelled`), фаза
   (`draft | upcoming | open | closed | cancelled`) и `PanelRace.editable` (поля, действия, причины) считаются по
   `CLOCK`. Черновик сезона не хранит — сезон фиксируется при публикации под замком (R9).
7. **Владение** (R8): `races.manage` без `races.manage_any` (организатор) — только свои гонки; чужая — `404`.
8. **Публичное чтение** (Q14): `GET /v1/races`, `/v1/races/:id`, `/v1/seasons/current`, `/v1/calendar`,
   `/v1/calendar/:id`, `/v1/calendar/cities` — без входа, только опубликованное (гонки — и отменённые), без владельца и
   служебных полей, `Cache-Control: public, max-age=60`, IP-лимит `public-read`. Enum-ы ответов приложения —
   `tolerantEnum` (R6): незнакомое значение — `'unknown'`, экран показывает нейтральный вариант.
9. **Гонка-анонс без коридора** (Q4): до слайса «Маршруты» гонка публикуется без эталонного коридора (дистанция —
   вручную); слайс маршрутов делает коридор обязательным до участия.

## Альтернативы

- **Отдельные модули `seasons` и `races` с портами** — цикл зависимостей или событийная согласованность с окном
  нарушения. Нет.
- **Уникальный индекс по дню / Redis-лок** вместо `lockSchedule` — индекс не ловит пересечение диапазонов, Redis-лок
  вне транзакции БД. Нет.
- **Всё моментами для сезонов** — «1 апреля — 31 октября» превращается в `23:59:59.999` и ошибки на границе дня. Нет.
- **Хранимая фаза** — нужен планировщик переходов, расходится с часами. Нет.
- **Строгий `z.enum` в ответах приложения** — новый класс или фаза роняет разбор всего списка у старых сборок. Нет.

## Последствия

- Все правки сезонов и публикации гонок сериализуются одним документом — принято (единицы правок в минуту).
- Фаза в публичном списке видна с задержкой кэша до минуты.
- Блокировки отмены (D-19), фиксация полей с первой записи (V-12), фазы результатов — точки расширения
  (`editable.reasons`, enum-ы — только в конец), их добавят слайсы участия, результатов и споров.
- `tolerantEnum` и функции времени — кандидаты в `@rkarakulov/contracts-core`; компоненты `src/ui` панели — в
  `admin-kit` (F6).
