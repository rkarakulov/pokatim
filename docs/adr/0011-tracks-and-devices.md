# 0011. Треки и устройства: ручная загрузка FIT/GPX, импорт Garmin и Wahoo через агрегатор Open Wearables

- Статус: Accepted (автор, 2026-10-26)
- Дата: 2026-10-26
- Задача: `docs/tasks/2026-10-26-tracks-devices` (R1–R13, ответы автора Q1–Q11, N1–N3)

## Контекст

Райдеру нужно получать заезды в «Покатим» без записи GPS в приложении (`AGENTS.md` §1): файлом с часов или
велокомпьютера и автоматически из Garmin и Wahoo. Рамки MVP запрещали «Strava/Garmin API» без ADR; правила требовали
файлы пользователей в S3 (его в проекте нет), resumable-загрузку в приложении и хранение «сэмплов» трека. Прямые
интеграции с провайдерами — это OAuth, ротация и шифрование токенов, вебхуки без подписи, заявки на consumer-ключи;
соседний проект уже держит self-hosted агрегатор Open Wearables (OW), который делает это за приложение.

## Решение

1. **Рамки MVP расширены:** Garmin и Wahoo — только **импорт велозаездов** через self-hosted агрегатор (без push,
   записи GPS, BLE, без выгрузки в провайдеров). Strava и др. — нет.
2. **Порт агрегатора `WearablesAggregator`** (доменные типы pokatim) и единственный адаптер `OpenWearablesAggregator`
   (REST OW, ключ `X-Open-Wearables-API-Key`). REST OW вне адаптера запрещён; другой агрегатор (ROOK и т. п.) — новый
   адаптер. Версия OW пинуется; контрактный тест адаптера — против фейкового OW.
3. **Токены провайдеров у pokatim не хранятся** — их держит OW. У pokatim — API key OW и секрет вебхука **только в
   env** и соответствие «пользователь pokatim ↔ пользователь OW» (`external_user_id = pokatim:<userId>`, без ПДн).
4. **Активация подключения под входом по одноразовому тикету** из `redirect_uri`: OW связывает аккаунт провайдера
   уже в своём callback, поэтому подключение без `complete` владельцем тикета не активируется и не импортируется;
   чужой `complete` и неподтверждённое за TTL — отзыв в OW.
5. **Pull — основной путь** (каждые 15 мин + «Синхронизировать сейчас»), вебхук OW (Svix-подпись) — только сигнал
   «пора забрать», данные из тела не используются; без секрета — `404`.
6. **Ручная загрузка FIT/GPX** — сырой поток `application/octet-stream` ≤ 16 МиБ, формат по содержимому; разбор —
   только в worker (`worker_threads` с лимитами памяти и времени), парсеры `@garmin/fitsdk` и `fast-xml-parser`
   (без DTD и сущностей) в `packages/tracks` (вход `@pokatim/tracks/parse` — только сервер).
7. **Исходник хранится без прореживания**: файл загрузки или поток точек OW в нашем формате `pokatim.stream.v1`
   (gzip JSON) — через порт `TrackFileStore`; на dev — том сервера с квотой и уборкой, S3-адаптер — до прода
   (отклонение от правила «файлы — S3», C2). Файлы наружу не выдаются.
8. **Активность** — сводка (время, дистанция, спорт, флаги датчиков) и упрощённая `LineString` (≤ 1000 точек,
   `2dsphere`); дубли одного заезда из разных источников — группа с основной по приоритету, вставка под
   `lockUserActivities` (как `lockSchedule`, ADR-0010).
9. **Биометрия не хранится** (C5): ряды пульса/мощности у агрегатора не запрашиваются и в БД не пишутся; флаги
   `hasHeartRate`/`hasPower` — только для приоритета дублей, наружу не выходят.
10. **Окружения:** dev — общий инстанс OW соседнего проекта (свой API key, `OW_SHARED_INSTANCE=true`); prod — свой
    инстанс и свои consumer Garmin/Wahoo; `OW_SHARED_INSTANCE=true` в production — отказ запуска.
11. **Отклонения от правил** (C3, C4): загрузка в приложении v1 — одна попытка с прогрессом и отменой, без resumable и
    очереди, переживающей перезапуск; TCX не поддерживается.

## Альтернативы

- **Прямые OAuth и вебхуки Garmin/Wahoo** (редакция 1) — шифрование и ротация токенов, Redis-замки refresh, relay
  чужих вебхуков, заявки на consumer; заменено агрегатором.
- **Завершать подключение в callback без входа** — привязка чужого аккаунта провайдера по ссылке злоумышленника.
- **Только вебхуки** — на общем OW исходящие вебхуки — настройка всего инстанса; pull работает без неё.
- **GridFS** для файлов — растит БД и бэкапы; **S3 сразу** — новый внешний сервис и IAM до прода.
- **Хранить ряды пульса/мощности** — биометрия без нужды v1.

## Последствия

- Новый внешний сервис (OW) — версия пинуется, адаптер сверяется с ней; на dev общий инстанс без изоляции данных
  (глобальный API key) — принято для тестеров; один аккаунт Garmin — в одном проекте на общем consumer.
- Привязка в OW возникает до подтверждения — компенсируется статусом `pending` и уборкой.
- Подрезка рядов OW (data lifecycle) не влияет на сохранённые заезды — у pokatim своя копия потока.
- До прода: S3-адаптер `TrackFileStore`, свой OW и consumer, видимость финальных провалов в панели.
- **`@garmin/fitsdk` (V5, решение автора 2026-10-26):** проприетарная FIT Protocol License — SDK только на сервере,
  в git не вендорится, в бандл приложения не попадает; риск принят автором. Рекомендация — приватные образы GHCR
  (решает владелец). Путь отката — MIT-парсер FIT за тем же портом разбора (`packages/tracks`).
- Удалённый пользователем заезд агрегатора не воскресает: маркер объекта источника (`track_source_refs`) в
  транзакциях удаления и приёма.

## Дополнение: исключения «файлы наружу не выдаются»

- Перекодированный аватар (ADR-0019) и перекодированное фото организатора кофе-райда (ADR-0028): только JPEG без
  метаданных, по случайному id, исходник не хранится. Исходники треков и маршрутов — по-прежнему не выдаются.
