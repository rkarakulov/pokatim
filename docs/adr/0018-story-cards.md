# 0018. Карточки для сторис: серверный рендер satori + resvg в воркере, capability-URL картинки, системный шаринг

- Статус: Accepted
- Дата: 2026-10-28
- Задача: `docs/tasks/2026-10-28-story-cards`

## Контекст

Райдер делится своим результатом гонки картинкой 9:16 (1080×1920) для сторис: линия трека, время, место, группа,
название гонки, бренд. Карточка — в цветах и гарнитурах активной темы (ADR-0016: тема глобальная, её знает сервер).
Приложение одно на iOS, Android и web с SSR (ADR-0003); `docs/proposal-stack-architecture.md` закладывал серверный
рендер карточек в очереди. Нужны: одинаковая картинка на всех платформах, перенос длинных названий, приватность
(имя — по согласию, трек — без точки у дома), без роста бандла приложения.

## Решение

1. **Рендер — сервер, задача BullMQ `story-card` в worker.** satori (дерево flex-разметки → SVG, вёрстка текста по
   метрикам шрифта) + `@resvg/resvg-js` (SVG → PNG). Замер: satori ≈ 45 мс, resvg ≈ 170 мс, холодный старт ≈ 1.7 с —
   тяжёлое по AGENTS §4.5, поэтому не в HTTP-процессе. Рендер — чистая функция данных, роли темы, шаблона и токенов
   `storyCard` (`@pokatim/design-tokens`).
2. **Шрифты** — TTF пакетов `@expo-google-fonts/*` (те же гарнитуры, что у приложения), зависимость `apps/api`;
   грузятся один раз на процесс воркера, только начертания тем.
3. **Доставка:** `GET /v1/races/:raceId/entry/story-card?template=line|night` (вход, своя заявка) → `pending` |
   `ready` + `token` | `failed` (последний рендер не удался — сообщается один раз, `GETDEL`; повтор ставит заново);
   клиент опрашивает раз в секунду до 30 с. Адрес картинки строит api-client (`storyCardImageUrl(token)` →
   `${baseUrl}/v1/story-cards/<токен>.png`): сервер свой публичный origin не знает. PNG — в Redis (TTL 24 ч) под
   случайным 128-битным токеном, выдача без авторизации (capability-URL: картинку берут `<img>`, `fetch` и загрузчик
   файлов native без заголовков), IP-лимит `story-card-image`. Ключ кэша — sha256 входов (заявка, попытка, её
   ревизия проверки и разметка, место, ничья, группа, статус, имя, тема, шаблон, окно и название гонки,
   `renderVersion`). Дедупликация постановки — ключ NX по хэшу (jobId — вторая линия); worker перечитывает входы и
   при несовпадении хэша задачу пропускает. **Изменил разметку, тексты или токены карточки — подними
   `STORY_CARD_POLICY.renderVersion`.**
4. **Приватность на сервере:** имя — только с согласием (`RIDER_NAMES`), линия — отрезок своей попытки между
   воротами гонки или публичная линия маршрута; точек до ворот старта на картинке нет.
5. **Шаринг на клиенте:** native — файл в кэш (`expo-file-system`) и `expo-sharing` (системный лист: «Сохранить
   изображение», Instagram Stories через лист Instagram, без SDK-ключей); web — Web Share API с файлом, иначе
   скачивание PNG.

6. **Право на карточку — сервер:** один предикат `storyCardEligible` (`results.policy.ts`) для
   `MyRaceEntry.actions.canShareStory` и `409 STORY_CARD_UNAVAILABLE` (заявка активна, время есть, статус
   `provisional | finisher | final | revised`).
7. **Шаблоны** `line` (светлая схема темы) и `night` (тёмная): карточка следует теме «Протокола», а не схеме
   устройства. Цифры времени не табличные (satori не поддерживает `font-variant-numeric`): кегль — ступенями по
   длине строки (≤ 7 символов — 216, 8 — 180, ≥ 9 — 156 px). Дата — окно гонки по Минску с годом, а не дата своего
   заезда (её публичная таблица не раскрывает).

## Рассмотренные альтернативы

- **Клиент: `react-native-view-shot` + html2canvas на web** — три растеризатора с разным текстом и сглаживанием,
  новый нативный модуль, web-скриншот DOM нестабилен (шрифты, трансформации); приватность и тема — на клиенте.
- **Клиент: SVG-строка → `Svg.toDataURL` (native) и canvas (web)** — без переноса строк (нет вёрстки текста), на
  web шрифты в SVG-картинке работают только base64-встраиванием (сотни КБ на гарнитуру), native и web рисуют
  по-разному.
- **satori/resvg-wasm в бандле приложения** — +2–5 МБ wasm и шрифтов на web, рендер на слабых телефонах ~1 с.
- **Синхронный рендер в HTTP-обработчике** — проще (без опроса), но 0.2–1.7 с CPU в event loop API на запрос.

## Последствия

- Образ api тяжелее: нативный бинарь resvg (~6 МБ, prebuilt linux-x64-gnu для bookworm) и TTF гарнитур тем.
- Новый нативный модуль приложения `expo-sharing` → новая dev-сборка iOS/Android.
- Уже скачанную картинку отозвать нельзя; новая после DQ/снятия не выдаётся, ссылка живёт ≤ 24 ч.
- Капабилити-токен — в пути: попадает в access-лог nginx dev-стенда (формат без query его не убирает). Содержимое
  картинки — публичные данные таблицы и имя с согласием, TTL 24 ч; ссылки `auth/verify/<token>` логируются так же —
  принято. Логи worker — заявка, шаблон, итог, байты и время, без `userId`, имени и токена.
- Данных пользователя в MongoDB модуль `sharing` не хранит; PNG с именем живёт ≤ 24 ч в Redis — порта стирания
  аккаунта нет.
- Native без модуля `ExpoSharing` (Expo Go, dev-сборка до story-cards) — режим «Скачать PNG» через системный браузер;
  `expo-sharing` импортируется лениво.
- Тот же рендер — основа карточки-приглашения кофе-райда и OG-картинок (следующие слайсы).

## Дополнение: карточка-приглашение кофе-райда (`docs/tasks/2026-10-28-ride-invite-card`)

- `GET /v1/rides/:rideId/invite-card?template=line|night` (`AuthGuard`, `no-store`, ответ — `StoryCardStatus`):
  любой вошедший, кому виден райд; скрытый (и организатору) и неизвестный — 404, не будущий опубликованный — 409
  `STORY_CARD_UNAVAILABLE`. Та же очередь `story-card` (задача `ride-invite.render`), тот же кэш, лимиты и
  `GET /v1/story-cards/:file`; общий поток статуса — `CardRequests`.
- Картинка не зависит от зрителя (ключ — поля райда, тема, шаблон, публичный маршрут): «Кофе-райд», название, дата
  без года, день недели и время, «Старт: место», дистанция и темп, бренд; без организатора и участников (Q7). Линия —
  только маршрута, который **сейчас в каталоге** (`RideRoutes.catalogLine`, без кэша); свой маршрут организатора
  (`private`) на картинку не попадает никогда. Данные — порт `rides` `RIDES_FOR_SHARING`.
- `line` — 4b «карточка-линия», `night` — 4a без фото (фото организатора — follow-up, модуль `media`).
- Отметка провала (`failed:<hash>`, `GETDEL`) у приглашения общая для всех зрителей райда: её может «забрать» другой
  зритель, а тот, у кого рендер упал, увидит `pending` и поставит рендер снова (свой лимит) — принято.

## Дополнение: OG-картинки публичных страниц (`docs/tasks/2026-10-29-og-images`)

- Своя картинка 1200×630 — гонка (`published`), кофе-райд (`published`, любая фаза), маршрут каталога (`IN_CATALOG`),
  старт календаря (`published`); остальные публичные страницы (`/welcome`, `/`, сезон, профиль райдера, вход,
  регистрация, `/status`) — бренд-картинка. Шаблон один, светлая схема темы «Классика» (гость — «Классика»,
  ADR-0021; глобальной активной темы больше нет), токены `ogCard`. Отменённые гонка и райд — бренд.
- Версия в URL: `GET /v1/og/cards/<kind>/<id>` → `{ version }` (16 hex sha256 входов: вид, `renderVersion`, тема,
  публичные поля, ссылка на публичную линию); PNG — `GET /v1/og/images/<kind>/<id>/<v>.png` без входа: текущая
  версия — `200` `public, max-age=86400`; старая — `302` на текущую (`public, max-age=300`); PNG ещё нет — бренд-PNG
  `no-store` и постановка рендера; непубличный — `404` JSON. SSR берёт версию отдельным запросом (кэш 60 с) —
  модули-владельцы о `sharing` не знают; данные — порты `RACES_/RIDES_/ROUTES_/CALENDAR_FOR_SHARING`.
- Рендер — только worker (`og-card.render` в очереди `story-card`, `priority` ниже сторис). Пререндер `og.sync`
  (очередь `og-sync`, каждую минуту и при старте, DV-1 — без outbox): объекты, изменившиеся после курсора
  `(updatedAt, _id)`; смена темы или `OG_CARD_POLICY.renderVersion` — полный проход. Хранение — Redis
  (`og:png:<hash>`): вариант A R-A1 — TTL 7 суток с продлением при выдаче, пререндер только «живых» объектов (райд —
  старт ≤ 14 сут. назад, гонка — окно закрылось ≤ 30 сут. назад, старт — ≤ 14 сут.), PNG ≤ 300 КБ (замер — 20–50 КБ);
  остальные получают картинку самолечением при первом запросе.
- Приватность: на картинке только поля публичной страницы, без организатора, автора, участников и описания; линия
  райда — только маршрута, который сейчас в каталоге; PNG ищется по текущему хэшу — старый PNG с линией по URL
  недостижим (старая версия — `302`).
