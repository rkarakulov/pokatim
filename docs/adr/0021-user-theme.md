# 0021. Личная тема райдера: поле профиля, `PUT /v1/profile/theme`, тема карточек — создателя, SSR из cookie

- Статус: Accepted
- Дата: 2026-10-29
- Задача: `docs/tasks/2026-10-29-user-theme`
- Поправка к [ADR-0016](0016-app-themes.md): п. 4–5 и решение T1 («тема глобальная») заменены этим ADR.

## Контекст

По ADR-0016 тему всем райдерам задаёт панель (`GET/PUT /v1/appearance`). Пользователь решил (U1–U4): каждый вошедший
райдер сам выбирает одну из 7 тем в «Настройках», выбор виден на всех его устройствах; гость и вошедший без выбора —
«Классика»; карточки для сторис и приглашения — в теме того, кто их создаёт; сезонный декор остаётся глобальным в
панели.

## Решение

1. **Хранение — `profiles.themeId?: AppThemeId | null`** (документ `_id` = userId). Нет поля / `null` — «Классика».
   Без миграции и индекса (по теме не ищут). Pipeline-upsert'ы профиля (`KEEP_PROFILE_FIELDS`) поле не трогают. Тема —
   предпочтение, не ПДн: в публичный профиль, модерацию и логи не выходит; стирание аккаунта удаляет её вместе с
   документом `profiles`.
2. **Чтение — `ProfileView.themeId`** (`GET /v1/profile`): `tolerantEnum(APP_THEME_IDS).default('classic')` — ответ
   старого сервера без поля — «Классика», будущая тема в старой сборке — `'unknown'` (клиент → «Классика»).
3. **Запись — отдельный `PUT /v1/profile/theme` `{ themeId }`** (`AuthGuard`, `strictObject`, ответ — `ProfileView`,
   `no-store`), не поле `PATCH /v1/profile`: PATCH — транзакция с журналом согласий (ПДн-путь), теме хватает одной
   атомарной операции над своим документом вне транзакции (`ProfileRepository.setTheme`, гонка первых upsert — один
   повтор на `_id_`). Лимит — свой ключ `profile-theme:<uid>` 60/ч: выбор применяется на каждое нажатие и не съедает
   бюджет правки имени (`profile-update` 30/ч). Журнала смены темы нет.
4. **Тема карточек — порт `RIDER_THEMES`** (`modules/profile/index.ts`, `themeOf(userId)` → id, нет выбора —
   «Классика») для `sharing`: тема запрашивающего карточку (владелец заявки для сторис, зритель для приглашения).
   `themeId` уже в хеше входов — смена темы даёт новую картинку; `renderVersion` не поднимается. Порт `APP_APPEARANCE`
   модуля `appearance` удалён.
5. **`appearance` — только сезонный декор.** `PUT /v1/admin/appearance` = `{ decor, version }` (`themeId` — 400),
   `PanelAppearance` без темы. Публичный `GET /v1/appearance` остаётся `{ themeId, decor }`, `themeId` — константа
   `'classic'`: у установленных сборок поле обязательное, без него разбор падает и пропадает декор. Удалить поле — только
   новой версией эндпоинта, когда старых сборок не останется. `platform_settings.appearance.themeId` — legacy, не
   читается и не пишется, без миграции; история `appearance.theme_changed` в журнале панели остаётся.
6. **Клиент (активная тема):** вошедший — `themeId` из `['profile']`; пока профиль не пришёл — последняя известная
   (native: кэш `pokatim.appTheme`; web: cookie через SSR); сессия `signedOut` (любой путь) — «Классика» и стирание
   кэша/cookie. Выбор — оптимистичная мутация `PUT /v1/profile/theme` с откатом и баннером при ошибке.
7. **SSR web — cookie `pokatim_theme` + `requestHeaders()` из `expo-server`.** Клиент пишет cookie своего origin
   (`Path=/; Max-Age=31536000; SameSite=Lax`, `Secure` на https; не httpOnly — по замыслу, «Классика» не пишется).
   Адаптер `expo-server` уже запускает каждый запрос в своём `AsyncLocalStorage` (общий для бандлов через `Symbol.for`),
   `requestHeaders()` доступен в рендере `+html.tsx` и корня: `ssrThemeId()` = cookie → `toAppThemeId` (закрытый
   список), вне запроса — «Классика». Своего `AsyncLocalStorage` и `+middleware.ts` с темой процесса нет; manifest —
   «Классика».

## Последствия

- Два PR: A — контракты, API, панель, i18n (общие ключи `theme.*`), превью тем `previewOf` в `@pokatim/design-tokens`;
  B — приложение (экран «Тема», активная тема, cookie, SSR). Между ними приложение у всех в «Классике».
- Открытая вкладка старой панели после деплоя получит 400/ошибку разбора — перезагрузка (принято).
- Web-гость с устаревшей cookie получает SSR в прежней теме и одно переключение на «Классику» после гидрации сессии;
  cookie стирается этим же переходом.
- Старые PNG карточек живут до TTL кэша (24 ч).
