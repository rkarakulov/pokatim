# 0014. Карты: MapLibre, векторные тайлы OSM по URL стиля из env, коридор гонки на карточке

- Статус: Accepted
- Дата: 2026-10-27
- Задача: `docs/tasks/2026-10-27-maps-01-route-corridor`

Принят 2026-10-27: провайдер на старте — OpenFreeMap (выбор пользователя).

## Контекст

Карты в продукте нет: карточка гонки показывает коридор строкой «±N м от маршрута». Стек закладывал MapLibre
(RN + GL JS) и «PMTiles в S3 или MapTiler» (`docs/proposal-stack-architecture.md`); эпик результатов вынес карту и
тайлы за свои рамки как внешний сервис (`docs/tasks/2026-10-27-race-results/epic.md` §7). Приложение — универсальное
Expo SDK 58 (RN 0.88, новая архитектура): iOS, Android, web с SSR. Данные есть: линия показа маршрута (≤ 1000 точек),
старт и финиш (`routes`), `races.corridor` (`routeId`, `widthM`).

Требования: тайлы OSM без собственной инфраструктуры на старте; лицензия, допускающая коммерческое использование;
публичный ключ (если есть) — в бандле (`pokatim-app.md`); смена провайдера — без правки кода; светлая и тёмная тема.

Проверено 2026-10-26 (официальные страницы, context7 недоступен):

| | OpenFreeMap | MapTiler Cloud | Свои PMTiles |
|---|---|---|---|
| Аккаунт, ключ | нет | аккаунт, ключ в URL | хранилище + CDN |
| Стоимость | 0 (донаты) | Free: 5 000 сессий карты/мес, «non-commercial»; Flex — $30/мес + $2,50 за 1 000 сессий | S3/CDN-трафик |
| Лимиты | без лимита просмотров; без SLA | Free — пауза до конца месяца при превышении | свои |
| Коммерция | разрешена | Free — под вопросом, Flex — да | да |
| Стили | Liberty, Bright, Positron, Dark, Fiord | много, свои | сборка своими силами |
| Атрибуция | «OpenFreeMap © OpenMapTiles Data from OpenStreetMap» (MapLibre ставит сама) | логотип MapTiler на Free + © OSM | © OSM, OpenMapTiles |

## Решение

1. **Тайлы — по URL стиля MapLibre из env**, без кода провайдера: `EXPO_PUBLIC_MAP_STYLE_LIGHT` и
   `EXPO_PUBLIC_MAP_STYLE_DARK` (публичные, вшиваются в бандл; ключ провайдера — частью URL, например `?key=`). Не
   заданы — карты нет, карточка показывает текстовую альтернативу (сборка не падает). Смена провайдера — смена env и
   пересборка.
2. **Провайдер на старте — OpenFreeMap** (`https://tiles.openfreemap.org/styles/positron` / `…/dark`): без ключа,
   аккаунта и денег, коммерция разрешена. Риск «нет SLA» закрывает п. 1: переход на MapTiler (Flex) или свои PMTiles —
   сменой URL. Пересмотреть до публичного запуска в сторах.
3. **Атрибуция** — штатный контрол MapLibre (компактный, `customAttribution` не убираем), на native — кнопка
   атрибуции карты. Данные OSM (ODbL) не храним и не перераспространяем — только показ.
   Поправка 2026-10-28: в приложении кнопка «i» — своя (`MapAttributionButton`: иконка `info` дизайн-системы, подпись
   «Об источниках карты», стиль кнопок камеры) — кнопка MapLibre читалась точкой. Текст атрибуции — по-прежнему из
   стиля: native — диалог `MapRef.showAttribution()` (`attribution={false}`), web — плашка `AttributionControl`
   (своя кнопка её переключает, кнопка контрола скрыта). Панель — без изменений.
4. **Библиотеки:** native — `@maplibre/maplibre-react-native` 11.x (только новая архитектура, RN ≥ 0.80, peer
   `expo ≥ 54`, config plugin `@maplibre/maplibre-react-native` в `app.json`; Expo Go не поддерживается — нужна
   dev-сборка `eas build --profile development`). Web — `maplibre-gl` 6.x в платформенном файле `*.web.tsx`.
5. **SSR:** карта — только клиент. SSR и первый рендер отдают место карты фиксированной высоты (без сдвига вёрстки) и
   текстовую альтернативу; `maplibre-gl` грузится динамическим `import()` после монтирования — на сервере не
   исполняется (код в серверном бандле Metro есть: сервер не делится на чанки), в первый клиентский чанк не попадает
   (отдельный async-чанк). Воркер `maplibre-gl` — свой файл на origin (`setWorkerUrl`, `import.meta.url` в Metro нет).
   Native — пакет MapLibre RN грузится лениво и только при наличии нативного модуля (Expo Go и старый dev-клиент —
   без карты).
6. **Коридор** рисуется линией маршрута шириной 2 × `widthM` в метрах, переведённой в пиксели выражением зума
   (`interpolate exponential 2` по метрам на пиксель на широте маршрута) — без буфер-полигона на сервере; поверх —
   осевая линия, старт и финиш кругами. Цвета — роли темы `map.*` дизайн-системы.
7. **Данные:** публичное чтение `GET /v1/races/:id/route` — линия показа, старт, финиш, рамка, `widthM`; только
   опубликованная/отменённая гонка с коридором и готовым маршрутом, кэш `public, max-age=60`, лимит `public-read`.
8. ~~Панель «Протокол» остаётся с SVG-превью линии~~ — заменено поправкой routes-05: панель использует ту же карту
   (`maplibre-gl` 6, общий пакет `@pokatim/route-view`).

## Альтернативы

- **MapTiler сейчас:** нужен аккаунт и ключ пользователя; Free — некоммерческий и с паузой при превышении, Flex —
  $30/мес до запуска. Остаётся сменой URL (п. 1).
- **Свои PMTiles в S3:** S3 и CDN в проекте ещё нет; сборка тайлов Беларуси и их обновление — инфраструктура раньше
  продукта. Пересмотреть при росте трафика или требовании SLA.
- **Растровые тайлы openstreetmap.org:** политика OSMF запрещает нагрузку приложений; нет тёмной темы.
- **`react-map-gl` на web:** лишняя обёртка поверх `maplibre-gl` для одного экрана.
- **Буфер-полигон коридора с сервера:** точнее на изломах, но новая геометрия и вес ответа; визуально ширина линии в
  метрах достаточна (сверка всё равно идёт на сервере по `matchCorridor`).

## Последствия

- Native-сборки требуют пересборки dev-клиента; Expo Go с картой не работает. Jest — мок нативного модуля.
- Без SLA OpenFreeMap: при недоступности тайлов карточка показывает ошибку карты и текстовую альтернативу, сверка
  результатов от тайлов не зависит.
- Вес web: `maplibre-gl` (~1,1 МБ min) — отдельный async-чанк, грузится только на карточке гонки, но хешированный
  чанк попадает в precache service worker — PWA скачивает его при установке всем (follow-up при жалобах на трафик).
  CSS `maplibre-gl` (~70 КБ) Metro web подключает глобально — `<link>` на всех страницах.
- Ошибка стиля или тайлов — сообщение поверх карты без повтора (повтор — перезаход на карточку).
- Следующие слайсы (свой трек с подсветкой вне коридора, «рядом» для райдов, карта в панели) используют тот же
  компонент и env.

## Дополнение 2026-10-27 (routes-04b): интерактивная карта

Решения пользователя I1–I4 (`docs/tasks/2026-10-27-routes-04b-map-interactive/`). Правило статичной карты maps-01
(жесты выключены, камера только по рамке) заменяется — карта гонки, маршрута каталога и «Моего маршрута» (общий
`RouteMap`) двигается и масштабируется, прокрутка страницы не ломается.

1. **Web — кооперативные жесты `maplibre-gl`** (`interactive: true`, `cooperativeGestures: true`): мышь тащит карту,
   колесо с Ctrl/⌘ — зум, без модификатора — прокрутка страницы и подсказка поверх карты; на тач-экране один палец
   прокручивает страницу (`touch-action: pan-x pan-y`), два — двигают и масштабируют карту; двойной клик/тап —
   приближение. Строки подсказки и подпись холста — опция `locale` из `@pokatim/i18n`. Подсказка — штатный слой
   MapLibre (затемнение, нейтрально в обеих темах), при reduce motion — без затухания.
2. **Native — нативные жесты MapLibre остаются выключены**, жесты двумя пальцами (пан, щипок) и двойной тап — RNGH
   поверх карты, камера — императивно (`CameraRef.jumpTo` на кадр, без ре-рендера). Пропсы `dragPan`/`touchZoom`
   MapLibre RN 11 — только вкл/выкл: включённые, они отдают карте и один палец (Android `dragPan` зовёт
   `requestDisallowInterceptTouchEvent`), прокрутка карточки ломается. На время жеста карты экран не прокручивается
   (`MapGestureLockContext`: активация пана или щипка — выкл, конец последнего — вкл). Новых нативных зависимостей нет.
3. **Зум 2–17** (`MAP_MIN_ZOOM`/`MAP_MAX_ZOOM`), без `maxBounds` (свои маршруты бывают за границей): минимум ниже зума
   рамки самого длинного маршрута (гонка до 1000 км, свой GPX) на узком телефоне — начальная камера и «в рамку» не
   обрезаются (ревью pass 1; минимум 4 обрезал маршруты длиннее ≈ 450 км по вертикали); вращение и наклон выключены.
4. **Кнопки «+», «−», «в рамку»** — колонка сверху справа (атрибуция «i» — снизу справа); «в рамку» видна всегда.
   Отступ рамки справа — под кнопки. Анимация камеры кнопок и двойного тапа — 300 мс, при reduce motion — без
   анимации (native `fitBounds` по умолчанию — 2 с `'fly'`: длительность передаётся явно). Компонент — локальный
   `MapControls` (`IconButton` в `@rkarakulov/ui` нет — follow-up в app-foundation, как и токен длительности анимации).
5. **Маркер скраббинга** (routes-04) пересчитывает пиксели линии на каждое движение камеры (web — `move`, native —
   события региона) в стор вида карты; на кадр перерисовывается только слой маркера.
6. **Доступность — исключение для сдвига карты:** правило «`accessibilityActions` вместо единственного drag-жеста» для
   сдвига карты на native не выполняется — карта не единственный носитель информации (подпись-альтернатива,
   `adjustable` профиля), масштаб и возврат — кнопками; на web холст в фокусе двигается стрелками, масштаб — «+»/«−».
   Действия «сдвинуть на север…» скринридеру — шум, кнопки-стрелки на карте 220 px — перегруз.
7. **Ошибка карты на web** — «Карта не загрузилась» только при ошибке до `load` (стиль, первые тайлы): ошибка тайла
   новой области после `load` (перетаскивание, зум, сеть на секунду) не гасит живую карту и кнопки — как native
   (`onDidFailLoadingMap` — только загрузка стиля).

Альтернативы: web — свой обработчик колеса и своя подсказка (дубль библиотеки), `interactive` без кооперативного
режима (колесо и палец «съедают» прокрутку страницы); native — нативные `dragPan`/`touchZoom` (один палец двигает
карту), только нативный щипок без перетаскивания (урезание I1); блокировка прокрутки — RNGH `ScrollView` с отношением
`block` (замена `ScrollView` и `RefreshControl` на трёх экранах) или проп у `RouteMap` (проброс через три обёртки).
Риски: жесты двумя пальцами внутри `ScrollView` на устройстве и кооперативные жесты в мобильном браузере проверяются
вручную (в CI карты нет: стиля в смоуке нет).

### Поправка 2026-10-27 (routes-04c): карта — одним пальцем

Решение пользователя: «двигать карту 2 пальцами очень неудобно, давай сделаем одним»
(`docs/tasks/2026-10-27-routes-04c-one-finger/`). Пункты 1, 2 дополнения routes-04b заменяются; 3–7 — без изменений.

1. **Web — без кооперативного режима** (`cooperativeGestures: false`, `dragPan: true`): мышь и один палец тащат
   карту, два пальца — масштаб; касание карты страницу не прокручивает, вне карты — прокручивает. Колесо: Ctrl/⌘
   (и щипок тачпада — колесо с `ctrlKey`) — зум `scrollZoom` вокруг курсора; без модификатора — прокрутка страницы и
   своя подсказка «Чтобы изменить масштаб, крутите колесо с Ctrl» (⌘ на Mac) на 1,5 с. `cooperativeGestures`
   maplibre-gl 6 связывает колесо с тачем (`touch_pan` требует двух пальцев, пока режим включён), поэтому колесо без
   модификатора гасит свой слушатель `wheel` в фазе перехвата на контейнере карты (`guardWheelZoom`, с routes-05 — в
   `@pokatim/route-view`, общий с панелью: `stopPropagation` до `scrollZoom`, без `preventDefault` — страница
   прокручивается). Опции жестов web (`interactiveMapOptions`) — тоже в пакете: одно поведение у приложения и панели.
2. **Native — нативные жесты MapLibre RN 11:** `dragPan`, `touchZoom` включены, двойной тап — включён, при reduce
   motion выключен (анимация нативная, длительностью не управляется); `doubleTapHoldZoom`, `touchRotate`,
   `touchPitch` — выключены; зум 2–17 ограничивает `Camera` (`minZoom`/`maxZoom`) и для жестов. Касание карты
   забирает жест у прокрутки карточки: Android — `MLRNMapView.onTouchEvent` при `dragPan` зовёт
   `requestDisallowInterceptTouchEvent(true)` (теперь это желаемо), iOS — распознаватели `MLNMapView` глубже
   `UIScrollView`; вне карты экран прокручивается. RNGH-оверлей (`map-gestures.ts`), математика жестов
   (`cameraAfterGesture`, `zoomAround`) и блокировка прокрутки (`MapGestureLockContext`) удалены: прокрутку на время
   жеста карты блокирует сам натив. Маркер скраббинга — вид над картой: касание маркера идёт его RNGH-жесту, мимо
   маркера (`box-none`) — карте; камера для маркера — по-прежнему `onRegionIsChanging`/`onRegionDidChange`.

Альтернативы: однопальцевый пан на RNGH поверх карты (дубль нативного жеста, своя инерция и блокировка прокрутки);
на web — `cooperativeGestures` (тач остаётся двухпальцевым). Цена: вертикальный свайп, начатый на карте, двигает
карту, а не страницу (карта — 3:2 по ширине, вне неё экран прокручивается). Риски: поведение в `ScrollView` на
устройствах iOS/Android и в мобильном браузере проверяется вручную (в CI карты нет).

### Поправка 2026-10-27 (routes-04d): карта на весь экран, шторка, «Моё местоположение»

Решения пользователя (`docs/tasks/2026-10-27-routes-04d-sheet/`, L1–L6, G1–G4). Пункты выше — без изменений, кроме
отмеченного.

1. **Карта на весь экран** (карточка маршрута каталога): `RouteMap` получает необязательные `fill` (рамка `flex: 1`
   вместо 3:2) и `bottomInset` (видимая высота шторки, обновляется в конце снапа, не на кадр). Отступ камеры —
   `cameraPadding(inset, mapHeight)` (`map-camera.ts`): `MAP_FIT_PADDING` + inset снизу, ограниченный высотой карты
   (иначе `fitBounds` maplibre-gl при отступах больше холста не двигает камеру). Начальная камера — по inset
   развёрнутой шторки (карта монтируется после измерения шторки и области); при снапе камера не двигается. Web — для
   позиции `easeTo({ offset })`, не `padding`: `padding` в `easeTo` становится постоянным `tr.padding` и прибавляется к
   отступам `fitBounds`. Карты нет (env, нативный модуль, 404) — ровный фон `map.background`, шторка работает.
2. **Атрибуция «i» — в левом нижнем углу на всех картах** (native `attributionPosition { bottom, left }`, web
   `attributionControl: false` + `AttributionControl({ compact: true })` в `'bottom-left'`), в `fill` — со сдвигом на
   `bottomInset`: правая колонка — четыре кнопки камеры, низ — шторка (атрибуция OSM/OpenFreeMap остаётся видимой, п. 3).
3. **Колесо мыши в `fill`** — масштаб без Ctrl/⌘ (`guardWheelZoom` не подключается, `scrollZoom` по умолчанию):
   полноэкранная карта страницу не прокручивает. Карта гонки (3:2 в прокрутке) — как в поправке routes-04c.
4. **«Моё местоположение»** — четвёртая кнопка колонки (`MapControls onLocate`) на всех картах: одно foreground-чтение
   позиции по нажатию (`features/location/current-position(.web).ts`: native — `expo-location`, `Accuracy.Balanced`,
   свой таймер; web — `navigator.geolocation.getCurrentPosition` синхронно из обработчика, без высокой точности), без
   `watch` и без слоя `UserLocation` MapLibre (он следит за позицией). Точка — свой слой (`location-style.ts`: ореол +
   точка с толстой обводкой, отличима от старта, финиша и маркера скраббинга без цвета); native — `LocationLayer`,
   подписанный на стор позиции экземпляра карты (`location-store.ts`, только память), web — `addSource`/`setData`.
   Состояние чтения — в листовом `MapOverlayControls`: карта при нажатии и новой точке не перерисовывается.
5. **Приватность (меняет рамку MVP «координаты не читаются до фичи „рядом“»):** явное нажатие кнопки — намерение
   пользователя (pre-permission экран онбординга был; гость на web его не видел — системного запроса браузера
   достаточно). Координаты — только в памяти: не в TanStack Query, не в сторах с persist, не в `console.*`, URL (`hash`
   maplibre-gl выключен), подписях a11y и запросах. Отказ навсегда — баннер-ссылка в настройки ОС
   (`Linking.openSettings()`), web — текст «в настройках браузера»; ошибка — «Не удалось определить местоположение».
   Строка iOS `locationWhenInUsePermission` описывает показ на карте (действует после новой нативной сборки).

Альтернативы: `@gorhom/bottom-sheet` (новая зависимость поверх Reanimated, без web SSR) и шторка на Reanimated-worklets
(первый потребитель worklets, правка jest-окружения) — отклонены: шторка — RNGH v3 `usePanGesture` + `Animated` из
`react-native` (native) и pointer events (web). Кнопка позиции отдельно слева (отход от G1) и четвёртая кнопка только в
`fill` (две раскладки) — отклонены. Риски: конфликт жестов шторки, карты одним пальцем и скраббинга на устройстве,
диалог разрешения и отказ на iOS/Android, Geolocation по HTTPS в Safari — проверяются вручную (в CI карты нет).

### Поправка 2026-10-28 (05c): райды рядом, карта ленты, маршрут райда

Задача `docs/tasks/2026-10-28-rides-route-map/` (решение и ADR-0013 п. 4). Меняет п. 5 поправки routes-04d в части
«координаты не уходят в запросы».

1. **Координаты пользователя — только в запрос «Рядом».** По нажатию чипа «Рядом» (одно foreground-чтение, как «Моё
   местоположение») приложение шлёт `near=<lat>,<lon>` в `GET /v1/rides` и `GET /v1/rides/map`, округлённые до 0,01°
   (~1 км) клиентом и ещё раз сервером (схема `RideListQuery`/`RideMapQuery`). Радиус — 5…100 км, по умолчанию 25.
   Сервер координаты не хранит и не логирует (Fastify-логгер выключен, фильтр ошибок URL не пишет). Клиент держит их
   в памяти экрана и в замыкании запроса: в ключах и данных кэша TanStack Query — только счётчик нажатий, persist нет;
   не в `console.*`, URL экрана и подписях a11y.
2. **Access-лог прокси — без query.** Prod-Caddy access-лог не включает; nginx dev-стенда (`infra/deploy/bootstrap.sh`)
   пишет свой формат `pokatim_noquery` (как `combined`, путь `$uri` без query; подтверждено человеком 2026-10-28,
   8.1 RC-6) — координаты в лог стенда не попадают.
3. **Точка райда.** Райд хранит `routeId` и точку «Рядом» `geo`: старт маршрута, видимого публично в момент записи
   (`startPrecise`), иначе центр города (`CITY_CENTERS`). Наружу `geo` не уходит. `start` в ответах — старт маршрута,
   **видимого зрителю сейчас** (проверка на каждом чтении через порт `RideRoutes`, без кэша): снятый с публикации,
   скрытый или удалённый маршрут перестаёт раскрывать старт; свой непубличный маршрут раскрывает старт только
   организатору. При стирании аккаунта точки райдов на его маршрутах сбрасываются на центр города.
4. **Точка на чтении и остаток риска.** Сохранённая точная `geo` действует, только пока маршрут в каталоге: лента
   «Рядом» и карта ленты на каждом чтении сверяют маршрут через порт `RideRoutes`, и райд на снятом, скрытом,
   удалённом или ставшем непубличным маршруте ищется и считается по центру города и на карту не попадает. Стирание
   аккаунта после шага `routes` сбрасывает на центр города точные точки райдов на висячих маршрутах (удалённых автором
   раньше). Кандидаты «Рядом» и карты выбираются только по публичным данным: райды городов, чей центр в круге, и
   райды на маршрутах каталога со стартом в круге (`RideRoutes.publicStartsWithin`, до 500 маршрутов). Сохранённая
   точка райда на снятом маршруте не влияет ни на страницы, ни на курсор (оракул через `nextCursor` после пачек
   закрыт, фиксы ревью pass 2). Остаток: пока маршрут в каталоге, его старт и так публичен; между удалением маршрута
   автором и стиранием его аккаунта (или без стирания) снятая точка остаётся в БД, но наружу, в фильтры и в курсор не
   попадает. Сверх 500 маршрутов каталога со стартом в круге райд на них виден в «Рядом» только по городу (принятое
   ограничение).
