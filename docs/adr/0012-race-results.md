# 0012. Результаты гонок: коридор из маршрута, заявки и попытки, сверка по исходнику, протокол

- Статус: Proposed
- Дата: 2026-10-27
- Задачи: `docs/tasks/2026-10-27-race-results` (эпик), `docs/tasks/2026-10-27-race-results-01-corridor`,
  `docs/tasks/2026-10-27-race-results-02-matching`

Пункты 1–2 реализует слайс 01 (маршрут и коридор), пункт 5 — слайс 02 (алгоритм сверки), пункты 3–4, 6–8 —
слайсы 03–06; каждый слайс уточняет свой пункт. Решения автора эпика (§6) приняты 2026-10-27; статус Accepted —
после ревью слайса 02 (п. 5).

## Контекст

Гонка по коридору (ADR-0010) — анонс без коридора; заезды (ADR-0011) — активности с исходником. Нужны: эталонный
коридор, участие, сверка трека с коридором, места, протокол, споры, рейтинг. Сервер — единственный авторитет;
MongoDB не умеет буфер линии и привязку к маршруту (ADR-0007) — геометрия в `packages/tracks`.

## Решение

1. Эталонный коридор = неизменяемый маршрут модуля `routes` (v1 — маршруты команды платформы из GPX в панели) +
   допуск `widthM` гонки. Старт и финиш — концы маршрута; КП v1 — покрытие отрезков 250 м в порядке хода.
2. Коридор задаётся до первой заявки и до открытия окна (гонке без коридора — и в открытом окне); дистанция гонки с
   коридором — длина маршрута (сервер).
3. Участие — явная заявка (`results`), первая заявка фиксирует коридор, окно, класс, покрытия (V-12).
4. Попытка = (гонка, основная активность): явная или автоматическая (новая активность заявленного райдера в окне).
   Лучшая засчитанная — результат участника.
5. Сверка — `matchCorridor` (`@pokatim/tracks/parse`, вход worker `analyzeAttempt`) по исходнику без прореживания в
   worker (`worker_threads`); `engineVersion` и `checkRevision` в попытке. Алгоритм версии 1 (слайс 02):
   - **Линия:** почти прямые участки прореживаются (допуск 2 м, развороты сохраняются), затем уплотнение до
     отрезков ≤ 25 м; сеточный индекс 200 м, не больше 32 отрезков в ячейке (≈ три прохода маршрута через ячейку;
     иначе коридор отвергается как ошибка коридора, не попытки — время привязки ограничено и на слабом worker). Метрика коридора — длина этой линии; `distanceM` маршрута — только диагностика.
   - **Привязка:** отклонение `d` — до ближайшего отрезка в радиусе `max(3·widthM, 150 м)`; кандидаты точки —
     ветви маршрута (локальные минимумы расстояния вдоль линии, ≤ 4 ближайших); доля маршрута `s` — путь
     минимальной суммарной стоимости `Σ d + 0.5·|Δs − Δgeo|` по всему треку (Витерби; у петли — без свёртки по
     кругам): разворот раньше точки маршрута или ответвления — один скачок на обратную ветку, а не обратный ход.
     Выбросы — окно 1–2 точек со скоростью в него и из него > 30 м/с; точки без времени не участвуют.
   - **Ворота:** круг `max(widthM, 30 м)`: старт — вокруг первой вершины линии, финиш — вокруг последней (`isLoop`
     — только развёртка `s`); у линейного маршрута круги не пересекаются. Старт — выход из ворот старта вперёд по
     `s` (выходы в пределах 60 с — последний; ≤ 20 кандидатов), финиш — первый вход в ворота финиша строго после
     старта при покрытии ≥ 98 %. Момент — пересечение окружности на шаге (хорда сквозь круг — при шаге ≤ 1 км);
     длинный шаг по маршруту (редкая запись, поворот у ворот) — по отметке `s` (R от начала / до конца круга).
     `elapsedSec = Math.round(elapsedMs / 1000)`.
   - **Покрытие и направление:** ячейки 250 м; покрыты точкой внутри коридора или шагом между точками внутри
     (`Δgeo ≤ 1 км`, `0 ≤ Δs ≤ 1.5·Δgeo + 50 м`); направление — по порядку первого покрытия ячеек.
   - **Сход (A6):** длина трека вне коридора (шаг целиком снаружи — весь, одна точка снаружи — половина; выход
     завершается точкой внутри). Каждый шаг «внутри → внутри» сегмента — отдельный выход: больше из части хорды вне
     коридора (точно: пересечение отрезка с буферами отрезков маршрута) и **недобранного пути** `Δs − хорда` сверх
     допуска `10 м + 5 % хорды` (решение автора 2026-10-27: недобранный путь — сход; от частоты записи и Δt не
     зависит, обхода прореживанием нет). Пороги — по неокруглённым метрам с допуском 1 см (разрешение координат);
     в результате — целые метры. **Автопауза** (большой Δt, те же координаты) схода не даёт: хорда и `Δs` ≈ 0.
     Недобранный путь считается и на шаге без интерполяции покрытия (`Δs > 1.5·хорда + 50`) — как сход, не «редкая
     запись»; шаг с хордой > 1 км — разрыв GPS (`gps_gap`), не сход. Скорость отдельного шага сходом не считается
     (шум GPS на быстром спуске). Трек неправдоподобен (ошибка файла `implausible`, не отказ попытки), если средняя
     скорость по **сглаженному** пути (точки через ≥ 10 с или ≥ 100 м — шум между ними не копится) > 30 м/с или
     сумма хорд > 2 × сглаженный путь + 20 м на точку — это и есть бюджет точной геометрии хорд. Привязка ищет ветви сначала в радиусе коридора, полный радиус `max(3·widthM, 150 м)` — только
     если внутри коридора ничего нет.
   - **Коды (порядок):** `wrong_direction`; `missed_section` (< 98 % или непокрытая полоса > 500 м, или вход в
     ворота финиша без покрытия); `gps_gap` (полоса внутри шага > 1 км); `off_corridor` (доля > 2 % или один выход
     > 500 м, строго «больше»; если нарушение главным образом из недобранного пути хорд — `sparse_recording`,
     «запись слишком редкая» — только по шагам, где покрытие интерполируется); `outside_window` (A5: старт ≥ начала окна, финиш < `windowEndsAt + 1 мин`). Без
     кандидата старта — `no_start`, без финиша — `no_finish`; обратный ход всего трека — `wrong_direction`.
     Несколько засчитанных сегментов — лучший по времени. Сторож версии — эталон полного результата фикстур
     (`corridor-golden.json`).
6. Места — при чтении до публикации, снимок строк при публикации; ничья — «=N». Фаза `final` — в конец
   `RACE_PHASES`; «предварительный» — статус результата.
7. После публикации — только экстренный пересчёт с причиной; пересчёты, исключения, споры — append-only.
8. Биометрия — не хранится; ряды для разбора спора — по запросу в worker, только в панели.

### Реализация п. 1–2 (слайс 01)

- `routes`: `POST /v1/admin/routes` (`races.manage`, GPX ≤ 5 МиБ, формат по сигнатуре, дедуп по sha256 сотрудника) →
  транзакция { `routes` `processing` + `route_sources` (исходник в БД, не в `TrackFileStore` — уборка треков удаляет
  файлы без загрузки) + журнал `route.created` + outbox `routes.route-received` } → очередь `route-processing` →
  `analyzeRoute` (`@pokatim/tracks/parse`) в `worker_threads` → `ready` с линией показа (≤ 1000 точек) и линией сверки
  (≤ 20 000 точек) в `route_geometries` или `failed` с кодом. Готовый маршрут не меняется.
- `races.corridor = { routeId, widthM, distanceM }`: маршрут проверяет порт `RouteCatalog` в транзакции правки гонки
  (`ready` терминален, удаления нет — замок не нужен); допуск 20–200 м шагом 5, по умолчанию 50 (эпик A2);
  `distanceKm` = длина маршрута с точностью 0,1 км. Публично — только `corridor: { widthM }`.
- Сверка (п. 5) получает `CorridorGeometry { line = matchLine, widthM, isLoop, distanceM }`: `isLoop` — только
  развёртка пройденной доли по кругам (ворота финиша — всегда вокруг последней точки линии), `distanceM` —
  диагностика (метрика коридора — длина линии, без проверки расхождения).

## Альтернативы

- Эталонный GPX прямо в гонке, без `routes` — расходится с прототипом («только маршрут библиотеки»), дубль модели
  при появлении библиотеки.
- Сверка по упрощённой линии `activity_tracks` (≤ 1000 точек) — ошибка до десятков метров и время по ±5 мин.
- `$geoWithin` буфера в MongoDB — буфера нет (ADR-0007); полигон-буфер ручной сборки дорог и некорректен на петлях.
- Только явный выбор заезда — импорт Garmin/Wahoo теряет смысл «проехал и забыл».
- Хранимые места до публикации — пересчёт всех строк на каждую попытку и гонки записи.
- Ворота — линия поперёк маршрута вместо круга — неоднозначна на петлях и разворотах (слайс 02, Q2).
- turf/rbush/flatbush для привязки — GeoJSON-объект на точку (память), лишние зависимости; сетка на типизированных
  массивах проще и детерминированна.

## Последствия

- Новый модуль `routes` раньше библиотеки маршрутов: UGC-библиотека расширит его (`origin: 'rider'`, модерация).
- Сверка читает исходник (`TrackFileStore`) — на проде нужен S3-адаптер до открытия гонок (ADR-0011).
- Пороги коридора (2 %, 500 м, 98 %) — политика сервера (`CORRIDOR_POLICY`); их смена — новая `engineVersion` и
  новые эталоны фикстур.
- Срез по параллельной дороге ближе допуска коридором не ловится (принятый предел A2); сильный шум (σ ≥ 40 м) может
  дать ложный сход — флаг «Требует внимания» (слайс 07) и ручное исключение/возврат (слайс 05).
- Запись раз в 30–60 с на извилистом маршруте может не засчитаться (`sparse_recording`) — автор это принимает:
  по хорде срезку не отличить от честного проезда; прямой участок с такой записью засчитывается.
